# v0.12.16 — NovaSeal p99 Latency CI Gate

Released: 2026-05-15

`NovaSeal.seal()` now has an enforced latency benchmark in the CI pipeline.
A dedicated `seal-latency-gate` job runs 100 rounds of the sign operation on
every PR and blocks merge if nearest-rank p99 exceeds 200 ms.

---

## Background

ADR-0041 defines NovaSeal as the cryptographic hot path for every capsule
produced by NovaFabric.  The 200 ms p99 budget comes from the cluster-scale
collector design (ADR-0020): `NovaSeal p99 < 200 ms` is the per-capsule signing
budget that keeps the batch signer from becoming the throughput bottleneck at
100 K events/sec.

Before this release the budget existed only as a comment in the ADR.  This
release makes it machine-checked.  The gate also provides a regression baseline:
future changes to the signing path (key type, Merkle log backend, algorithm) are
immediately visible in the per-PR artifact.

Locally on a modern laptop: p99 ≈ 16 ms — 12× headroom under the gate.

## Added

### `tests/seal/test_benchmark.py`

New file — single test `test_seal_p99_latency_gate`:

- Uses `pytest-benchmark`'s `pedantic` mode: 5 warmup rounds, 100 timed rounds,
  1 call per round.
- Each round seals a distinct manifest (`seq` counter) so Merkle-log append-path
  effects remain realistic.
- After the benchmark, extracts per-round timings from `benchmark.stats.stats.data`
  and asserts nearest-rank p99 < 200 ms.
- Skips (via `pytest.skip`) when fewer than 10 timing samples are present.  This
  happens when `--benchmark-disable` is active (the flag used by the normal test
  run); the function is still called once to verify correctness.

The assertion message on failure includes n, min, median, and max for immediate
diagnosis without re-running.

### `seal-latency-gate` CI job

New job in `.github/workflows/ci.yml`:

- Runs on every push/PR to `main` in parallel with the existing `unit` and
  `integration` jobs.
- Executes `pytest tests/seal/test_benchmark.py -v --benchmark-json=bench-results/seal_latency.json`.
- Uploads `bench-results/seal_latency.json` as a 90-day GitHub Actions artifact
  named `seal-latency-<sha>`.  Compare artifacts across PRs for trend analysis.
- Timeout: 5 minutes (the full 100-round run takes ~1 s on CI).

### `make benchmark`

New Makefile target:

```bash
make benchmark
```

Runs the same command as the CI gate and writes results to
`.benchmark-results/seal_latency.json`.  Useful for checking locally before
pushing.

### `pytest-benchmark>=4.0`

Added to `[dependency-groups] dev` in `pyproject.toml` (BSD-2-Clause license,
Tier A under ADR-0024).  `uv.lock` updated.

## Changed

### `unit` CI step: `--benchmark-disable`

The existing `unit` job now passes `--benchmark-disable` to pytest.  Without
this flag, pytest-benchmark would run 100 rounds of `seal()` during the
coverage-measurement step, adding ~1 s overhead and introducing benchmark
timing data into coverage accounting.

No change to any other CI behaviour.

### `make test`

Updated to pass `--benchmark-disable` matching the CI unit step.  Coverage
runs fast; use `make benchmark` explicitly to run the latency gate.

---

## Upgrade Notes

No API changes.  The new benchmark test is dev-only (`tests/seal/` directory).
If you run `pytest tests/` without `--benchmark-disable`, pytest-benchmark will
run the 100-round gate and report timings in the terminal — this is harmless and
the gate will pass on any machine where `NovaSeal.seal()` takes under 200 ms
p99 (which is all modern hardware by a wide margin).
