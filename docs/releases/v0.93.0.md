# NovaFabric v0.93.0 — 2026-07-29

**Which step actually caused the failure — proven, not guessed?** ADR-0101's
counterfactual root-cause search ships: `nova diagnose --search-root-cause` sweeps the
causal-root candidates of a failed run and replays each one, zero-token, until a
correction actually flips the outcome. That candidate is the decisive root cause —
proven by re-execution, not merely ranked by a heuristic. `experimental`. Full detail:
`CHANGELOG.md` §[0.93.0].

## Highlights

### The search (ADR-0101 §NF-018)

`nova diagnose <run-id> --intervene` (shipped 2026-07-15) tests only the single top
ADR-0084 hypothesis. `--search-root-cause` widens that into a search: it sweeps the
ADR-0101 §NF-019 causal-root candidates — already ranked shallowest/earliest-first,
which is exactly the pruning this ADR called for over a naive linear sweep of every
step in the trace — and replays each one under mocked semantics until one confirms an
outcome flip.

```bash
nova diagnose run-xyz --search-root-cause --max-interventions 5
```

```python
from novafabric.diagnose import search_root_cause

search = search_root_cause("./capsules/run-xyz")
if search.confirmed:
    print("decisive root cause:", search.confirmed.hypothesis["step_id"])
for attempt in search.attempts:
    print(attempt.step_id, attempt.verdict.value, attempt.reason)
```

### Bounded by construction

The search is capped at `max_interventions` (default 8, hard ceiling 50, clamped
server-side) intervention replays — a capsule with many causal-root candidates can
never make a single `nova diagnose` invocation run unboundedly long. When the cap is
hit before any candidate confirms, the result says so explicitly (`bounded=True`)
rather than silently looking exhaustive.

### Auditable, not just its winner

Every attempt — confirmed, refuted, or honestly reported as not auto-intervenable
(the same model-call-only auto-mapping `--intervene` uses) — is recorded on the
result. A search that finds nothing is exactly as informative as one that does.

### NF-020: taxonomy on the sealed record itself

`HypothesisVerification` and the new `RootCauseAttempt` both now carry a top-level
`taxonomy` field (previously the `AgentErrorTaxonomy` tag only lived nested inside
`hypothesis`), so a consumer can filter or aggregate verified attributions by taxonomy
without unpacking the hypothesis payload.

### One replay-driving core, no duplication

The intervention-synthesis-and-replay logic that `verify_hypothesis` (NF-017) already
shipped is factored into a shared `_verify_step()` helper; `search_root_cause` reuses
it rather than re-implementing the replay orchestration.

### Scope, honestly

Pure-code, zero-token, no new dependencies. Auto-mappable subset is unchanged from
`--intervene`: **model-call hypotheses only** — tool/span/run causal-root candidates
are honestly reported as not auto-intervenable, never fabricated. ADR-0101 moves to
fully `accepted`: NF-017/018/019/020/022 and NF-021's structural half are all shipped
experimental; only the semantic *conflicting*-claim half of NF-021 remains future
design (it needs a semantic-equivalence judgment this ADR deliberately does not build).

## Upgrade notes

Additive only — two new CLI flags (`--search-root-cause`, `--max-interventions`), one
new optional JSON key (`root_cause_search`), two new `novafabric.diagnose` exports
(`search_root_cause`, `RootCauseSearch`, `RootCauseAttempt`), and a new `taxonomy`
field on `HypothesisVerification` (defaults to `None`, so existing callers are
unaffected). No breaking changes, no new dependencies.
