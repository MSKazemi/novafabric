# v0.103.0 — governed delete, opt-in timestamping, spec-conformant seals, and a dashboard that explores capsules

**Released 2026-10-04.** The first release since v0.102.1 and the largest since v0.102.0: about
twenty parallel development streams, merged and gated together. It closes real defects in
sealing and verification, makes several defaults safer, and adds a governed delete path, OTLP
log ingest and a much richer dashboard. **Six behaviour changes are listed under Upgrade notes
— read them before upgrading a server.**

Maturity labels follow the project convention: **works today**, **experimental**, **planned**,
**future design**. Features below are labelled in the [CHANGELOG](../../CHANGELOG.md) entry for
this version.

## What's in it

| Area | What changed |
|---|---|
| **Sealing and verification** | New NovaSeal seals sign the DSSE envelope over the spec PAE, so stock DSSE tooling verifies them (legacy seals still verify). RFC 3161 tokens are bound to the envelope they timestamp. `nova verify` no longer needs the sealer's own Merkle log, so an independent auditor can verify a capsule. Timestamping is **opt-in** (ADR-0292). |
| **Encryption at rest** | Envelopes are bound to their object and plaintext reads from an encrypted store are refused; a digest-pinned legacy inventory and a v1 strict mode ease migration. |
| **Governed delete (ADR-0206 P2)** | Capsule delete and index delete share one governed path; holds, WORM locks and sealed capsules are refused; a failed rollback can no longer destroy the only copy; the tombstone reaper keeps indexed or unfinished deletes. |
| **Dashboard** | Runs filter bar with URL view state, capsule explorer (summary, Integrity, Lineage), a Dashboards view with a validate-and-apply write path, evidence-cart export, accessibility fixes from a real-browser axe pass. |
| **Ingest and server** | OTLP logs ingest into an append-only sidecar; per-org usage budgets and API-key workspace-binding enforcement; keyset pagination for runs, assets and lineage nodes. |
| **CLI** | `nova replay --environment`, `nova diff --environment` / `--group-by environment`, `nova consent attest`, `verify-attestation` and `withdraw`. |
| **Capture** | Strict capture mode (opt-in); capture scope follows threads and pool items; the Google ADK adapter runs on a real `Runner`. |
| **Correctness** | A custom `NOVAFABRIC_HOME` is honoured everywhere through one resolver; a failed GDPR erasure no longer reports success; an unpriced model no longer reads as $0.00. |

## Upgrade notes

- **RFC 3161 timestamping is opt-in.** There is no default TSA any more. To keep timestamping,
  set `tsa_url:` (or `tsa_urls:`) in `novaseal.yaml`. Earlier capsules verify unchanged.
- **Deleting a sealed capsule is refused (409 `sealed_capsule`).** Set
  `NOVAFABRIC_ALLOW_SEALED_DELETE=1` on the server to restore the old behaviour; it never
  overrides a legal hold or an unexpired WORM lock.
- **Plaintext reads from an encrypted object store fail.** Use the legacy inventory and v1
  strict mode described in the server admin guide to migrate.
- **Refused aggregate figures are `null`, not `0`** (ADR-0234 D2) — consumers that summed them
  as zero must handle null.
- **Invalid pagination cursors return 400.**
- **New seals use the DSSE spec PAE.** Verifiers older than this release cannot check new
  seals; this release still verifies legacy ones.
- No capsule or evidence-bundle schema change. Local mode needs no server and no network.
