# v0.102.1 — the release pipeline actually publishes

**Released 2026-09-27.** v0.102.0 looked like a clean release — a tag, release notes, green
CI — and shipped almost nothing. No PyPI package, no Helm chart, and a container image that
was published unsigned. The repository had moved from the `novafabric` organisation to
`MSKazemi` seven weeks earlier, and every part of publishing that named the old identity had
been quietly broken ever since. Nothing failed until a tag fired. This release repairs the
pipeline, corrects the paths users were being handed, and adds a guard behind each fix so the
next move of the repository cannot repeat it.

## What's in it

| Area | What changed |
|---|---|
| **PyPI publishing** | The trusted publisher was still registered to the pre-transfer repository path, so the OIDC claim `repo:MSKazemi/novafabric…` was rejected and **0.102.0 never reached PyPI**. Re-registered against the real repository; the stale grant — a standing publish right for a path this project no longer controls — was removed. |
| **Helm chart** (breaking for the chart's default image) | `publish-chart.yml` hardcoded `oci://ghcr.io/novafabric/charts`; a repo-scoped `GITHUB_TOKEN` cannot write another owner's package, so the push failed outright. The namespace now derives from `github.repository_owner`, lowercased for GHCR. |
| **Image signing** | An OCI repository name must be lowercase and `github.repository` is not. `docker/metadata-action` lowercases its own input, so the build and push succeeded and hid the problem while `cosign` failed on `parsing reference`. The reference is resolved once and reused by signing, attestation and both scans. |
| **Vulnerability gate** | The same raw reference fed the ADR-0186 trivy gate that blocks a release on fixable CRITICAL findings — it could not resolve its image, so it was not gating. Fixed by the same change. |
| **Documented install paths** | 18 live references in `docs/ops/`, `deploy/helm/` and `deploy/k8s/` still named the unreachable namespace, **including the chart's own default `image.repository`** — so `helm install` produced ImagePullBackOff and every documented `docker pull` returned 401. Corrected; `docs/releases/` was left alone, as those record what was true per release. |
| **CI on the private mirror** | `.github/` is part of the shared tree, so the mirror re-ran the entire suite on billable minutes — `CI` five times, every one failing, one for 40 minutes. All 35 jobs are now confined to the public repository. |
| **Colourised help assertions** | Rich emits ANSI escapes inside option names when colour is on, so nine `--flag` assertions passed locally and failed only in CI. They now assert the rendered text. Two were additionally **vacuous** — a missing `assert` keyword meant the check never ran at all. |

## Upgrade notes

- **No API, schema or CLI change.** Every fix is to the release pipeline, its guards, or the
  documentation. Capsules, evidence bundles and the public interface are untouched.
- **If you install the Helm chart or pull the image, update the path you use.** The working
  namespace is `ghcr.io/mskazemi/…`; the old organisation path is not publicly readable.
  Only `0.102.0`, `0.102` and `latest` exist there — earlier tags remain at the unreachable
  path and are not being backfilled.
- **`ghcr.io/mskazemi/novafabric:0.102.0` is unsigned.** That image shipped before the signing
  fix, so `cosign verify` cannot succeed for it. This release is the first with a signature.

## Verification

Each fix carries a guard, and every guard was attacked before being trusted — mutation red,
restore green:

- `test_registry_namespace_matches_ci.py` — no workflow hardcodes a GHCR namespace, live docs
  name the public remote's owner, and no OCI reference is built without lowercasing.
- `test_workflows_run_only_on_the_public_repo.py` — checks the guard is *effective*, not merely
  present: `A || B && guard` binds as `A || (B && guard)` and still runs on the mirror.
- `test_release_metadata_is_consistent.py` — `CITATION.cff`, the CHANGELOG heading and the
  release-notes file must agree with `pyproject.toml`, and the notes file must be publicly
  tracked.
- `test_help_assertions_strip_ansi.py` — narrowed after a first version flagged 12 working
  assertions, then hardened against two of its own bypasses.

`make test-par` (byte-for-byte the CI `unit` job), run on this tree: **17,306 passed,
0 failed, 59 skipped, 2 xfailed, coverage 93.99%** (≥90% floor), in 13m48s. Public CI was
green on the commit this release is cut from, including the `unit` job that the
help-assertion fix repairs.

The gate earned its place twice while cutting this release. It caught that the version bump
had left both `api/*.yaml` contracts stale — the same staleness v0.102.0 shipped with — and it
caught two daemon tests whose `Thread.join(timeout=3)` does not raise on timeout, so under
20 workers they asserted against an empty list and blamed the signal rather than the
unfinished thread. Neither was re-run until green; both were diagnosed and fixed.

⚠ One gap is documented rather than closed: the local gate runs with `FORCE_COLOR` unset while
CI enables colour, so the ANSI class is invisible to `make test-par` at runtime. The guard
catches it statically; runtime parity remains an open decision.
