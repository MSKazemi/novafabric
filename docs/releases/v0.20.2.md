# v0.20.2 — Topology graph renders with populated data

**Released:** 2026-05-18

---

## Summary

The 2D Sigma.js topology view (`nova serve --topology`) was crashing silently
after the `/api/topology/seed` call populated the graph with cluster super-nodes.
This patch fixes the crash, adds visible sizing and colors to all node types,
and ships the seed + snapshot REST endpoints used to bootstrap the topology from
existing capsules.

---

## Fixed

### Sigma.js `could not find a suitable program for node type "cluster"` crash

`GraphologyModel.applyClusterLayer()` sets `type: "cluster"` on cluster super-nodes
and `applyDeltaBatch()` sets `type: "agent"` or `"model"` on individual agents.
Sigma looks up a WebGL program for each distinct node type at render time — when
no `nodeProgramClasses` map was provided, it threw an uncaught error that left the
canvas blank with no visible feedback.

**Fix** (`packages/nova-dashboard/src/renderer/renderer.ts`): pass `nodeProgramClasses`
mapping `cluster`, `agent`, and `model` to `NodeCircleProgram` from `sigma/rendering`.

### Invisible nodes (no size / color attributes)

Even with the program fix, nodes would be invisible (zero-pixel circles) because
Sigma uses per-node `size` and `color` attributes when present — and none were set.

**Fix** (`packages/nova-dashboard/src/graph/model.ts`):
- Cluster super-nodes: `size = max(16, √agent_count × 8)`, `color = "#3b82f6"` (blue), `label = "cluster N (M agents)"`.
- Agent (run) nodes: `size = 8`, `color = "#6366f1"` (indigo).
- Model nodes: `size = 8`, `color = "#8b5cf6"` (purple), node `type` set to `"model"`.
- `expandCluster()` and `_collapseClusterInternal()` updated to carry the same attributes.

### TV-5 build failure — missing Three.js packages

`@react-three/fiber`, `@react-three/drei`, and `three` were used by `TV5Panel.tsx`
but were absent from `packages/nova-dashboard/package.json`, causing TypeScript errors
that prevented `npm run build` from completing.

## Added

### `POST /api/topology/seed`

Scans `capsule_dir` for all existing capsules. For each run directory that contains
a `capsule.yaml`, it creates an agent node of type `"run"` with `status = "success"`
(exit_code == 0) or `"failed"`. For each distinct model seen in `model-calls.jsonl`,
it creates a model node with a `"calls"` edge from the run node.

After scanning, it calls `run_louvain_pass()` to assign cluster membership.
The endpoint is idempotent — re-running merges rather than duplicating.

**Response:**
```json
{
  "ok": true,
  "agents_added": 10,
  "models_added": 1,
  "edges_added": 9,
  "errors": [],
  "node_count": 11,
  "edge_count": 9,
  "cluster_count": 2
}
```

### `GET /api/topology/snapshot`

Returns the current in-memory topology counts so the SPA status bar can poll
without opening the WebSocket:
```json
{ "node_count": 11, "edge_count": 9, "cluster_count": 2 }
```

## Upgrade

```bash
pip install --upgrade novafabric
```

After restarting `nova serve --topology`, call the seed endpoint once to populate
from existing capsules:

```bash
curl -X POST "http://localhost:4321/api/topology/seed?token=<token>"
```

The topology graph in the browser will then show cluster super-nodes in blue and
individual run / model nodes when a cluster is expanded.
