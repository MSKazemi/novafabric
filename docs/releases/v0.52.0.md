# NovaFabric v0.52.0 — Warm Capture Daemon (resident emitter, slice A)

**Released:** 2026-06-14

This release ships the first slice of the **resident-emitter** rework
([ADR-0092](../decisions.md), extending
[ADR-0020](../decisions.md)): an
opt-in, long-lived per-node capture daemon that removes the per-run cold-start of
`nova capture` at fleet scale — without changing what a capsule contains.
Everything here is **experimental** and **Linux only**.

## Why

`nova capture <cmd>` spawns a fresh Python process per run, paying an interpreter
+ `novafabric`-import cold-start each time (a few hundred ms warm, ~3 s cold —
SPK-COL-2). The steady-state capture cost is already tiny (+0.36 %/call), so the
thing worth removing at scale is process startup. Every mature edge-telemetry
agent (OpenTelemetry agent pattern, Datadog Agent, Vector, Fluent Bit) solves
this the same way: a warm node-resident process, not a process per workload.

## Highlights

### `nova daemon start | stop | status`

A prefork `AF_UNIX` daemon that imports `novafabric` **once**, then `os.fork()`s
one isolated worker per run. The worker inherits all warm modules via
copy-on-write (≈0 import cost) and runs the existing `CaptureOrchestrator`
verbatim — preserving NovaFabric's "one run = one process, one capsule = one
writer" invariant. The socket lives under `$NOVAFABRIC_HOME/run/` (dir `0700`,
socket `0600`), is UID-checked (`SO_PEERCRED`), and is never networked.

### `novacap <cmd…>` — stdlib-only thin client

```bash
nova daemon start &      # under systemd / Slurm Prolog / K8s DaemonSet in production
novacap python agent.py
```

`novacap` imports no NovaFabric code (so it starts in tens of ms), forwards
argv/cwd/env, and passes your stdin/stdout/stderr through via SCM_RIGHTS. If no
daemon is reachable it falls back to `nova capture --no-daemon` automatically —
it never blocks your workload.

### `nova capture --daemon/--no-daemon` (default auto)

A plain capture delegates to the daemon when one is running; any capture using
`--runner/--runner-option/--timeout/--asset/--mark-provenance/--output-dir` runs
in-process so those flags are honored.

## Measured (warm-fs, developer laptop)

| workload | direct `nova capture` | `novacap` (warm daemon) | reduction |
|---|---|---|---|
| `/bin/true` | 593.9 ms | 209.6 ms | **−64.7 %** |
| `python -c pass` (nova-instrumented) | ~1.62 s | ~1.43 s | ~−9–12 % |

A capsule produced via the daemon is **structurally identical** to one from a
direct `nova capture` (automated fidelity gate).

## Honest scope

The daemon removes the **orchestrator** import cold-start (#1). A nova-instrumented
**Python** agent still pays a one-time `sitecustomize` import in its own process
to install the wire hooks (#2), which dominates for that case — reducing it is a
later slice (a spool-light client / `--fast-emit`). On cold-filesystem /
first-run-per-node fleets, #1 is seconds, so the saving there is much larger than
the warm-fs numbers above.

## Try it

See the [warm capture daemon guide](../warm-capture-daemon.md) for the full

## Compatibility

Fully opt-in and additive. With no daemon running, `nova capture` is byte-for-byte
unchanged. No new runtime dependencies. No schema or public-CLI breaks.
