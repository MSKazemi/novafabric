# v0.13.2 — OPA Trace Viewer in PolicyTab (DC-5 Explain)

Released: 2026-05-15

PolicyTab gains an "explain" mode: when the checkbox is checked, the policy check
fires OPA with `--explain full --format pretty` and surfaces the full trace in a
collapsible panel below the ALLOW/DENY badge.

---

## Background

OPA's `--explain full` flag produces a human-readable trace of every rule
evaluation step — which rules fired, which failed, what their inputs were. This
is the primary debugging tool when a `nova policy check` returns an unexpected
DENY. Previously the dashboard showed only the final decision; this release makes
the trace available inline.

The two-subprocess approach is intentional: the first subprocess produces
structured JSON (for the decision model), the second produces `--format pretty`
output (for the trace string). Merging them into one call would require parsing
OPA's AST explanation format, which is not stable across OPA versions.

---

## Added

### `PolicyDecision.trace_text: str | None`

New optional field on the `PolicyDecision` Pydantic model. Populated only when
`explain=True` is passed to `OpaEngine.evaluate()`. `None` in all other cases.

### `OpaEngine.evaluate(input_, explain=False)`

The `explain` parameter is forwarded to a new private `_explain()` method that
runs a second OPA subprocess:

```
opa eval --data <bundle_dir> --input <tmpfile> --explain full --format pretty <query>
```

Stdout + stderr are merged, stripped of ANSI codes, and returned as `trace_text`.
Errors are silently swallowed — if the explain subprocess fails, `trace_text` is
`None` and the main decision is unaffected.

### `POST /api/policy/check` — `explain` parameter

The endpoint now accepts `explain: bool` in the JSON body (default `False`).

### PolicyTab "explain" checkbox and trace panel

- Checkbox labelled "explain" next to the "run policy check" button.
- When checked: `api.checkPolicy(input, true)` is called with `explain=true`.
- When `decision.trace_text` is present: a "show trace ↓" link appears in the
  metadata row of the decision result card.
- Clicking toggles a `<pre>` block with `max-h-64 overflow-y-auto` showing the
  full OPA trace.

---

## Changed

### `web/src/lib/api.ts`

`PolicyDecision` interface extended: `trace_text?: string`.
`checkPolicy(input, explain = false)` — `explain` boolean merged into the request body.

---

## Upgrade Notes

No CLI changes. The explain mode requires OPA to be installed (`opa` binary on
`$PATH`). If OPA is absent, the existing "OPA not installed" warning is shown
regardless of explain mode — the explain call is never attempted.
