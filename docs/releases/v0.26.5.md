# v0.26.5 — OPA Policy-Source Evaluation + Dashboard UX Fixes

Released: 2026-05-19

Bug fixes only. OPA now evaluates user-supplied Rego source directly in the
dashboard policy check panel; three dashboard UX regressions are corrected.

---

## What's fixed

### OPA engine — custom Rego source evaluation (`nova policy test`)

`OpaEngine.evaluate()` previously ignored any `policy_source` passed by the
dashboard policy-check form, silently falling back to the bundled policy.

The fix writes the supplied source to a temporary directory and passes
`--data` to the OPA subprocess so the custom policy is actually evaluated.
The returned `PolicyDecision.policy_path` is now prefixed with `custom:` to
distinguish custom evaluations from bundle evaluations.

Empty or whitespace-only source continues to fall back to the bundled policy
(existing behaviour preserved).

Corresponding API change: `POST /api/policy/check` now extracts and forwards
the optional `policy_source` field from the request body.

Dashboard change: `PolicyTab` description label updated from "advisory lint
only" to "evaluated when provided; uses bundled policy if empty"; `policySource`
is now wired into the API call.

### Dashboard `HomeTab` — cost-report 401 on first load

The 7-day cost-summary fetch was reading `localStorage` directly before the
connection was established (e.g., when the dashboard is loaded via a URL query
param `?token=…`). Replaced the direct reads with `getConnection()` from
`api.ts`; the fetch is now skipped entirely when no token is present.

### Dashboard `RegistryTab` — stale sparkline bars after eval run

Sparkline bars in the asset list did not update after clicking "Run Eval" on
a row. The `IntersectionObserver`-based re-fetch does not re-fire for rows
that are already visible, so the bars stayed stale until the page was refreshed.
Fixed by adding an explicit `refetchEvalHistory(assetId)` call immediately
after a successful eval run response.

### Dashboard `InfraTab` — `MCPScanPanel` positioning

`MCPScanPanel` was rendered after the "CLI-only operations" footer note,
making it look like an orphaned appendage. Moved above the footer note so it
sits in the main content flow.
