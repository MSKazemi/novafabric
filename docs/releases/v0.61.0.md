# NovaFabric v0.61.0 — 2026-07-16

The enterprise-readiness release. Twelve new ADRs (0178–0189) were assessed,
accepted, and shipped as first **and** second vertical slices in one pass, on top
of the merged backlog branches (A5/A6, ADR-0149/0154/0166/0170/0172/0173/0174/0190
slices). Everything below is labelled `experimental` unless stated otherwise.
Full detail: `CHANGELOG.md` §[0.61.0] and `design/enterprise-readiness-plan-2026-07.md`.

## Highlights

### Security & identity
- **Secure-by-default local server auth (ADR-0184; breaking for the local default).**
  With OIDC disabled, `nova server` now requires an auto-generated bearer token
  (printed at startup; `~/.novafabric/.server-token`, mode 0600; pinnable via
  `NOVAFABRIC_SERVER_TOKEN`). Anonymous admin requires the explicit
  `--insecure-no-auth` opt-out and refuses non-loopback binds without
  `--i-know-this-is-public`.
- **Workspaces, organizations, service accounts (ADR-0178).** Additive `/v0/orgs`,
  `/v0/workspaces`, `/v0/service-accounts`; effective roles = union of global and
  scoped memberships. `tenant_id` remains the sole RLS isolation key.
- **SCIM completion (ADR-0139/0190).** Groups→role mapping with provenance-safe
  reconciliation, Group `PUT` full-replace, `nova server scim-map-group` incl. `--list`.

### Operations
- **Self-observability (ADR-0182).** `/livez`, `/readyz` (itemized checks),
  reader-gated `/v0/version`, Prometheus `/metrics` on both apps; opt-in
  self-tracing into the deployment's own OTLP ingest (never leaves the deployment).
- **Backup & restore (ADR-0181).** `nova backup create/verify` (local + `--profile pg`)
  with DSSE-signed manifests and a normative key-exclusion filter; `nova restore`
  verifies first, extracts safely, replays crypto-shreds, and reports ok only when
  the verification chain passes.
- **Support bundle (ADR-0187).** `nova support-bundle`: allowlist-only, redacted,
  hash-manifested diagnostics, now with bounded log collection.
- **Rate limiting & quotas (ADR-0179).** In-process token-bucket (default off) with
  the standard 429 contract; storage quotas warn-then-reject at ingest.
- **HA/upgrade posture (ADR-0180).** Expand-contract N/N+1 migration rule is now a
  release gate; single-writer active-passive contract documented.

### Data protection & supply chain
- **Opt-in encryption at rest (ADR-0185).** KMS-wrapped per-object AES-256-GCM DEKs,
  encrypt-before-WORM, hashes over ciphertext, `shred()` crypto-shred; store wiring
  via `NOVA_OBJECT_STORE_ENCRYPTION=1`.
- **Vulnerability management (ADR-0186).** Blocking pip-audit CI gate with expiring
  waivers, Dependabot, trivy image scan at release, CVE response SLAs in SECURITY.md;
  pillow bumped for 6 HIGH advisories.
- **API lifecycle (ADR-0188).** RFC 9745/8594 `Deprecation`/`Sunset` header mechanism,
  a published deprecation register (currently empty), and a CI drift gate.

### Architecture
- **Server consolidation begins (ADR-0183).** `server/` declared the strategic surface;
  serve inline routes frozen with a ratcheting CI guard (187→184 after the first
  migration wave: legal holds → `serve/routers/`).
- **Trust surfaces:** Merkle proof tree (`nova merkle-tree`, ADR-0172), trust radar
  (`nova trust-radar`, ADR-0173), redaction X-Ray (`nova redaction-xray`, ADR-0174),
  agent passport (`nova passport`, ADR-0149), WORM-report signing honesty (backlog A5).

### Documentation & governance
- Enterprise-readiness assessment + phased plan, 4 feature specs, server admin guide,
  backup/restore runbook, THREAT_MODEL "Enterprise-Readiness Surfaces" STRIDE delta,
  all registries synced. Security-Architect review remains a **pre-production
  blocking condition** for ADRs 0178/0184/0185/0186.

## Upgrade notes

- **Local `nova server` deployments:** requests now need the local token when OIDC
  is off (see above) — same-machine scripts can read `~/.novafabric/.server-token`;
  CI should pin `NOVAFABRIC_SERVER_TOKEN`. All other changes are additive/opt-in.
- New optional dependency in the `[server]` extra: `prometheus-client` (Apache-2.0).
