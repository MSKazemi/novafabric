# v0.18.0 — Dashboard parity for v0.17.0

**Released:** 2026-05-18

This release closes the dashboard gap opened by v0.17.0. v0.17.0 shipped
seven new CLI surfaces (cap-001..006/009 + KG + TV-5 3D), but only TV-5 3D
had a dashboard equivalent. v0.18.0 adds dashboard surfaces for the other
six per the v0.11 completeness principle ("every CLI capability has a
dashboard equivalent").

---

## Four DB-* items shipped

| Item | Dashboard | Serve routes | CLI mirrored |
|---|---|---|---|
| **DB-KG-1** | new `KGTab` (Sidebar `✦ KG`) | `GET /api/kg/status`, `GET /api/kg/agents/{agent_id}/edges` | `nova kg status/query` (cap-007 / ADR-0067) |
| **DB-CAP-1** | Capture-level panel in `PolicyTab` | `GET /api/policy/capture-level`, `POST /api/policy/capture-level` | `nova policy capture-level get/set` (cap-004) |
| **DB-ERA-1** | GDPR erasure panel in `ComplianceTab` | `POST /api/compliance/erasure/request`, `GET /api/compliance/erasure/status` | `nova erasure request/status` (cap-003) |
| **DB-STG-1** | Storage operations card in `InfraTab` | `GET /api/storage/validate`, `GET /api/storage/inspect/{run_id}` | `nova storage validate/inspect` (cap-003 / cap-009) |

**Total: 8 new serve endpoints, 1 new dashboard tab, 3 dashboard tab
extensions, 17 new backend tests.**

## What each surface does

### `KGTab` (DB-KG-1)

- Status header: store health (`ok` / `not_initialised` / `error`), edge
  count, db path, hint to run `nova kg init` when empty.
- Per-agent query panel: enter an agent_id (auto-suggest from recent run
  IDs), see the models it called and tools it used with CRDT-aggregated
  call_count / verified_count / confidence.
- CLI-equivalent display for one-click copy.
- Gracefully degrades when `kuzu` extra is not installed (501 → empty
  EmptyState).

### Capture-level panel in `PolicyTab` (DB-CAP-1)

- Current level badge (color-coded: minimal → green, standard → blue,
  forensic → yellow, air_gapped → red).
- Level selector dropdown.
- Field-list preview for the selected tier (`(all fields)` for forensic /
  air_gapped).
- Set button → validates the value, returns the exact
  `NOVA_CAPTURE_LEVEL=…` env-var instruction (mirrors CLI behaviour:
  process-start config; no live mutation).

### GDPR erasure panel in `ComplianceTab` (DB-ERA-1)

- Subject ID + reason form (gdpr_art_17 / dsar / internal).
- Submit returns state: `PENDING` (cap-003 enabled), `FEATURE_FLAG_OFF`
  (default), `TOMBSTONED` / `FAILED` (future when ClickHouse-backed
  pipeline ships).
- Warning banner when `NOVA_CAP003_ENABLED=false` — points to OQ-01 as the
  blocker.

### Storage operations card in `InfraTab` (DB-STG-1)

- **Validate sub-panel**: enter endpoint + bucket, get a structured
  response from `NovaObjectStore.validate()`. Errors (boto3 unreachable,
  Object Lock not supported) returned as `{ok: false, error_class, error}`
  rather than 500.
- **Inspect sub-panel**: enter a run_id, see the computed
  `audit_object_key` and `pii_object_key` (latter is `null` unless
  `NOVA_CAP003_ENABLED=true`).

## Makefile fix bundled

The `make bundle` target previously ran `rsync -a --delete web/dist/
src/novafabric/serve/static/`, which would wipe `topology/`. v0.16.5 fixed
the underlying `web/scripts/copy-dashboard.mjs` to preserve owned
directories, but the Makefile was still using the old rsync line.
v0.18.0 changes the Makefile to call `npm run build:dashboard` (which uses
the safe copy script). `topology/` is now structurally safe across
rebuilds.
