# NovaFabric v0.98.0 — 2026-07-31

**The enterprise-readiness release.** v0.97.0 modernized the dashboard; this one
works through the audit findings that stand between the codebase and a
deployable product — horizontal scaling, connection pooling, request
correlation, signed artifacts, and six concrete security fixes — and builds the
interactive trust surfaces that had been documented as *future design* since
v0.61. The deployment finding is **advanced, not closed**: a real server-mode
path exists, but it is opt-in (see below).

The dashboard remains **experimental** (ADR-0027). Nothing here changes that gate.

## Highlights

### Server mode can actually scale now

The audit found that `uvicorn` was handed an app *object*, which makes worker
processes structurally impossible — a single event loop was the permanent
ceiling. v0.98.0 adds a real app factory (`server/factory.py`) and
`nova server start --workers N`.

Alongside it: **opt-in Postgres connection pooling** (ADR-0221,
`NOVAFABRIC_METADATA_DB_POOL=1`, default off, SQLite untouched), wired through
the factory and surfaced as live `nova_db_pool_in_use` / `nova_db_pool_size`
gauges sampled at scrape time rather than by a background thread.

### You can trace a request across the stack

A per-request id is set by an outermost middleware from a sanitised inbound
`X-Request-ID` — or generated — echoed on the response, and injected onto every
log record. `nova server start --log-format json` emits one JSON object per
record so an ops team can correlate access logs, audit events, and SIEM egress.
Worker processes inherit the format.

### Published artifacts are signed and attested

Keyless cosign signatures over image digests (Sigstore/Fulcio + Rekor), SBOMs,
and SLSA provenance for both container images and wheels — closing the
uncomfortable gap where the *provenance product* shipped unsigned artifacts.
Verification recipes are in `docs/ops/server-deployment.md`.

### The deploy artifacts gained a real server-mode path

The shipped Docker entrypoint and Helm chart offered only
`nova serve --experimental --insecure` — the auth-disabled dashboard — behind
`tcpSocket` probes that could not observe the resulting failure. There is now a
real server path: `NOVA_MODE=server` (Helm `mode: server`) runs
`nova server start` against Postgres with OIDC/RBAC and never
`--insecure-no-auth`. **Both** modes now use `httpGet /livez` + `/readyz`, so a
process that cannot reach its dependencies stops reporting itself healthy.

> **This finding is only partly closed.** Server mode is **opt-in** — the
> **default is still the experimental dashboard with `--insecure`**. Set
> `NOVA_MODE=server` / `mode: server` for any multi-user deployment. Changing
> the default is a breaking change for existing image users and is deferred.

### Six security fixes

| Finding | Fix |
|---|---|
| Admin bearer token written to the application logger (lands in aggregated logs) | Terminal only; the logger keeps just the token-file path |
| Audit-log spot-check sampled with `random` (Mersenne Twister, predictable) — the one defense against an entry edited while its stored leaf hash was left intact | `secrets.SystemRandom` |
| A corrupt line in `holds.jsonl` was silently skipped, potentially voiding an active legal hold | Fails **closed** — an unparseable line is a blocking hold |
| Webhook targets could reach private/link-local/reserved addresses (SSRF) | Resolution guard, loopback still allowed, explicit opt-out |
| `GET /v0/replays/{id}` + its SSE events stream had no auth | Reader role required |
| Serve token comparison returned early on length mismatch | Hash-then-compare (v0.97.0) |

### Trust surfaces you can look at

The ADR-0173 radar and ADR-0174 redaction x-ray shipped their data/CLI halves in
v0.61; the interactive views were the documented *future design* half. Both now
exist in the dashboard's **Seal** tab, built on the already-shipped endpoints —
no new server routes, no new dependencies, inline SVG per ADR-0201.

The point of the design is the honesty contract, preserved from the CLI:

- an axis the capsule **cannot evidence** is drawn as a hollow dashed tick and
  is *excluded from the filled claim polygon* — the shaded area only ever claims
  what was actually verified, so an unsealed capsule can never be made to look
  like a failed one;
- coverage over an empty sensitive surface reads **"undefined"**, never 100%;
- a capsule with no scan metadata says so instead of erroring — "nothing was
  scanned" is a real answer;
- ADR-0174 §1 is held at the type level: the payload has no field-value to render.

The proof-tree explorer (ADR-0172) remains **future design** — it has no serve
endpoint yet, so there is nothing for a view to read.

### Honest index maintenance

Found while validating the new panels against a real store: the dashboard listed
runs whose capsule directory no longer existed, and every drill-in 404'd. The
index rebuild is additive by design, so those rows survive forever. `POST
/api/admin/reindex-runs` now accepts `{"prune": true}` (default false) to drop
them. Capsules are never touched — only the derived index row.

## Upgrade notes

- No breaking changes. Response-envelope changes are additive (`pruned`).
- `--workers`, the connection pool, JSON logging, and pruning are all **opt-in**;
  defaults are unchanged.
- **Existing container/Helm users are unaffected by default** — the entrypoint
  still starts the experimental dashboard unless you set `NOVA_MODE=server`
  (Helm `mode: server`). If you want the multi-user REST API, opt in explicitly
  and supply the Postgres/OIDC settings it needs.
- `psycopg_pool` is a new optional dependency (LGPL-3.0, Tier B under ADR-0024,
  same justification as psycopg itself); install the relevant extra to use pooling.
