# NovaFabric v0.12.11 Release Notes

**Released:** 2026-05-14
**Type:** Configuration — canonical data directory (`NOVAFABRIC_HOME`)
**Prior release:** [v0.12.10](v0.12.10.md)

---

## Summary

All internal NovaFabric data files (`registry.db`, `.serve-token`,
`dashboard-audit.jsonl`) previously hardcoded `~/.novafabric/` as their
base directory at module import time.  Running a Docker-based server and
a host-side CLI in the same environment caused the files to land in
different locations (container's `/root/.novafabric/` vs host's
`/home/user/.novafabric/` vs `--db-path` CLI override), forcing
manual reconciliation after every restart.

This release introduces **`NOVAFABRIC_HOME`** — a single env var that all
internal paths derive from.  Set it once; every nova command, `nova serve`,
and the Docker container read and write to the same location.

No schema, CLI, or API changes.

---

## What changed

### New: `src/novafabric/_paths.py`

Central path-resolution module.  All internal paths call into this module
rather than constructing `Path.home() / ".novafabric" / ...` inline.

```python
from novafabric._paths import nova_home, registry_db_path, serve_token_path

nova_home()          # $NOVAFABRIC_HOME  (default: ~/.novafabric)
registry_db_path()   # $NOVAFABRIC_DB_PATH  ‹ $NOVAFABRIC_HOME/registry.db
serve_token_path()   # $NOVAFABRIC_HOME/.serve-token
dashboard_audit_path()  # $NOVAFABRIC_DASHBOARD_AUDIT_FILE ‹ $NOVAFABRIC_HOME/dashboard-audit.jsonl
default_capsule_dir()   # $NOVAFABRIC_CAPSULE_DIR  (None if unset)
```

Priority order for each path:
1. Individual override env var (`NOVAFABRIC_DB_PATH`, etc.) — highest priority
2. `NOVAFABRIC_HOME` base directory
3. `~/.novafabric` — default

### `deploy/docker/docker-compose.yml`

Container now receives `NOVAFABRIC_HOME=/data/nova`, which matches the
`/data/nova` bind mount.  Token file and audit log land in the
bind-mounted volume instead of `/root/.novafabric/` inside the container.

Updated quick-start comment shows the matching host-side env vars:

```bash
export NOVAFABRIC_HOME="${NOVA_DATA_DIR:-$HOME/novafabric-data}/nova"
export NOVAFABRIC_CAPSULE_DIR="${NOVA_DATA_DIR:-$HOME/novafabric-data}/capsules"
```

## Upgrade notes

No migration required for single-host setups where everything ran on the
default `~/.novafabric/` path.

### Docker / shared-directory setups

Rebuild and recreate the container to pick up `NOVAFABRIC_HOME`:

```bash
cd /path/to/novafabric
docker compose -f deploy/docker/docker-compose.yml up --build --force-recreate nova
```

If the token is now written to `/data/nova/.serve-token` (inside the
container) instead of `~/.novafabric/.serve-token`, update any scripts
that read it:

```bash
# Old
docker exec nova-serve sh -c "cat ~/.novafabric/.serve-token"

# New (after NOVAFABRIC_HOME=/data/nova is set in the container)
docker exec nova-serve sh -c "cat /data/nova/.serve-token"
```

### Host-side CLI (`nova capture`, `nova register`, etc.)

To share a registry DB and capsule dir with the container, export:

```bash
export NOVAFABRIC_HOME=/path/to/shared/nova
export NOVAFABRIC_CAPSULE_DIR=/path/to/shared/capsules
```

Both variables can live in a `.env` file loaded by your Makefile.

## Verification

After rebuild:

```bash
# Container token lands in the bind-mounted path
docker exec nova-serve sh -c "ls -la /data/nova/.serve-token"

# Host CLI uses same registry
NOVAFABRIC_HOME=/path/to/shared/nova nova list
```
