# v0.24.0 — B-Tier Feature Completeness Sprint

Released: 2026-05-19

This release closes seven Tier-B feature completeness gaps identified in the v0.22
gap-closure audit. Every gap is fully implemented, tested, and documented. The test
suite grows to 3 473 passing tests (59 skipped) with coverage at ≥ 90%.

---

## What's new

### B-4 — Python cffi spool wrapper (`collector_cffi`)

- **`NovaPySpool`** (`src/novafabric/collector_cffi/spool.py`) — pure-Python atomic-rename
  spool with optional cffi binding to the Go `libnovaspool.so` shared library.
- **Binary segment format** — 16-byte header (`<IQBBxx`: PID uint32, Seq uint64,
  WriteComplete byte, Version byte) compatible with the Go spool reader in
  `collector/internal/spool/segment.go`.
- **cffi shim** (`collector/pkg/cffi/exports.go`) — exports `SpoolWrite`, `SpoolDrain`,
  `SpoolLastError` via cgo `//export` so CPython can dlopen the collector library.
- **OCB builder config** (`collector/ocb/builder-config.yaml`) — OpenTelemetry Collector
  Builder manifest for the custom NovaFabric OTel Collector distribution.
- **`collector-cffi` optional extra** — `pip install novafabric[collector-cffi]` pulls
  cffi; core install remains cffi-free.
- 13 tests (`tests/collector/test_python_spool.py`), 2 integration-gated.

### B-5 — OCS zstd dictionary compression registry

- **`ZstdDictRegistry`** (`src/novafabric/object_capsule_store/zstd_dict.py`) — thread-safe
  dictionary lifecycle manager: `train()`, `register()`, `compress()`, `decompress()`.
  Raises `CompressionDictNotFound` on unknown dict ID.
- **OCS client integration** — `ObjectCapsuleStoreClient.put_capsule()` accepts
  `compression_dict_id: str | None`; compression runs before SHA-256 CAS key
  derivation. `get_capsule()` auto-decompresses after chain verification.
- **`compression_dict_id` field** in manifest chain (field pre-existed; wired up here).
- **`ocs-compress` optional extra** — `pip install novafabric[ocs-compress]` pulls
  `zstandard` (BSD-3-Clause).
- 14 tests (`tests/ocs/test_zstd_dict.py`).

### B-6 — Maker-checker bypass notification dispatch

- **`BypassNotifier` Protocol** (`src/novafabric/promote/bypass_notify.py`) — extensible
  notification interface with three built-in implementations:
  - `NullBypassNotifier` — silent (default, no config required).
  - `FileBypassNotifier` — appends JSON lines to a local path; set
    `NOVA_BYPASS_NOTIFY_FILE=/path/to/bypass.jsonl`.
  - `WebhookBypassNotifier` — HTTP POST via stdlib `urllib.request`; set
    `NOVA_BYPASS_NOTIFY_WEBHOOK=https://hooks.example.com/nova`.
  - `MultiBypassNotifier` — fan-out to multiple backends.
- **`BypassEvent` dataclass** — structured payload with timestamp, actor, capsule ref,
  reason, and justification.
- **`build_notifier_from_env()`** — auto-builds a notifier chain from env vars; returns
  `NullBypassNotifier` when neither env var is set.
- **`PromoteBundleStore.put_bypass()` wired** — fires notification after every bypass
  write; errors in notification are logged and never propagate.
- 21 tests (`tests/promote/test_bypass_dispatch.py`).

### B-7 — NovaSeal Cloud KMS dual-mode signing

- **`SigningBackend` Protocol** (`src/novafabric/trust/novaseal/signing_backend.py`) —
  pluggable signing abstraction; `LocalSigningBackend` preserves full backward
  compatibility with Ed25519 + ECDSA P-256 local keys.
- **Three cloud backends** with lazy imports (no import-time penalty when SDK absent):
  - `AwsKmsSigningBackend` — ECDSA_SHA_256 via `boto3` `kms.sign()`.
  - `AzureKvSigningBackend` — ES256 via `azure-keyvault-keys` + `azure-identity`
    `DefaultAzureCredential`.
  - `GcpKmsSigningBackend` — SHA256 digest via `google-cloud-kms` CryptoKeyVersion.
- **`build_signing_backend(profile)`** — factory function that reads the `SigningProfile`
  and returns the correct backend.
- **Optional extras**: `seal-aws`, `seal-azure`, `seal-gcp` — each pulls the minimum
  required SDK packages (all Apache-2.0 / MIT / Apache-2.0).
- **`create_envelope()` updated** — accepts optional `backend: SigningBackend | None`
  kwarg; falls back to `LocalSigningBackend` when omitted.
- 20 tests (`tests/seal/test_cloud_kms_backends.py`) using mock KMS clients.

### B-8 — Metadata DB scale benchmark at 100 K rows

- **`tests/metadata_store/test_scale_migration.py`** — three tests:
  - `test_scale_100k_insert_query` — inserts 100 000 run records and asserts
    `query_runs` p99 ≤ 200 ms.
  - `test_scale_checksum_sample` — selects a 1% random sample and asserts every
    sampled row has a non-null checksum field (integrity assertion).
  - `test_scale_integration` (gated on `NOVA_INTEGRATION=1`) — runs the full
    scale benchmark against a live Postgres instance.
- **`bench/rls_partition_pruning/fr05_scale.sh`** — shell runner for the FR-05
  scale gate in CI.
- **`bench/rls_partition_pruning/REPORT.md`** — FR-05 section added with acceptance
  criteria and expected p99 envelope.

### B-9 — Lineage: JanusGraph real Gremlin + LDBC SNB BI queries + Helm chart

- **`JanusGraphLineageStore`** (`src/novafabric/lineage/backends/janusgraph.py`) — full
  Gremlin implementation replacing the prior stub:
  - Lazy `_connect()` using `DriverRemoteConnection`.
  - `insert()` with fold/coalesce/unfold upsert (idempotent edge creation).
  - `provenance()` — `repeat(out("depends_on")).until(loops().is(gte(depth)))`.
  - `blast_radius()` — `repeat(in_("depends_on")).until(loops().is(gte(depth)))`.
  - `replay_chain()` — follows `replayed_from` edges.
- **`LineageSnbQueries`** (`src/novafabric/lineage/backends/janusgraph_snb.py`) — five
  LDBC SNB Business Intelligence query adaptations:
  - BI-Q1 run frequency histogram
  - BI-Q2 top-N most influential runs by in-degree
  - BI-Q3 shortest dependency path between two capsule refs
  - BI-Q4 dependency chains longer than `min_depth`
  - BI-Q5 per-tenant activity summary
- **`janusgraph` optional extra** — `pip install novafabric[janusgraph]` pulls
  `gremlinpython` (Apache-2.0).
- **JanusGraph Helm chart** (`deploy/helm/janusgraph/`) — `Chart.yaml`, `values.yaml`,
  `templates/deployment.yaml`, `templates/service.yaml`, `templates/configmap.yaml`;
  Gremlin server on port 8182, configurable storage backend (default:
  `berkeleyje-server`).
- 32 tests (`tests/lineage/test_janusgraph.py`), 4 integration-gated.

## Upgrade notes

No breaking changes. All new functionality is:
- behind optional extras (no import-time penalty when SDK absent);
- gated on environment variables (`NOVA_BYPASS_NOTIFY_FILE`, `NOVA_BYPASS_NOTIFY_WEBHOOK`,
  `NOVA_INTEGRATION`);
- additive to existing Pydantic models and Protocol interfaces.

The `LocalSigningBackend` path in NovaSeal is unchanged; existing key files and
envelopes remain valid.
