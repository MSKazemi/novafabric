# NovaFabric v0.30.0 — Dashboard CLI parity: verify, emit-openlineage, suggest-register

**Released:** 2026-05-20

## Highlights

- Three CLI commands that previously had no dashboard equivalent now have dedicated panels:
  `nova verify` (SealTab), `nova lineage emit-openlineage` (LineageTab), and
  `nova suggest-register` (RegistryTab).
- Two long-standing UX bugs fixed: span matching in `TraceDiffGraph` and the misleading
  "capsule: not found" error in the SealTab Merkle log verify path.
- 9 new endpoint tests; 3814 total tests passing.

---

## What's new

### Dashboard — Capsule Integrity Verify panel (SealTab)

`nova verify <run_id>` now has a dashboard equivalent.  Enter a run ID in the new
**Capsule Integrity Verify** panel and click **Verify capsule** to run the full
three-check verification:

| Check | Algorithm |
|---|---|
| DSSE signature | ECDSA P-256 (ADR-0041) |
| RFC 3161 timestamp | TSA counter-signature |
| Merkle log inclusion | NovaSeal linked-envelope chain |

The panel handles all three result states gracefully:

- **Not sealed** — capsule exists but was never signed; shown as informational, not an error.
- **NovaSeal not configured** — backend lacks a signing key; panel explains what to configure.
- **Full results** — per-check pass/fail with detail strings, matching `nova verify` output.

Backed by: `POST /api/runs/{run_id}/verify`

### Dashboard — Export OpenLineage Events panel (LineageTab)

`nova lineage emit-openlineage <run_id>` now has a dashboard equivalent.  Enter a run ID
in the new **Export OpenLineage Events** panel and click **Export events** to retrieve
the full event stream as JSON.

- Returns OpenLineage-compatible job/run event objects.
- Preview shows the first 3 events inline; a **Copy JSON** button copies the full payload.
- Backed by: `GET /api/lineage/{run_id}/emit-openlineage`

### Dashboard — Suggest Register panel (RegistryTab)

`nova suggest-register` now has a dashboard equivalent that is always visible in
RegistryTab (no run ID required).

The panel scans recent capsules for assets that appear in capture data but are not yet
in the registry and displays them in a table:

| Column | Description |
|---|---|
| Type | Asset type inferred from capsule data |
| Name | Asset identifier |
| Version | Version string detected |
| Calls | Number of times seen across recent capsules |
| Confidence | Match confidence percentage |
| Warnings | Any detection caveats (e.g. ambiguous version) |

Each row has a one-click **Register** button that calls `POST /api/assets/register-from-yaml`
and refreshes the list.  This replaces the previous fallback text that instructed users
to run `nova suggest-register` in the CLI.

## Bug fixes

### `TraceDiffGraph`: span matching now uses span name, not span ID

Spans were matched across runs using `span_id`, which is unique per run instance.
As a result, spans with identical names but different IDs were always shown as
REMOVED + ADDED rather than CHANGED.  The comparator now matches on span `name`
(stable across runs), so same-named spans correctly appear as CHANGED with a
before/after diff.

### `SealTab` Merkle log verify: empty log no longer shows misleading error

When the NovaSeal log contained zero entries (`entry_count === 0`), the panel showed
a red **capsule: not found** message, implying the capsule was missing or corrupted.
The panel now shows a muted **seal log is empty** notice in this case.

pattern used by every other dashboard endpoint.  No schema changes.
