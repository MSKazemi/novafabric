# v0.20.0 — Dashboard Tier 1 gaps: unregister, doctor, policy test/explain, audit coverage/bundle/verify

**Released:** 2026-05-18

Closes the last seven Tier 1 gaps identified in the v0.20 dashboard audit — every
`nova` CLI command now has a corresponding dashboard UI panel.

---

## What shipped

### New serve endpoints (7)

| Endpoint | CLI mirrored | Notes |
|---|---|---|
| `DELETE /api/assets/{name}/{version}` | `nova unregister <name@version>` | Status guard: 409 for staging/production/pending\_approval without `?force=true`. Audit-logged. |
| `GET /api/doctor` | `nova doctor` | 7-subsystem health check: capsule\_dir, registry\_db, lineage\_store, opa\_binary, novaseal\_db, kg\_store, python\_version. Returns `ok: bool` + per-check detail. |
| `POST /api/policy/test` | `nova policy test` | Runs OPA test suite against the policy bundle. Stub-aware: returns `backend: "stub"` when OPA binary not found. |
| `GET /api/policy/explain` | `nova policy explain <id>` | Looks up a `decision_id` from the dashboard audit log (`~/.novafabric/dashboard-audit.jsonl`). |
| `GET /api/compliance/audit/coverage` | `nova audit coverage` | Per-profile control coverage report (NIST AI RMF / EU AI Act / ISO 42001). Threshold gate: `threshold_met: bool`. Uses `AuditEngine`. |
| `POST /api/compliance/audit/bundle` | `nova audit bundle` | ZIP export of audit report + evidence files. Returns base64 content for browser download. |
| `POST /api/compliance/audit/verify` | `nova audit verify` | Validates an `AuditReport` JSON against the Pydantic schema. Returns `valid: bool` + per-error list. |

### New dashboard panels (4 tabs, 7 panels)

**RegistryTab**
- "delete" button visible for `development` and `archived` assets
- `ConfirmDialog` with `--force` checkbox for bypassing the status guard

**AdminTab**
- "System Diagnostics" panel — `nova doctor` button triggers live 7-check table
  showing ok/fail per subsystem with detail column

**PolicyTab**
- "Policy Test Suite" panel — run OPA tests against the bundle, terminal-style output
- "Policy Explain" panel — look up a `decision_id` to see the matching audit log entries

**ComplianceTab**
- "Audit Coverage" panel — profile + threshold selector, per-control status table
  (covered / partial / missing) with overall score bar
- "Audit Bundle Export" panel — one-click ZIP generation and browser download
- "Audit Report Verify" panel — paste AuditReport JSON, validate against schema

## Implementation notes

- `DELETE /api/assets/{name}/{version}` delegates to `novafabric.registry.service.unregister_asset`.
  Raises `AssetNotFoundError` → 404, `UnregisterBlockedError` → 409.
- `GET /api/doctor` uses `LineageStore._conn` (internal sqlite connection) for edge count.
  `KGStore.get_status()` is the public health API.
- `AuditReport` lives in `novafabric.compliance.audit.models` (not `engine`).
- Policy explain searches `~/.novafabric/dashboard-audit.jsonl` for matching `decision_id` entries.
