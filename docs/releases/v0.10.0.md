# v0.10.0 — NovaSeal Cryptographic Core

Released: 2026-05-12 (unreleased / dev)

This release ships Phase 0 of the cluster-scale roadmap: NovaSeal, the
cryptographic signing subsystem for regulated environments. Capsules can now
be signed with ECDSA P-256 (DSSE envelope), timestamped via RFC 3161, and
verified against a per-tenant append-only Merkle log. All features work in
a single local process — no service required in dev mode.

ADR-0041 is now **Accepted** (CTO self-sign-off 2026-05-12).

## What's new

### NovaSeal signing subsystem (`src/novafabric/trust/novaseal/`)

- **`NovaSeal` class** — sign, verify, and rotate keys for a single signing context.
- **`NovaSeal.seal(manifest)` → `SealBundle`** — JSON-serialise the capsule manifest,
  sign it with ECDSA P-256 (DSSE envelope), request an RFC 3161 timestamp, append a
  leaf to the SQLite Merkle log, and return the assembled bundle.
- **`NovaSeal.verify(capsule_id, seal_dir)` → `VerificationResult`** — verify DSSE
  signature (self-contained, cert embedded in envelope), TSR integrity (SHA-256 of DSSE
  bytes matches the messageImprint in the TSR), and Merkle inclusion proof.
- **`NovaSeal.rotate_key(new_config)`** — appends a key-rotation event to the Merkle
  log; future `seal()` calls use the new key.
- **DSSE envelope** (`envelope.py`) — Dead Simple Signing Envelope with PAE
  (Pre-Authentication Encoding) domain separation; interoperable with in-toto and SLSA.
  Payload type: `application/vnd.novafabric.capsule+json`.
- **SQLite Merkle log** (`merkle.py`) — append-only (enforced by DB-level triggers that
  reject UPDATE/DELETE on `leaves`); SHA-256 leaf and internal hashing with domain
  prefixes (`\x00` / `\x01`); O(log n) inclusion proofs.
- **RFC 3161 timestamp adapter** (`timestamp.py`) — wraps the existing
  `trust/_rfc3161.py` DER builder; `TSAUnavailableError` on network failure; structural
  TSR validation (PKIStatus + messageImprint hash check). No new dependencies added.
- **Config loader** (`config.py`) — reads `novaseal.yaml` from `NOVAFABRIC_SEAL_CONFIG`
  env var or `~/.novafabric/novaseal.yaml`; returns `None` (NovaSeal off) if neither
  exists.

### `nova verify <capsule>` CLI

```bash
nova verify .novafabric/runs/01HXAY7M5JZ8R7K4P9DPBYK2WX/
```

Checks all three signing properties and prints:

```
NovaSeal verification: 01HXAY7M5JZ8R7K4P9DPBYK2WX
  ✓ Signature (DSSE ECDSA P-256): OK
  ✓ Timestamp (RFC 3161): OK
  ✓ Merkle log inclusion: OK

signature_ok=True, timestamp_ok=True, log_integrity_ok=True
```

Exit 0 on full pass, 1 on any failure or missing `.seal/` directory.

### Opt-in capture hook

`nova capture` automatically seals the capsule after all artifacts are written when
`novaseal.yaml` is configured. The hook is non-blocking: if signing fails for any
reason (network, key file missing, etc.), a warning is printed to stderr and the
unsigned capsule is kept. Existing behavior is unchanged for unsigned capsules.

The `.seal/` bundle:

```
.seal/
  manifest.dsse       ← DSSE envelope JSON (payload + ECDSA P-256 sig + cert)
  manifest.dsse.tsr   ← RFC 3161 TSR from TSA (DER binary; empty if TSA skipped)
  log-entry.json      ← Merkle leaf: leaf_index, leaf_hash, root_hash, tree_size, entry
```

## Configuration

Create `~/.novafabric/novaseal.yaml`:

```yaml
profile: local        # only profile supported in v0.1
key_path: ~/.novafabric/seal.key
cert_path: ~/.novafabric/seal.crt
tsa_url: https://freetsa.org/tsr   # FreeTSA for dev; empty string to skip
merkle_db: ~/.novafabric/novaseal-merkle.db
```

Generate a test key pair:

```bash
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 \
  -out ~/.novafabric/seal.key
openssl req -new -x509 -key ~/.novafabric/seal.key -days 365 \
  -out ~/.novafabric/seal.crt -subj "/CN=NovaSeal-Local"
```

## Upgrade notes

**No breaking changes.** Signing is fully opt-in. If `novaseal.yaml` is absent,
`nova capture` behaves exactly as in v0.9. Unsigned capsules remain valid and
`nova verify` exits 1 with a clear message (not an error) when no `.seal/` is found.
