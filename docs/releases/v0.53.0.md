# NovaFabric v0.53.0 — Capture-side `record_*` API for the extended event taxonomy

**Released:** 2026-06-14

This release completes the capture-side wiring for the **extended event taxonomy**
([ADR-0082](../decisions.md)). v0.49 landed the
`CapsuleEventType` members and their Pydantic models but deferred the methods an
agent calls under capture to actually emit them. v0.53.0 adds those methods to
`EventRecorder`. No new dependencies, no CLI surface change.

## Why

The extended span taxonomy (25 → 33 event types, shipped v0.49) defined the schema
for richer agent telemetry — state transitions, memory operations, guardrails,
evaluators, rerankers, and vector retrievals — but the recorder could not yet write
them. Adapters and instrumented agents had the models but no fail-open emit path.
This release closes that gap so the taxonomy is usable end-to-end.

## Highlights

### Six new typed `record_*` methods on `EventRecorder`

Each method validates a Pydantic model, appends one line to a dedicated JSONL
stream tagged with an `event_type` discriminator (via `_append_typed`), and is
**fail-open** — a bookkeeping failure never surfaces to the agent workflow, the
same contract as the existing `record_file_event` / `record_network_event` /
`record_human_approval` methods.

| Method | JSONL stream | Event type |
|---|---|---|
| `record_state_transition` | `state_transitions.jsonl` | `StateTransition` |
| `record_memory_operation` | `memory_operations.jsonl` | `MemoryOperation` |
| `record_guardrail` | `guardrail_events.jsonl` | `GuardrailEvaluated` |
| `record_evaluator` | `evaluator_events.jsonl` | `EvaluatorScored` |
| `record_reranker` | `reranker_events.jsonl` | `RerankerApplied` |
| `record_vector_retrieval` | `vector_retrievals.jsonl` | `VectorRetrieval{Started,Completed,Failed}` |

`record_vector_retrieval` selects the `Started` / `Completed` / `Failed` member by
its `phase` argument (default `completed`).

## Try it

```python
from novafabric.capture.event_recorder import get_current_recorder

recorder = get_current_recorder()
if recorder:
    recorder.record_state_transition(
        step_index=3,
        state_digest_before="sha256:…",
        state_digest_after="sha256:…",
    )
    recorder.record_guardrail("toxicity-filter", outcome="passed", score=0.02)
    recorder.record_evaluator("faithfulness", score=0.91, passed=True)
    recorder.record_reranker("bge-reranker-v2", input_count=20, output_count=5)
    recorder.record_vector_retrieval(
        "pgvector", phase="completed", top_k=5, returned_count=5
    )
```

## Compatibility

- **Additive only.** No schema or CLI break. The new streams appear under a run
  capsule only when an agent (or adapter) calls the corresponding method.
- **No new dependencies.**
- Works in local mode without server mode.

## Tests
