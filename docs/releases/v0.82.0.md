# NovaFabric v0.82.0 — 2026-07-25

**Getting ready for the quantum transition — crypto agility, today.** ADR-0072's
Phase 1 hybrid-signature layer ships: sign under multiple algorithms in one
envelope, so an artifact survives a break in any one signature family — and add
post-quantum algorithms later with no format change. `experimental`. Full detail:
`CHANGELOG.md` §[0.82.0].

## Highlights

### The hybrid-signature envelope (ADR-0072 Phase 1)

The post-quantum migration is *hybrid*: sign a payload under both a classical
algorithm (Ed25519 today) and a post-quantum one (ML-DSA when its library lands),
carry both in one envelope, and treat **either alone as sufficient** to verify.
`trust/novaseal/hybrid_signature.py` provides:

- `sign_hybrid(payload, signers)` → a `HybridSignatureEnvelope` with one signature
  per signer.
- `verify_hybrid(payload, envelope, policy=...)` → verifies each signature under
  its registered algorithm, with a policy:
  - **`any_recognized`** (default) — valid if *at least one* recognized signature
    verifies (the Phase 1 "either alone is sufficient" rule);
  - **`all_recognized`** — every recognized signature must verify;
  - plus an optional `required_algorithms` set a deployment can demand.

### A pluggable registry — the migration is additive

`register_algorithm(name, sign, verify)` adds an algorithm's signer/verifier pair.
**Ed25519 is registered by default.** When a Tier-A post-quantum library becomes
available, ML-DSA-65/87 register into the *same* registry — **the envelope format
does not change**. Shipping the agility layer now is precisely what makes the PQC
signer a drop-in later; ADR-0072 gates the *algorithm* (on `cryptography` ML-DSA
support, ~2027), not this layer.

### Forward-compatible by construction

A signature whose algorithm the verifier does not recognize is **reported, not
fatal** — an old verifier keeps working when a new algorithm is added, and a new
verifier can require the new algorithm. That is what a decade-long migration
(CNSA 2.0, 2026–2035) needs.

### Scope, honestly

This ships the crypto-agility layer (envelope, registry, `sign_hybrid` /
`verify_hybrid`). The **ML-DSA signer itself is not shipped** — Phase 1 gates it on
Python `cryptography` ML-DSA support. Phase 2 (ML-DSA default) and Phase 3 (ML-DSA
only) remain future design. ADR-0072 (which was `Future Design`) was accepted
(agility-layer slice) under delegated authority.

## Upgrade notes

Additive — new module, no breaking changes, no new dependencies (Ed25519 via the
existing `cryptography`).
