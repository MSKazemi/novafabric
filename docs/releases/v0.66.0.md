# NovaFabric v0.66.0 — 2026-07-24

**ADR-0197 phase 2.** The `evidence_source` provenance marker introduced in
v0.65.0 now covers the *entire* compliance-export layer. Where v0.65.0 marked the
four field-group exporters, v0.66.0 marks all **thirteen pure-projection
families** the 2026-07-20 audit originally flagged — the ones that render
evidence-shaped documents from operator-supplied refs without re-performing any
sealed binding. Everything new is `experimental` and additive. Full detail:
`CHANGELOG.md` §[0.66.0].

## Highlights

### Every compliance export now states its provenance

| Family group | Exporters | Marking |
|---|---|---|
| Entry-list | `export-part11`, `export-model-risk`, `export-rai-scorecard`, `export-control-attestation` | per-entry `evidence_source`; checked-gap status (`missing` / `not_evidenced` / `unsupported`) → `unverifiable`, else `operator_asserted` |
| Crosswalk | `export-public-annex-viii`, `export-transparency-register`, `dsar assemble`, `export-public-disclosure` | per-field/record `operator_asserted`; gap lists (`unmapped_required` / `manual_completion_required` / DSAR `gaps`) → `unverifiable` via a `*_evidence_source` field |
| Flat | `export-foia`, `export-election-disclosure`, `export-public-incident`, `export-citizen-explanation`, `export-accessibility-claim` | one document-level `evidence_source` (`operator_asserted`) |
| Special | `export-whistleblower` | module constant `WHISTLEBLOWER_EVIDENCE_SOURCE` — a `source`-named field would violate the model's anti-identification invariant |

**The honest rule, uniformly applied.** None of these first-slice exporters
re-performs a sealed binding, so **not one is ever `capsule_verified`** — even a
field carrying a supplied capsule ref (e.g. Annex VIII / transparency register
`capsule_evidence`) is `operator_asserted`, because a supplied reference is not a
re-performed verification. A status that names a *checked gap* — evidence expected
for the field and found absent — is `unverifiable` (I-2), never downgraded to an
assertion. Elevating any of these to real `capsule_verified` is a documented
per-family follow-on: it requires that family's collector to read and re-perform
the sealed binding.

- New shared helper `provenance.source_for_status(status, *, gap_states)` keys the
  marker off each family's native status vocabulary.
- Additive and optional on the wire; a pre-ADR-0197 document deserializes with
  `evidence_source: null`.

No breaking changes. Existing exports keep working and gain provenance marking
