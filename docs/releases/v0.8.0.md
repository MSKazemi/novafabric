# v0.8.0 — Policy + Approval Gates + WORM Storage

Released: 2026-05-11

This release adds governance primitives for regulated deployments: OPA/Rego policy
gates, a tamper-evident audit log, multi-sign-off promotions, and WORM storage
adapters with a retention-policy engine. All features work in local-only mode;
no server required.

## What's new

### Policy engine (P-0, P-1, P-2)

- **`PolicyEngine` protocol** (`policy/_engine.py`) with two implementations:
  - `OpaEngine` — calls `opa eval` as an external subprocess (timeout: 30 s). Requires
    `opa` to be installed separately (see [OPA installation](https://www.openpolicyagent.org/docs/latest/#1-download-opa)).
  - `NoopEngine` — allow-all fallback used when `opa` is not on `PATH`. Every decision
    is logged with reason `"noop-engine: opa not configured"`.
- **`PolicyDeniedError`** — domain exception raised at all three policy gate sites so
  callers can catch it uniformly.
- **`get_policy_engine()`** factory — auto-selects the engine using `shutil.which("opa")`.

- **Built-in Rego bundle** at `src/novafabric/policies/novafabric/defaults/`:

  | Policy | Rule |
  |---|---|
  | `promote_gate.rego` | `eval_score ≥ 0.90` and `unsafe_skips == 0` |
  | `replay_mutating.rego` | actor must have `admin` role |
  | `evidence_export.rego` | `redaction_proof_present` and `unsafe_skips == 0` |
  | `dataset_license.rego` | blocks promotion from datasets whose license has expired |

  Each policy has a companion `*_test.rego` file. Run them with `nova policy test`.

- **Policy gates wired** into `promote_asset()` (action `"promote"`),
  `export_evidence()` (action `"evidence_export"`), and
  `ReplayEngine` (action `"replay_mutating"`, only when `--allow-mutating` is set).

- **`nova policy test`** — runs `opa test` on the bundle; exits 0 if all pass.
- **`nova policy explain <decision-id>`** — queries the audit log and prints the
  stored event for a given decision ID.

### Tamper-evident audit log (P-0)

- **`AuditLog`** (`audit/_log.py`) — SHA-256 hash-chained append-only JSONL at
  `~/.local/share/novafabric/audit.jsonl`.
- **`AuditEventType`** enum — 8 event types: `policy.allow`, `policy.deny`,
  `promote`, `approve`, `hold.create`, `hold.release`, `capsule.delete`, `evidence.export`.
- **`AuditLog.verify()`** — recomputes the hash chain and returns a list of error
  strings for any corrupted or tampered entries.
- The chain detects accidental corruption and naive single-entry tampering; it does
  not prevent an adversary who rewrites all entries and recomputes the chain. A future
  Merkle log (ADR-0030/0031) will address the stronger adversarial model.

### Multi-sign-off promotions (P-3)

- **`AssetStatus.pending_approval`** — new lifecycle state between `validated` and
  `staging/production`.
- **`approve_asset()`** — records the approver and note in the audit log; raises
  `InvalidLifecycleTransitionError` if the asset is not in `pending_approval`.
- **`nova approve <name@version>`** — CLI command with `--approver` (default: OS user)
  and `--note` options.
- Alembic migrations add the `approvals` table on both the SQLite and Postgres tracks
  (`0002_pending_approval.py`).

### OSCAL control crosswalk (P-4)

- **`design/compliance/oscal-ssp.json`** — OSCAL 1.1.2 System Security Plan mapping the
  4 built-in policies to NIST AI RMF (GOVERN-1.1, GOVERN-1.2, MANAGE-2.2, GOVERN-5.1)
  and ISO 42001:2023 (6.1.2, 8.4) controls. Documentation artifact only; no runtime
  integration.

### WORM storage adapters (W-0, W-1)

- **`WormAdapter` protocol** (`storage/worm.py`) — `@runtime_checkable`, 5 methods:
  `put`, `get`, `lock`, `list`, `verify_integrity`.
- **`WormReceipt`** — captures backend-native confirmation tokens: `capsule_id`,
  `backend_type`, `locked_until` (timezone-aware datetime), `backend_confirmation_token`.
- **`LocalWormAdapter`** — append-only SQLite journal for development and testing.
  **Not true WORM.** A filesystem administrator can modify the SQLite file directly.
  Do not use for compliance purposes.
- **`S3WormAdapter`** (`novafabric[worm-s3]`) — S3 Object Lock COMPLIANCE mode.
  `lock()` applies an object-level legal hold (`ObjectLockLegalHold=ON`).
- **`AzureWormAdapter`** (`novafabric[worm-azure]`) — Azure Blob immutable blob policy.
  `lock()` calls `set_legal_hold(True)` on the blob client.
- **`GCSWormAdapter`** (`novafabric[worm-gcs]`) — GCS Bucket Lock via
  `retentionPolicy`. `lock()` sets `temporary_hold=True` and patches the blob.
- All cloud SDK imports are lazy; installing `novafabric` without a cloud extra does not
  import boto3, azure-storage-blob, or google-cloud-storage.

### Retention-policy engine (W-2)

- **`RetentionPolicy`** — Pydantic model loaded from `retention-policy.yaml`.
  Fields: `version`, `registry`, `jurisdiction`, `retention_days`,
  `deletion_mode` (`defensible` | `prohibited`), `legal_hold_ids`.
- **`RetentionPolicyEngine.can_delete(policy, age_days)`** — returns `(bool, reason)`.
  `prohibited` mode always blocks. `legal_hold_ids` in the policy are cross-referenced
  against the engine's loaded holds; if any match, deletion is blocked.
- **`RetentionPolicyEngine.effective_retention(policy)`** — returns
  `max(policy.retention_days, max active hold duration)`. Indefinite holds return
  `10**9` days.

### Legal hold CLI + capsule delete enforcement (W-3)

- **`nova hold create/list/release`** — manage legal holds per registry.
  Holds are stored as append-only JSONL at
  `.novafabric/registries/<registry>/holds.jsonl`.
  `create` and `release` each append a signed entry to the audit log.
- **`nova capsule delete`** — enforces retention and holds before deletion:
  1. Checks `holds.jsonl` directly — if any active holds exist, deletion is blocked
     (regardless of whether a `retention-policy.yaml` is present).
  2. If a `retention-policy.yaml` exists, checks the retention window and
     `deletion_mode`.
  3. On success, appends a `capsule.delete` entry to the audit log.

## Breaking changes

None. The policy engine defaults to `NoopEngine` (allow-all) when `opa` is not
installed, preserving existing behavior. The audit log is created on first write.
No existing CLI commands changed their interface.

## Upgrade

```bash
pip install novafabric==0.8.0

# To use OPA policy gates, install OPA separately:
# https://www.openpolicyagent.org/docs/latest/#1-download-opa

# For cloud WORM backends (optional):
pip install 'novafabric[worm-s3]'    # AWS S3 Object Lock
pip install 'novafabric[worm-azure]' # Azure Blob immutable storage
pip install 'novafabric[worm-gcs]'   # GCS Bucket Lock
```

No migration required. The `approvals` SQLite table is created automatically on
first use of `nova approve`.
