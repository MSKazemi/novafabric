# v0.6.1 — Kubernetes and SLURM runners

Released: 2026-05-09

This patch release adds two runners to the v0.6.0 baseline. Both
satisfy the `RunnerSpec` protocol introduced in
[ADR-0025](../decisions.md) — the orchestrator,
CLI, and capsule format are unchanged.

## What's new

### KubernetesRunner (ADR-0025 Runners.3)

`nova capture --runner kubernetes --runner-option image=<ref>
--runner-option namespace=<ns> ...` runs the captured workload as a
Kubernetes `Job` via `kubectl`. After completion, capsule artifacts are
pulled back to the local filesystem via `kubectl cp`.

- **Required options:** `image`, `namespace`
- **Optional options:** `service_account`, `node_selector`, `resources`,
  `poll_interval_s`
- **Implementation:** shells out to `kubectl` (no Python kubernetes
  client dependency). Job → pod → logs → cp → delete.
- **Anti-patterns enforced** in the generated Job manifest:
  `securityContext.privileged: false`,
  `securityContext.allowPrivilegeEscalation: false`,
  `hostNetwork: false`, `hostPID: false`, `hostIPC: false`,
  `backoffLimit: 0` (one shot — no retries, capsule semantics).
- **RBAC required:** `create`, `get`, `watch`, `delete` on
  `jobs`+`pods`; `get` on `pods/log`+`pods/exec`. No cluster-admin.

### SlurmRunner (ADR-0025 Runners.4)

`nova capture --runner slurm --runner-option partition=<queue> ...`
runs the captured workload as a SLURM batch job via `sbatch` + `sacct`.

- **Required options:** `partition`
- **Optional options:** `account`, `qos`, `time`, `nodes`, `gres`,
  `mem`, `constraint`, `output_dir`, `poll_interval_s`
- **Implementation:** shells out to `sbatch` + `sacct`. Wall-clock
  limit derived from `spec.timeout_s` if `--runner-option time` is not
  set. sacct ExitCode column is parsed for the workload's actual
  exit code.
- **Required precondition:** the capsule directory must be on a
  filesystem shared between the submit and compute nodes (typically
  `/scratch`, `/lustre/…`, or the user's home directory). The runner
  does not rsync artifacts; it trusts the shared FS.
- **Image / venv responsibility:** the compute node must have
  NovaFabric importable. Typically achieved by activating the same
  venv the submitter uses, or by combining with a container runner
  (apptainer / singularity).

### CLI

```bash
# Kubernetes
nova capture --runner kubernetes \
  --runner-option image=myorg/agent-runtime:abc1234 \
  --runner-option namespace=novafabric-runs \
  --runner-option service_account=novafabric-runner \
  python my_agent.py

# SLURM
nova capture --runner slurm \
  --runner-option partition=gpu-a100 \
  --runner-option time=00:30:00 \
  --runner-option gres=gpu:a100:1 \
  --output-dir /scratch/$USER/capsules \
  python my_agent.py
```

## Quality

- **558 tests passing** (was 524 at v0.6.0; +34 from new runner tests)
- **90% coverage** maintained
- `ruff check src tests` — clean
- `mypy src` (strict) — clean across 87 source files
- Live-cluster integration tests are opt-in via env vars
  (`NOVAFABRIC_TEST_LIVE_KUBERNETES=1` / `NOVAFABRIC_TEST_LIVE_SLURM=1`)
  so CI does not require a cluster

## Breaking changes

None. Both runners are additive; existing `--runner local` and
`--runner docker` usages are unchanged. Capsule format unchanged.

## Upgrade

```bash
pip install --upgrade novafabric==0.6.1
```

No migration required.

## What's not yet in this release

These remain queued (per the v0.6.0 release notes):

- **C-3.3b** — per-provider Bedrock body adapters (Cohere, Titan, Llama).
  Needs design discussion on adapter location and plugin discovery.
- **C-3.4** — HTTP/SSE transport for `nova mcp-proxy`. Needs design
  discussion on chunk-vs-aggregated SSE record shape.
- **Real-cluster validation** — ROADMAP states the SLURM runner should
  be validated against at least 2 distinct cluster configurations as
  the acceptance gate for the SLURM track. This release ships the
  unit-tested implementation; live validation is queued separately.
