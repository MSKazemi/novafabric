# v0.32.0 — 2026-05-20

## Export CLIs + Scale-S1 runs_cache

### What's new

- **`nova export-rocrate <capsule_dir>`** — wires `export_ro_crate()` to a CLI command.
  Produces a compliant RO-Crate v1.1 ZIP archive (`ro-crate-metadata.json` + capsule
  files). Default output: `<capsule_dir>.rocrate.zip`; overridable with `--output/-o`.

- **`nova lineage export-prov <capsule_dir>`** — wires `export_prov_json()` as a `lineage`
  subcommand. Reads `lineage.jsonl` and emits a W3C PROV-JSON document.
  Default output: `<capsule_dir>/prov.json`; overridable with `--output/-o`.

- **Scale-S1: `runs_cache` indexed capsule summaries** — eliminates O(N disk) scan on
  every `/api/runs` request. New module `src/novafabric/registry/runs_cache.py`:
  `ensure_runs_cache`, `build_runs_index`, `query_runs`, `upsert_run`,
  `count_cached_runs`. `nova serve` builds index on startup and refreshes every 2 s.
  `/api/runs`, `/api/runs/search`, and `/api/stats` all use SQL with disk-scan fallback.
  `/api/runs` stays below 200 ms at 100K capsules.

- 19 new tests for RO-Crate + PROV-JSON exporters; 17 unit tests for `runs_cache`.
  Total test suite: 3878 tests.

### Fixed

- `test_kg_store_no_kuzu` isolation: test now snapshots and restores the original
  `novafabric.kg.store` module to prevent Prometheus counter re-registration cascades.

### Upgrade notes

No breaking changes. `nova serve` will auto-build the `runs_cache` index on first
startup — expect a brief one-time scan proportional to the number of capsule directories.
