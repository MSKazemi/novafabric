# v0.108.0 — Verification that checks content, state that survives a crash, and a dashboard that tells the truth

**Released 2026-10-25.** A correctness and security release. A second line-by-line review of the
code found about 280 problems across 15 slices (2 critical, about 50 high); every confirmed one
was fixed with a test that fails when the fix is removed. **This release changes behaviour in
many places. Read [Behaviour changes and upgrade notes](#behaviour-changes-and-upgrade-notes)
before upgrading.**

## What's in it

### Verification that checks content, not a file name or a flag

- **A seal is a seal that verifies.** The audit engine, evidence bindings, the safety-case compiler and the
  compliance exports used to accept a file named `seal-bundle.json` (which nothing writes) and missed a real
  `.seal/`. They now call one test, `capsule_seal_verifies`; exports claim a seal only when it verifies.
- **Approvals bind what was reviewed.** A maker-checker approval, a registry promotion and a protected-label move
  now sign the digest of the reviewed content, so swapping content between propose and approve fails. A signed
  rejection is no longer an approval, and a revoked approver can no longer approve through an old policy.
- **The safety case decides from content.** An eval whose whole confidence interval lies below the pass
  threshold is no longer `SUPPORTED`; the weakest of several eval files wins; the run id comes from
  `capsule.yaml`, not a random ULID.
- **Compliance exports state only what was recorded.** NIS2 fields nobody supplied are empty and `missing`;
  GDPR/ISO controls are not inferred from unrelated files; the system card names the models the run called.

### State and secrets that survive a crash

- **Owner-only from the first byte.** `dek.db` (raw per-subject PII keys), the erasure queue, token files, the
  keyring, login credentials, the ratchet state and the audit log are created `0600` and never written through a
  planted link. 27 places that publish a file by renaming it now fsync it and its directory.
- **Crash-safe ratchet rotation, WORM and legal holds that fail closed.** An unreadable `worm.db` or registry
  directory blocks deletion instead of reading as "no locks".
- **The collector signs or refuses to start**, and its spool is durable: acknowledged segments are reclaimed, a
  completed temp segment is promoted instead of deleted at recovery, an event up to 1 MiB drains intact, and
  the dead-letter queue counts what it actually stored.

### Server, storage and restore

- **`nova serve`/`nova server`:** `GET /api/storage/validate` no longer sends the server's S3 credentials to a
  caller-chosen host; rate limits cannot be bypassed with a fresh invalid token; OIDC works with Keycloak, Okta
  and Auth0; webhook targets are checked for SSRF at every delivery; security headers are sent.
- **The Postgres Merkle log serialises appends** (a rolled-back insert or two concurrent seals made genuine
  capsules fail verification forever) and a connecting sealer no longer deadlocks with an appending one.
- **Restore proves RLS:** row security must be enabled and `WITH CHECK` must match, and drift in the restored
  database is reported before it is repaired. A forged object-store checkpoint is reported and never used.

### A dashboard that tells the truth

The Run inspector no longer shows a made-up redaction proof; the Diff tab counts changed model calls; a
mutation answered `ok:false` is an error, not a toast of success; the Reports chart no longer runs capsule
text as HTML; the Cost tab no longer asks for run `"undefined"`; the replay dry-run pane counts `[DENY]`
decisions; the Home tab no longer shows a constant "0 violations"; GDPR erasure, PII key destruction and
hold release ask for confirmation; a reload keeps your token unless the server answers `401`. The shipped
bundle is rebuilt in this release, so these fixes are in the package.

### Integrations

`nova api-proxy` relays `retry-after` and rate-limit headers and the MCP HTTP proxy carries `Mcp-Session-Id`
and `Authorization`; `@novafabric/dashboard` no longer drops about one live topology event in 256;
`@novafabric/sdk`'s `submitScore` returns the stored record on a replay; the Go collector's ULIDs are unique.

## Behaviour changes and upgrade notes

The full list is in the [CHANGELOG](../../CHANGELOG.md) under *Changed — BREAKING*. The ones most likely to
affect you:

- **Exit codes:** `nova replay --mode exact` exits `1` for an ineligible capsule; `nova seal sign --backend local`
  exits `2` and signs nothing; `nova audit map` exits `1` for a required control with no evidence;
  `nova eval compare` exits `2` for runs it cannot compare and fails CI only on a *decrease*;
  `nova eval agent` fails an asset with no eval suites.
- **Re-propose pending approvals.** Maker-checker proposals and bypasses, registry promotion proposals and label
  moves signed before the upgrade fail (`nova seal verify` exits `10`); propose them again.
- **Sigstore:** bundles made by `POST /api/seal/sigstore/sign` before this release cannot verify.
- **Collector:** `novaseal_batch_signer` exits at start unless `local_wal: true` or `fail_open: true`;
  `keystore_endpoint` is refused until its mTLS fields exist; `novafabric-hpc-hub` exits `1` (not implemented).
- **Config:** `LLMJudge` needs `api_base=` or `NOVA_JUDGE_ENDPOINT`; `NOVAFABRIC_SERVER_*` overrides are
  range-checked; building the dashboard needs Node 22.23.4 or newer.
- **After upgrading:** `chmod 0600` an existing audit log, and any `dek.db` or token file you did not let this
  release narrow on open; remember that erasure entries written before the upgrade keep the old digest (the
  log is append-only). See [SECURITY.md](../../SECURITY.md).

## Try it

```bash
pip install --upgrade "novafabric==0.108.0"
nova --version                          # novafabric 0.108.0

nova verify --json ~/.novafabric/capsules/<run-id>           # the seal is checked, not a file name
nova safety-case build ~/.novafabric/capsules/<run-id> --template clymer-generic-v0
nova replay <run-id> --mode exact                            # exit 1 with reasons if the capsule is not eligible
```

## Verification

Release-preparation gates on the release tree: the fast tier (`pytest -m "not container"`, 4 workers) ran
**23,556 passed, 0 failed, 104 skipped, 2 xfailed**; the container tier ran **91 passed, 6 skipped, 1 xfailed**
against a real PostgreSQL (including the new concurrent-append, RLS-drift and Merkle-log tests);
`ruff check` and `mypy src` (1,023 files) are clean; the dashboard type-checks and its unit suite passes
(322 tests); the OpenAPI specs, the command registry and the architecture diagrams are regenerated; the
sdist holds exactly the public tree (no private path) and the wheel installs in a clean environment and
reports `novafabric 0.108.0`. Every fix has a test that fails when the fix is reverted. **No separate
attack review of this round's fixes was run** (v0.107.0 had four); the Postgres, restore and collector
fixes were exercised against a real server and with `-race`, and the remaining known limits are in the
[ROADMAP](../../ROADMAP.md) open-items table. The dependency audits (`pip-audit`, `npm audit`) and the
sharded CI run on the tagged commit before anything is published (ADR-0316).

## Known limits

Listed in the [ROADMAP](../../ROADMAP.md) open-items table: stream relay in both proxies (they buffer),
`novafabric-hpc-hub`, the KMS keystore for the collector, `capsule_verified` for unsealed derived exports and
the SAML session credential (owner decisions), and an unverified `nats stream flush` in `deploy/hpc/epilog.sh`.
