# v0.6.2 — Per-provider body adapters (C-3.3b)

Released: 2026-05-09

This patch closes the C-3.3b gap left open at v0.6.0. The wire-level
`urllib3` hook captures AWS Bedrock calls (the URL is in the registry
since v0.6.0 / C-3.3a), but the captured records had
`gen_ai.request.model: "unknown"` and missing semconv fields because
each Bedrock provider uses its own non-OpenAI body shape.

This release ships an adapter contract that normalizes those bodies
into the OpenAI shape the shared OTel GenAI extractor expects.

## What's new

### Body adapter contract

`src/novafabric/capture/body_adapters/` exports:
- `AdapterProtocol` — the contract every adapter satisfies (one method:
  `adapt(body: dict, url: str) -> dict`)
- `adapt_body(body, url)` — dispatcher; the wire-level extractor calls
  this internally
- `register_adapter(adapter)` / `unregister_adapter(name)` — runtime
  registration for plugins

Adapters are stateless pure-Python dict transforms; per ADR-0021 §6
(cost/overhead) they run on the wire-level hot path with µs overhead.

### Vendored Bedrock adapters

| Adapter | Bedrock providers covered | Body shape normalized |
|---|---|---|
| `aws.bedrock.anthropic` | Claude family on Bedrock | injects `model` from URL; passes through `messages`, `temperature`, `top_p`, `top_k`, `max_tokens`, `stop_sequences` |
| `aws.bedrock.cohere` | Command, Command-R, Embed | synthesizes `messages` from `prompt`; renames `p`→`top_p`, `k`→`top_k` |
| `aws.bedrock.titan` | Titan Text + Amazon Nova | synthesizes `messages` from `inputText`; flattens `textGenerationConfig` (`maxTokenCount`→`max_tokens`, `topP`→`top_p`, `stopSequences`→`stop_sequences`) |
| `aws.bedrock.llama` | Llama family | synthesizes `messages` from `prompt`; renames `max_gen_len`→`max_tokens` |

Routing is by URL: the dispatcher pulls the model id from the Bedrock
URL path (`/model/<modelId>/invoke`), URL-decodes it, then matches the
provider prefix (`anthropic.`, `cohere.`, `amazon.`, `meta.llama`).

### Idempotency

`adapt_body()` is idempotent — calling it twice on the same input is
safe. A body that already has both `model` AND `messages` (i.e. is
already OpenAI-shaped) is returned unchanged. This keeps the wiring
robust if any future code path normalizes early.

### Plugin extension

Third-party packages can register adapters at runtime via
`register_adapter()`. Future revision will wire a `novafabric.body_adapters`
entry-point group for auto-discovery (mirroring the C-2 hook plugin
contract); for v0.6.2, runtime registration is the supported path.

## Breaking changes

None. Adapters are additive; if no adapter is registered for a URL,
the body passes through unchanged (the prior v0.6.1 behavior).

## Upgrade

```bash
pip install --upgrade novafabric==0.6.2
```

No migration. Capsules captured under v0.6.1 are unaffected;
re-capturing the same Bedrock workload under v0.6.2 will produce
records with correctly-populated `gen_ai.request.model` and other
semconv fields.

## Try it

```bash
# Capture a Bedrock-Anthropic call (requires AWS creds)
nova capture python my_bedrock_agent.py

# Inspect the captured record — model is now correct, not 'unknown'
cat .novafabric/runs/<run-id>/model-calls.jsonl | jq '{
  system: .["gen_ai.system"],
  model: .["gen_ai.request.model"],
  max_tokens: .["gen_ai.request.max_tokens"],
  temperature: .["gen_ai.request.temperature"]
}'
# {
#   "system": "aws.bedrock",
#   "model": "anthropic.claude-haiku-4-5-v1:0",  ← was "unknown" before C-3.3b
#   "max_tokens": 1024,
#   "temperature": 0.7
# }
```
