# v0.100.1 — the container image builds again

**2026-08-05** · Apache-2.0 · `pip install novafabric==0.100.1`

A patch release with **no library changes**. It exists because two workflows can only
fail at release time, and tagging v0.100.0 was the first thing in weeks to exercise them.

If you install from PyPI, [v0.100.0](v0.100.0.md) already has everything you need — this
release only matters if you pull the container image.

---

## Fixed — the container image has been unbuildable since v0.99.0

v0.99.0 added `force-include` entries for the canonical JSON Schemas that runtime
validators load (BL-037) but no matching `COPY` in `deploy/docker/Dockerfile`, so the
wheel build inside the image failed:

```
FileNotFoundError: Forced include not found: /build/schemas/export-manifest.schema.json
error: Failed to build `/build`
```

**This is the second instance of the same omission.** The identical mistake broke the
image for `alembic/` on 2026-07-24, and the Dockerfile's own comment records it.

The class is unpleasant because it is invisible everywhere except a container build:
`uv build` on a developer machine succeeds, because there the repository root *is* the
build context. Only Docker's narrower context exposes the gap.

`tests/packaging_metadata/test_dockerfile_force_includes.py` now asserts that every
`force-include` source both exists and is copied into the build context, so a third
instance fails in the test suite rather than at a release tag.

## Fixed — the MetadataStore Security Gate could not pass

It ran `uv sync` without `--all-extras`, so mypy could not resolve `psycopg_pool` or
`alembic.command` and reported two missing installs as if they were type errors.

**Fifth instance of the class BL-022 named.** The guard therefore no longer names one job
at a time — it scans **every** workflow that runs mypy or pytest. The two benchmark jobs
stay exempt by design: they measure capture overhead, and installing extras changes what
gets imported and skews the numbers.

## Fixed — the manual re-publish escape hatch was itself broken

`publish-image.yml` offers `workflow_dispatch` and its comment promises "a manual
re-publish from the Actions tab if a tag run needs a retry". But the only tag rule was
`type=semver`, so a dispatch from a branch derived **no tags at all** and buildx failed
with `tag is needed when pushing to registry` — the escape hatch failed in exactly the
situation it exists for.

Branch dispatches now fall back to a branch tag and a short-SHA tag. Dispatching with
`--ref v1.2.3` still takes the semver path unchanged.

