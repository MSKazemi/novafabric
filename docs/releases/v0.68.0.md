# NovaFabric v0.68.0 — 2026-07-24

**The Phase 6 at-scale lineage backend, implemented.** `PostgresLineageStore` —
long documented as the single largest genuinely-remaining engineering item — was
a `NotImplementedError` stub. It is now a real, correctness-complete backend.
Everything new is `experimental` and additive. Full detail: `CHANGELOG.md`
§[0.68.0].

## Highlights

### `PostgresLineageStore` (ADR-0053)

`lineage/backends/postgres.py` is now a psycopg3-backed lineage store that
traverses the graph with `WITH RECURSIVE` CTEs and an array-based visited set for
cycle safety — on **plain PostgreSQL, no Apache AGE extension required**. It is a
behavioural peer of the reference `SqliteLineageStore`:

- **Parity-proven.** A testcontainers suite (`tests/lineage/test_postgres_backend.py`)
  loads the same graph into a real Postgres and the SQLite reference and asserts
  `provenance`, `blast_radius`, and `replay_chain` return identical answers
  (including depth bounds and step ordering). It skips cleanly when Docker /
  testcontainers is unavailable.
- **Idempotent inserts** (`ON CONFLICT DO NOTHING`), same node/edge schema and
  indexes as the SQLite tier.
- **Zero new dependencies** — psycopg is the existing `[server]` extra.

### What is still gated (honestly)

- The **10M-edge depth-5 p99<500ms benchmark** (Phase 6 B-7) is a separate,
  infra-heavy **promotion** gate. This release ships a *correctness-complete*
  backend that works at moderate scale; it does not claim the production-scale
  benchmark. The at-scale variant should swap the single locked connection for a
  pool.
- `lineage/backends/age.py` (Apache AGE) **remains a stub** — it genuinely needs
  the AGE Postgres extension, which the standard `postgres:16-alpine` image does
  not carry.
- `SqliteLineageStore` remains the local-mode default; nothing about local usage
  changes.

## Upgrade notes
