# v0.13.5 — Security hardening: envelope version validation + capsule read integrity

Released: 2026-05-15

A security and correctness hardening release that closes three audit items from the
2026-05-14 runtime gap audit (BQ-016, BQ-010, BQ-017). No public Python API, CLI
commands, or REST endpoints changed. No breaking changes.

## Background

A design-implementation gap audit (2026-05-14) identified three build-queue items:

- **BQ-016** — parent/child capsule security hardening (lineage injection prevention,

BQ-016 and BQ-010 were confirmed already implemented and tested during the audit; their
BUILD_QUEUE.md entries are updated to `done`. BQ-017 required new code.

## Added (BQ-017)

### `ObjectCapsuleStore.get_capsule()` — authenticated capsule read

```python
from novafabric.object_capsule_store import ObjectCapsuleStore

store = ObjectCapsuleStore(adapter=adapter, novaseal_client=ns)
raw_bytes = store.get_capsule(tenant="acme", run_id=run_id, capsule_uri=uri)
```

The read path:

1. Walks the per-`(tenant, run_id)` manifest chain to find the **trusted SHA-256 pin**
   for `capsule_uri` (raises `KeyError` if the URI was never recorded).
2. Fetches bytes from the WORM backend adapter.
3. Recomputes `sha256(bytes)` and compares to the chain pin.
4. Returns bytes on match; raises `CapsuleIntegrityError` on mismatch.

This closes the gap where `put_capsule` was protected by the 5-step WORM protocol but
`get_capsule` had no equivalent tamper-detection.

**Key files:**
- `src/novafabric/object_capsule_store/client.py` — `get_capsule()` method
- `src/novafabric/object_capsule_store/exceptions.py` — `CapsuleIntegrityError`

### `CapsuleIntegrityError`

```python
class CapsuleIntegrityError(ObjectCapsuleStoreError):
    capsule_uri: str
    expected_sha256: str
    observed_sha256: str
```

Raised when the SHA-256 of bytes returned by the WORM backend does not match the pin
recorded in the manifest chain at write time. Signals backend tampering or corruption.

### Envelope version pre-filter in Go collector (BQ-017)

`filterInvalidEnvelopeVersions()` is called inside `ConsumeLogs` **before** the
canonical-encoding + Ed25519 signing pipeline. For each `ResourceLogs` batch it removes
any `LogRecord` whose `envelope_version` field is not `"1"`:

```
ConsumeLogs(ld plog.Logs):
  0. filterInvalidEnvelopeVersions(ld)   ← NEW
  1. canonical encode
  2. Ed25519 sign
  3. attach signature attributes
```

Dropped records:
- Are never signed or forwarded.
- Emit `slog.Error("novaseal_batch_signer: rejecting record with unknown envelope_version", ...)`.
- Increment `nova_invalid_envelope_version_total{observed_version=<ver>}`.

If all records in a batch are filtered out the batch is acknowledged without signing
(no error returned to upstream), consistent with the existing
`ld.LogRecordCount() == 0` early-exit path.

**Key files:**
- `collector/internal/processor/novasealbatchsigner/processor.go` — `filterInvalidEnvelopeVersions`, `envelopeVersionFromRecord`
- `collector/pkg/metrics/metrics.go` — `InvalidEnvelopeVersionTotal` counter

## Straggler additions (D-5 / C-5)

### Promote JSON schemas (D-5, ADR-0058)

Five JSON Schema 2020-12 files that formally define the maker-checker payload contracts:

| File | Predicate |
|---|---|
| `src/novafabric/schemas/promote_proposal_v1.json` | Maker step — proposal payload |
| `src/novafabric/schemas/promote_approval_v1.json` | Checker step — approval payload |
| `src/novafabric/schemas/promote_bypass_v1.json` | Emergency bypass payload |
| `src/novafabric/schemas/promote_bypass_review_v1.json` | Post-bypass review payload |
| `src/novafabric/schemas/promote_policy_v1.json` | Policy configuration payload |

All schemas use `additionalProperties: false` and are Tier A (Apache-2.0 project, MIT-compatible schema format).

### `jcs>=0.2` dependency (D-5)

`jcs` (MIT) provides RFC 8785 JSON Canonicalization Scheme — used by `nova promote propose` to compute a deterministic `proposal_digest` (SHA-256 of the canonical JSON payload) before signing with Ed25519. Tier A per ADR-0024.

### DiffTab `useEffect` guard fix (C-5)

The `useEffect` that loads diff IDs from session storage used a stale `if (initialA || initialB) return` guard after the C-5 refactor renamed those props to `initialIds`. Changed to `if (initialIds?.length) return`. Without this fix, navigating to DiffTab with pre-filled run IDs (e.g. via the "Compare selected" RunsTab button) would load the stale session value over the intended IDs.

Static bundle rebuilt to include this fix (`DashboardApp.D2H-44L8.js`).

## Upgrade notes

No migration required. `get_capsule()` is a new method — callers of `put_capsule` are
unaffected. The Go collector envelope pre-filter silently drops unknown-version records;
existing pipelines sending only `envelope_version: "1"` events see no change.

If you have a custom Go collector build, rebuild with the updated
`novasealbatchsigner` processor to get the pre-filter and the new Prometheus counter.
