# v0.14.3 — RBAC API + BQ-011 collector acceptance criteria

**Released:** 2026-05-15
**ADRs:** [ADR-0060](../decisions.md) (proposed); collector BQ-011 (Phase 2 — experimental)

---

## What's new

This release delivers two independent tracks:

1. **RBAC API (P1 of v0.14 admin overhaul)** — role-management REST surface for the multi-user server. No UI yet; the role-management UI ships in P2.
2. **BQ-011 collector acceptance criteria** — 4 of 5 acceptance criteria for the cluster-scale collector pipeline are now satisfied. One criterion (NATS-on-Lustre) remains hardware-gated.

---

## RBAC API

### New routes

| Route | Server mode | Local mode | Description |
|---|---|---|---|
| `POST /v0/admin/roles` | ✅ | — | Assign role to subject. Idempotent. |
| `POST /api/admin/roles` | — | ✅ | Assign role to subject (local, query-string token). |
| `DELETE /v0/admin/roles/{subject}/{role}` | ✅ | — | Revoke role with last-admin lockout guard (409 if blocked). |
| `DELETE /api/admin/roles/{subject}/{role}` | — | ✅ | Revoke role (local). |
| `GET /v0/admin/roles` | ✅ | — | List `role_assignments` with `effective_now` flag per row. |
| `GET /api/admin/roles` | — | ✅ | List `role_assignments` (local). |

The `GET` routes replace the legacy placeholder body (always `roles: []`) with the live response shape. The response keys `server_mode`, `roles`, and `message` are preserved — backward-compatible.

### New CLI command

**`nova server revoke-role <user> <role>`** — symmetric counterpart to `nova server assign-role`. Exits with code 2 when the lockout invariant blocks the operation (i.e., revoking would leave no active admin).

### Store layer hardening

`LastAdminError`, `revoke_role()`, and `list_subjects()` added to `server/rbac_store.py`. The lockout invariant is enforced at the store layer (defense in depth), not only at the route layer.

### Test coverage

38 new tests across:
- `tests/test_server_rbac_store.py`
- `tests/test_serve_admin_roles.py`
- `tests/test_server_rbac.py`
- `tests/test_server_cli_commands.py`

100% statement coverage for `rbac_store.py` and `routes/roles.py`.

## BQ-011 — Collector acceptance criteria

### Acceptance scorecard

| Criterion | Status | Evidence |
|---|---|---|
| Canonical byte encoding — 10K cross-language round-trip (Go→Python Ed25519 verify) | ✅ | `TestCanonicalEncode_CrossLanguageRoundTrip10K` |
| NovaSeal batch processor — ≥100K events/sec, p99 < 200ms | ✅ | 295K events/sec, p99 4.7ms (`TestNovaSealBatchSigner_ThroughputAndLatency`) |
| HPC leaf autonomy during hub disconnection — 200 events buffered + drained exactly once | ✅ | `TestSpoolStore_AutonomyDuringHubDisconnection` |
| Slurm Epilog flush within PrologEpilogTimeout — exits 0 | ✅ | `TestEpilogScript_ExitsZeroWithinTimeout` (exits 0 in <10s) |
| NATS-on-Lustre — validated on representative cluster | ⏳ | Hardware-gated; no code changes needed |

### Crash-safety gap closed

`collector/internal/spool/checkpoint.go` previously used `os.WriteFile`, which does not guarantee durable writes on power-fail. Two new platform-specific files now call `fdatasyncFile` before the rename-commit:

- `collector/internal/spool/checkpoint_sync_linux.go` — `syscall.Fdatasync(fd)` on Linux
- `collector/internal/spool/checkpoint_sync_notlinux.go` — `f.Sync()` on other platforms

This closes the one remaining crash-safety gap in the cap-001 spool.

### Cross-language round-trip verifier

`collector/scripts/verify_canonical_roundtrip.py` — standalone Python Ed25519 verifier using the `cryptography` library. Used by `TestCanonicalEncode_CrossLanguageRoundTrip10K` to confirm Go-signed canonical batches verify correctly in Python.

### Makefile target

`make roundtrip-test` — runs `TestCanonicalEncode_CrossLanguageRoundTrip10K` directly. Requires `python3` and the `cryptography` package.

### New files

| File | Purpose |
|---|---|
| `collector/internal/spool/checkpoint_sync_linux.go` | `syscall.Fdatasync` before rename (Linux) |

| `collector/pkg/canonical/corpus_roundtrip_test.go` | 10K cross-language Ed25519 round-trip test |

## Upgrade

No schema changes, no CLI changes to existing commands, no API shape changes to existing routes. Drop-in replacement for v0.14.2.

The new `nova server revoke-role` command is additive. The `GET /api/admin/roles` and `GET /v0/admin/roles` response shape is backward-compatible (same keys; content changes from placeholder to live data).
