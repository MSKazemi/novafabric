# v0.6.3 — HTTP/SSE transport for `nova mcp-proxy` (C-3.4)

Released: 2026-05-09

This patch closes C-3.4 — the last open implementation track from the
v0.6 wire-level expansion. `nova mcp-proxy` previously supported only
stdio (subprocess upstream); v0.6.3 adds HTTP transport with SSE-aware
recording.

## What's new

### `nova mcp-proxy --listen` mode

```bash
nova mcp-proxy \
  --capsule-dir /path/to/.novafabric/runs/01HX... \
  --listen 127.0.0.1:8765 \
  --upstream-url http://upstream-mcp.internal:9000/mcp
```

The proxy listens on the given host:port, forwards every HTTP POST
request to `--upstream-url`, and writes a `tool-calls.jsonl` record
for each `tools/call` exchange. Stdio mode is unchanged and remains
the default; HTTP and stdio are mutually exclusive on a single
invocation.

### SSE response aggregation

The C-3.4 design call (committed in v0.6.2 release notes): **one record
per `tools/call`, aggregated**, not per chunk. When upstream returns
`Content-Type: text/event-stream`, the proxy:

1. Streams the bytes through to the client unchanged (preserves the
   client's streaming experience).
2. Walks the SSE event stream looking for the JSON-RPC message whose
   `id` matches the request's `id`.
3. Records that single message as the `response_envelope` in the
   tool-call record.
4. Sets `extensions.io.novafabric.streaming = {streamed: true,
   chunk_count: N}` so consumers know it was a stream and how many
   events were buffered.

Why aggregated: replay determinism (the mock dispatcher serves one
response per call), cluster-scale storage (per-chunk would be 10–100×
more records), and schema parity with stdio. Detailed rationale in the
v0.6.2 release notes.

### Schema additions (additive — no breaking changes)

Tool-call records produced by HTTP-mode proxy carry one new extension:

- `extensions.io.novafabric.transport_kind`: `"http"` (vs `"stdio"`)

Plus the streaming sub-block when the response was an SSE stream:

- `extensions.io.novafabric.streaming.streamed`: `true`
- `extensions.io.novafabric.streaming.chunk_count`: integer

Stdio-mode records are unchanged.

### Robustness

- **Upstream unreachable** (`httpx.ConnectError`, etc.): the proxy
  returns a synthesized JSON-RPC error envelope (HTTP 502 +
  `{"error": {"code": -32000, "message": "upstream unreachable: ..."}}`)
  to the client. The `tools/call` is still recorded with `status=error`,
  preserving the audit trail.
- **Malformed upstream JSON** (Content-Type says JSON but body isn't):
  recorded as `status=success` (no `error` key) with empty
  `response_envelope`. Audit trail intact; downstream tooling can
  detect the empty envelope.
- **SSE stream missing the response id** (e.g., upstream connection
  dropped mid-stream): record is still emitted with empty
  `response_envelope`.
- **Bookkeeping failures** (writer errors): swallowed silently — the
  proxy is a transport, never a policy point.

### Implementation notes

- Stdlib only on the listening side: `http.server.ThreadingHTTPServer` +
  `BaseHTTPRequestHandler`. No new runtime dependencies.
- Upstream HTTP calls go through `httpx` (already a runtime dep).
- The `serve_one_request_for_test()` seam lets unit tests exercise
  every code path through the request handler without binding a
  socket — so CI doesn't need port permissions.

### CLI flag validation

- `--listen <spec>` parses `host:port` (and `:port` defaulting to
  `127.0.0.1`). Out-of-range ports, non-integer ports, and missing
  colons all error with helpful messages.
- `--listen` requires `--upstream-url`; missing it errors before any
  socket bind.
- `--listen` + a trailing stdio command errors (mutually exclusive).
- All existing stdio-mode behavior preserved bit-exact.

## Breaking changes

None. `--listen` defaults to absent; stdio mode is unchanged.

## Upgrade

```bash
pip install --upgrade novafabric==0.6.3
```

No migration. Capsules captured under v0.6.2 are unaffected.

## Try it

```bash
# Run a stub upstream MCP server (any HTTP server that accepts JSON-RPC POST):
# (left as exercise — depends on which MCP server you're proxying)

# Then run nova mcp-proxy in HTTP mode pointing at it:
RUN=$(date +%Y%m%d-%H%M%S)
mkdir -p .novafabric/runs/$RUN/{inputs,outputs}
touch .novafabric/runs/$RUN/{model-calls,tool-calls,trace,assets}.jsonl

nova mcp-proxy \
  --capsule-dir .novafabric/runs/$RUN \
  --listen 127.0.0.1:8765 \
  --upstream-url http://localhost:9000/mcp

# In another terminal, point your MCP client at http://127.0.0.1:8765
# Every tools/call gets recorded into tool-calls.jsonl with
# transport_kind=http, plus streaming.{streamed,chunk_count} when
# the upstream responded with SSE.
```
