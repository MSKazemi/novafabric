# v0.106.1 — The release image builds again, and the collector clears a new Go advisory

**Released 2026-10-22.** A release-pipeline patch for [v0.106.0](v0.106.0.md). It changes no
library code, CLI behaviour or on-disk format: install it, or stay on v0.106.0 from PyPI, and you
get the same NovaFabric. Read the [v0.106.0 notes](v0.106.0.md) for that release's security
fixes and behaviour changes.

## What's in it

- **The container image builds and publishes.** `deploy/docker/Dockerfile` did not copy
  `scripts/pypi_readme_hook.py`, the hatch metadata hook that writes the PyPI long description,
  so building the v0.106.0 image failed with "Build script does not exist" and **no v0.106.0
  container image was published**. The PyPI release and the Helm chart for v0.106.0 were
  published. This is the third time a build input went missing from the image build context, so
  the packaging guard (`tests/packaging_metadata/test_dockerfile_force_includes.py`) now also
  checks every hatch hook script, not only `force-include` sources.
- **The collector clears GO-2026-6809.** Collector CI now pins Go 1.26.10. The advisory
  (`crypto/x509`: distrust compromised intermediate certificates) is fixed only there, and the
  v0.106.0 tag's `govulncheck` run failed on Go 1.26.9.

## Upgrade notes

None. If you deploy the container image, use `ghcr.io/mskazemi/novafabric:0.106.1`. There is no
`0.106.0` image.

## Try it

```bash
pip install --upgrade "novafabric==0.106.1"
nova --version                         # novafabric 0.106.1
```

## Verification

The new packaging guard fails on the v0.106.0 Dockerfile and passes with the fix. A wheel built
with `uv build --wheel --no-sources` from exactly the files the Dockerfile copies (`pyproject.toml`,
`uv.lock`, `README.md`, `src/`, `alembic/`, `schemas/`, `scripts/pypi_readme_hook.py`) succeeds.
The push gate (`make test-gate`, the full non-container suite) and the docs and packaging suites
pass on the release tree; the full release tier and every security check for this code line are
the ones recorded in the [v0.106.0 notes](v0.106.0.md#verification), since no library code
changed. The Go 1.26.10 pin is checked by the collector's own CI run on this tag.
