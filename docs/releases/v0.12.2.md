# v0.12.2 — Regulated-Industries ADR Formalizations

Released: 2026-05-14

This release adds two formal architecture decision records that freeze the design for
NovaSeal's dual-mode signing identity and the regulated-industries risk-tier classifier.
No new runtime code ships; both ADRs document decisions already made in the
nova-design SoA2Prod study and bring them into the main ADR series.

## What's new

### ADR-0055 — Dual-Mode Signing Identity

`design/adr/0055-dual-mode-signing-identity.md`

Formalizes ADR-002 from the regulated-industries research pipeline. Defines how NovaSeal
supports two mutually exclusive signing profiles selectable via `signing.profile` in
`novaseal.yaml`:

| Profile | Use case | Key material | External services |
|---|---|---|---|
| `x509` | Regulated production | ECDSA P-256 or RSA-2048+ in PKCS#11 HSM or PKCS#12 bundle; operator's internal CA | None at signing time; RFC 3161 TSA (internal or eIDAS) at timestamp time |
| `sigstore` | CI / cloud | Ephemeral X.509 cert issued by Fulcio CA bound to OIDC identity | Fulcio CA + Rekor transparency log (public or private instance) |

Both profiles produce **byte-identical DSSE envelopes** and **identical `.seal/` bundle
layouts** — verifier libraries need only trust-bundle configuration, not signing-mode
awareness.

**Implementation status:** The `x509` path ships today (NovaSeal v0.12). The `sigstore`
path is design-frozen by this ADR; code is deferred. The `signing.profile` key is
reserved; only `x509` is accepted at runtime.

Resolves open question OQ-1 (dual-identity signing). Updates ADR-0041 "Formalized by"
table.

### ADR-0056 — Rules-Based Risk-Tier Classifier

`design/adr/0056-risk-tier-classifier.md`

Formalizes ADR-005 from the regulated-industries research pipeline. Freezes the design
for `novafabric/governance/classifier.py`: a deterministic, rules-based classifier that
maps an `AISystemRecord` to EU AI Act tiers, NIST RMF impact levels, and OMB M-24-10
flags.

Key design choices:
- Rules stored in versioned YAML files under `novafabric/governance/vocabularies/`
- Every rule carries a regulatory citation (e.g., `"Regulation 2024/1689 Annex III item 5(b)"`)
- Classifier output includes matched rules + citation strings — readable by legal counsel
- Every classification event is a signed NovaSeal log entry (vocabulary version pinned)
- Works fully air-gapped — no LLM API dependency

**Why not ML?** Two regulatory constraints make ML unsuitable: (1) every classification
must cite a specific regulatory article — an LLM rationale is not a citation; (2) the
output must be deterministic — the same `AISystemRecord` must classify identically 6
months later, which an LLM cannot guarantee.

**Implementation status:** Design frozen. `novafabric/governance/` module is deferred
to v0.13+. The OPA policy gate (`nova promote`, ADR-0028) handles promotion-time
enforcement today; the risk-tier classifier is a complementary pre-classification step.
