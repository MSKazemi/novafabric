# NovaFabric v0.50.0 — SOTA Gap-Closure Wave 2 (first slices)

**Released:** 2026-06-12

Wave 2 of the 2026 SOTA landscape sweep lands its first vertical slices: the
structural/verifiability arc. Every feature in this release is gated behind a
freshly committed Architecture Decision Record (ADR-0086…0091 + the ADR-0041
v0.2 amendment) and ships as **experimental**.

## Highlights

### Intervention (counterfactual) replay — gap-005, ADR-0086

The fifth replay mode answers "what if step k had gone differently?":

```bash
nova replay path/to/capsule --mode intervention --intervention-file spec.yaml
```

A YAML `InterventionSpec` selects exactly one captured event (`event_index`
or `span_id`) and applies exactly one substitution (`replace_model_response`,
`replace_tool_result`, or `mutate_payload`). Downstream steps re-execute
under mocked-replay semantics; the output is a minimal Run Capsule
hard-marked `replay_mode: intervention` — diffable against the baseline with
`nova diff`, and never mistakable for an original run. Optional named
check-functions assert on the post-substitution streams; failures are
reported by name (never swallowed) and `fatal: true` aborts.

### Evidence completeness, criterion bindings, re-performance — gap-008, ADR-0087

Three additive evidence components, signed with the existing DSSE machinery:

```bash
nova evidence completeness <capsule> --key ed25519.pem
nova evidence bind <capsule> --profile eu-ai-act-high-risk --key ed25519.pem
nova evidence attest-replay <capsule> --key ed25519.pem --mode mocked
```

- **CompletenessAssertion** — per-stream event counts, drop counters, capture
  level, time window, active hooks: auditors can mechanically distinguish
  "no events occurred" from "events were not captured" (the Art. 12
  distinction).
- **CriterionBinding** — audit-profile control IDs bound to the exact capsule
  files (path + sha256 + optional JSONPath) that evidence them;
  re-checkable offline with `sha256sum`.
- **ReperformanceAttestation** — a signed statement that a replay of run X at
  time T reproduced outcome digest D under mode M with verdict V.

Pre-existing bundles still verify; all three blocks are optional.

### Incident records + Art. 73 deadline clock — gap-010, ADR-0088

```bash
nova incident open --title "..." --classification unauthorized_tool_use \
  --severity high --occurred-at ... --aware-at ... --run-id 01HX...
nova incident status <id>     # 15/10/2-day Art. 73 deadline table
nova incident export <id> --format aim|nis2
```

A persisted, lifecycle-tracked incident record (forward-only
`open → reported → closed`) anchored to run capsules, with the EU AI Act
Art. 73 reporting deadlines computed from awareness — plus OECD AIM export
alongside the existing NIS2 exporter. Operational aid, not legal advice.

### Forward-secure key ratchet — gap-015, ADR-0089

```bash
nova seal ratchet init --node-id node-a
nova seal ratchet rotate --node-id node-a
```

Per-node HKDF-SHA256 epoch chains with deterministic per-epoch Ed25519 keys:
compromise at epoch N cannot forge signatures for epochs < N. Rotation
best-effort erases the previous chain key; an append-only epoch-pubkey
registry detects epoch rollback. Opt-in — the static-key path is unchanged.

### Merkle log consistency proofs — gap-001 slice, ADR-0041 v0.2

```bash
nova seal log verify --consistency 1000   # exit 2 if the proof fails
```

`consistency_proof(old_size, new_size)` on both the SQLite and Postgres
Merkle logs, with an O(log n) offline verifier — an auditor can prove the
current log head is an append-only extension of an earlier head. The proof
scheme is an aligned perfect-subtree decomposition valid for the v0.1
duplicate-padding tree (a documented deviation from RFC 6962 §2.1). The
tiled-WORM transparency log (SI-8) and witness cosigning (SI-9) are recorded
as gated design intent.

### Column-level lineage facets — gap-003 slice 1, ADR-0090

```bash
nova lineage provenance 01HX... --with-facets
```

A conservative, stdlib-only extractor pulls table/column **names** (never
values) from SQL captured in tool-call events and attaches them to lineage
edges via the existing `facets` field. Fail-open: unparseable SQL means no
facet, never an error. The sparse-Merkle verifiable half (SI-10) is
spike-gated design intent.

## Also in this release

- **ADR-0091** records eBPF agentless capture (gap-012) as future design —
  explicitly not implemented; gated on SPK-EBPF-1/2/3 and ADR-0020.
- **gap-002 (cluster collector)** remains spike-gated per ADR-0020:
  SPK-COL-1/3 require n1 infrastructure; no collector code ships before the
  spikes resolve.
- `design/architecture/implementation-status.md` gains the SOTA gap-closure
  arc table, including retroactive Wave-1 rows (ADR-0080…0085, v0.49.0).

## Compatibility

No breaking changes. All schema additions are additive and optional; default
replay mode, seal verification, lineage output, and evidence bundle
verification are byte-compatible with v0.49.0 behavior.
