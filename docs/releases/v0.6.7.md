# v0.6.7 — Plugin reference + capture-overhead benchmark

Released: 2026-05-09

A tooling release closing two long-standing gaps: a working plugin
reference example for third-party hook authors, and a benchmark
harness that measures `nova capture` overhead against the
[ADR-0021 §6](../../design/adr/0021-ai-factory-design-intent.md) cost/overhead
budgets.

## What's new

### `examples/plugin-hook-reference/` — installable plugin template

A self-contained Python package that demonstrates the
`novafabric.hooks` entry-point contract end-to-end. Plugin authors
can clone it as a starting template for their own plugin.

```bash
uv pip install -e examples/plugin-hook-reference/
nova capture python -m novafabric_example_plugin.demo
# → captured record carries:
#   "io.novafabric.plugin_name": "acme-ai-reference"
#   "io.novafabric.capture_method": "plugin"
```

Six tests pass against the package in isolation, plus an end-to-end
smoke verifying the entry-point auto-discovers under a real
`nova capture` invocation.

The reference patches a fake "AcmeAI" SDK defined inline so the
example runs without any real third-party dependency. Real plugins
replace that with their actual SDK call site
(e.g. `cohere.Client.chat`, `vertex.GenerativeModel.generate_content`,
anything not already covered by the wire-level layer).

`docs/integrations/writing-a-hook-plugin.md` now references this
working example at the top, so the abstract recipe in that doc has
a concrete artifact to anchor on.

### `benchmarks/capture_overhead.py` — capture-overhead measurement

Stdlib-only harness (no `pytest-benchmark` dep) that compares
`nova capture <workload>` wall-clock time against running the same
workload raw. Reports median / p95 / mean / stdev plus the absolute
and percentage overhead.

```bash
uv run python benchmarks/capture_overhead.py
uv run python benchmarks/capture_overhead.py --workload httpx --n 50
```

Not run in CI (overhead measurement needs a stable runtime); the
harness is a manual tool for PR authors who change the hot path.

### Honest finding: current capture overhead is ~10× over budget

The first run on developer hardware showed:

```
raw subprocess         median=  12.4 ms
nova capture           median= 492.5 ms

capture overhead (median): +480.2 ms  (+3885.2%)
```

ADR-0021 §6 sets the no-op budget at ≤50 ms; the measurement is ~10×
over. **This release does NOT fix the gap** — it documents it and
queues optimization work for v0.7.x. The candidate optimizations are
listed in `benchmarks/README.md`:

- Lazy-load lineage emission until at least one capsule artifact is
  present
- Defer secret scanning to capsule finalization (currently runs at
  open AND at write)
- Skip OpenLineage event construction entirely when no transport
  is configured
- Profile capsule allocation — env-lock dump is the most expensive
  single step

The v0.6.x program was about feature completeness; v0.7.x will be
about hot-path optimization.
