# v0.12.7 — Dashboard Coverage Phase 1 + Autocomplete

Released: 2026-05-14

This release completes Dashboard Coverage Phase 1 — every shipped CLI capability and
cluster-scale component now has a dashboard UI or an interactive placeholder with CLI
guidance — and adds context-aware autocomplete to every database-reference input.
No CLI changes, no schema changes, no API-breaking changes.

## What's new

### Infrastructure tab

A new **Infra** tab appears in the sidebar under the Infrastructure group. It shows ten
Phase 0–6 cluster-scale component tiles, one per component:

| Tile | Status |
|---|---|
| Run Capsule | shipped |
| NovaSeal v0.1 | shipped |
| Event Envelope v1 | shipped |
| Collector tier | shipped |
| Parent/Child Capsule | shipped |
| Object Capsule Store | shipped |
| Metadata DB (Production) | shipped |
| Lineage at Scale | shipped |
| Server Mode | shipped |
| Eval Suites | shipped |

Each tile shows the component description, its `shipped / partial / placeholder / planned`
badge, and the CLI commands an operator can run to verify its status. The goal is to let
operators confirm which Phase 0–6 components are active without consulting the CLI or
docs separately.

### Commands tab — expanded to 35 builders

The Commands tab was 13 builders at v0.8. It is now 35, covering all major CLI entry
points across four journey tracks:

**Debug & Replay** — `nova inspect`, `nova validate`, `nova replay --mode forensic /
semantic / exact`, `nova diff`, `nova rollback`, `nova run show`

**Govern & Approve** — `nova register`, `nova promote`, `nova suggest-register`,
`nova unregister`, `nova export-evidence`

**Audit & Lineage** — `nova lineage provenance / blast-radius / replay-chain /
time-travel`, `nova audit`, `nova hold create / list / release`

**Infrastructure & Scaling** — `nova serve --experimental`, `nova server start /
issue-token / revoke-token`, `nova api-proxy`, `nova mcp-proxy`, `nova capture` (all
4 runners), `novafabric-collector`

Each builder renders a live command preview that updates as you fill in the form fields,
with a one-click copy button.

### Lineage QueryPanel

The Lineage tab gains an interactive query panel. To use it:

1. Open the Lineage tab.
2. Click "Query" (or the search icon) to expand the panel.
3. Type a ref (`name@version` for provenance or blast-radius; `run_id` for replay-chain).
4. Select a mode: **Provenance**, **Blast Radius**, or **Replay Chain**.
5. Press **Run**.

Results appear as a sortable table below. The CLI equivalent (`nova lineage provenance
<ref>`) updates live as you change the fields, so you can copy it to a terminal.

### Enriched CaptureTab

The Capture tab now documents:

- All four runner types (local, Docker, Kubernetes, Slurm) with the relevant flags.
- Distributed-run commands: `nova new-run-id`, `nova run show`, `nova run
  validate-distributed`.
- A full matrix of what `nova capture` records (10 items: model calls, tool calls,
  prompts, outputs, traces, environment lock, eval results, metadata, redaction proof,
  evidence bundle).

The tab is purely informational (Layer C operations remain CLI-only) but gives operators
a quick reference without leaving the dashboard.

### Context-aware autocomplete on all ref inputs

Every text input that accepts a database reference now shows a live-filtered suggestion
dropdown. As you type, up to eight matching items appear below the input; click to fill.
Pressing Escape dismisses without selecting. When the input is focused and empty, the
top eight items are shown immediately.

**Lineage tab — query panel ref input**

- Provenance / blast-radius mode: suggests `name@version` from the asset registry.
- Replay-chain mode: suggests `run_id` values extracted from loaded lineage edges.

**Diff tab — run A and run B inputs**

- Both inputs suggest `run_id` values from the full runs list (already loaded for the
  "Recent runs" and "Suggested pairs" panels below).

**Holds tab — registry name input in the place-hold form**

- Suggests registry names from the active-holds dataset already on-screen.

**Policy tab — resource ref input**

- When resource kind = `asset`: suggests `name@version` from the registry.
- When resource kind = `capsule` or `replay`: suggests `run_id` values from the runs list.
- The placeholder text updates to match the selected kind.

### Shared `SuggestInput` component

A new `web/src/components/ui/SuggestInput.tsx` encapsulates the suggestion dropdown:
click-outside dismissal, Escape key, form submission compatibility (Enter closes the
dropdown and bubbles so `onSubmit` still fires).
