# v0.102.0 — thirty ADR slices, a deployable dashboard, and an honesty sweep

**Released 2026-09-27.** Three through-lines. `nova serve` authenticated but never
authorized, and shipped from a chart whose default exposed signed evidence over plain
HTTP — both are fixed, and the chart now refuses to upgrade until you state your intent.
Thirty accepted-but-unbuilt ADR slices were built, in three batches, every one marked
**experimental**. And a long sweep went after the worst class of defect this project can
have: a surface that reported a verdict it could not support. Most of what is new here is
experimental and interface-unstable; the corrections are not.

## What's in it

| Area | What you can do now |
|---|---|
| **`serve` authorizes** (ADR-0228, experimental) | Possession of the one shared bearer token no longer grants every endpoint — including `DELETE /api/runs/{id}`, PII erase, seal bypass and `POST /api/admin/roles`. Scopes are enforced and an unclassified route denies everyone. The roles UI previously let an operator assign a role, see it listed, and believe access was restricted while **nothing in `serve/` ever read an assignment**. Additive; the default local posture is byte-identical. |
| **`serve` tenancy** (ADR-0229, experimental) | `serve` reads eight stores that do not share a tenancy model; each now declares `aware`/`agnostic`/`unsafe`, and the declaration is **checked against the store's real schema** rather than against itself. Multi-tenant is refused at startup rather than served unscoped. Single-tenant is the default and unchanged. |
| **Secure-by-default chart** (ADR-0230, **breaking**) | `mode: server` with OIDC/RBAC and `serve.insecure: false`. Setting `insecure: true` makes `helm template` **fail**, not warn. `mode: dashboard` stays fully supported when deliberately chosen — the problem was the default, not the option. |
| **The dashboard becomes data** (ADR-0231–0236, 0239, experimental) | Portable versioned dashboard/widget JSON (`nova dashboard`); a filter-bar grammar whose power ceiling is enforced by the DSL itself; `nova query --scope node\|root\|tree`; `ratio(a, b)` where undefined is not zero; the evidence cart, which resolves **once** so a collected set attests to a state that existed; and an audit log that records who acted, what changed, and what was refused. |
| **Trust chain, offline** (ADR-0055, ADR-0070, experimental) | x509 signer-certificate chain validation against an operator CA bundle, RFC 3161 TSA trust-chain verification, and offline CRL revocation checking — `nova verify --ca-bundle`, `--tsa-ca-bundle`, `--crl-dir/--crl-strict`. |
| **The assurance loop closes** (ADR-0147, experimental) | `nova assure-baseline`, `assure-canary record`, `assure-alarm check`, `assure-impact report`, `assure-run`, plus `nova replay-equivalence check\|regime` and `nova drift collect\|fingerprint`. The C3 behavioural-equivalence verdict was built and tested since v0.59.0 with no CLI to reach it; it is reachable now. |
| **Media & computer-use provenance** (ADR-0148, experimental) | `nova capture-ui` treats keystrokes as the hazard they are (scan-before-digest, per-capsule salt, stated residual risk); `nova provenance` binds a C2PA manifest to the exact bytes of a captured media part; `nova diff --media` compares by exact hash and optionally pHash; `nova toolschema conformance\|deprecations\|track`. |
| **Human oversight and consent** (ADR-0150, experimental) | Decision-context receipts, overrides and rationale, consent receipts, accountability handoffs and acted-on-behalf records — `nova hitl`, `nova consent`. |
| **Regulated-domain exporters** (ADR-0159, ADR-0208, experimental) | `nova export-cat` (CAT-style lifecycle trail), `nova export-adverse-action` (ECOA / Reg B specific reasons), validation-independence and retention-posture packs, plus `nova server usage reconcile\|export` and `GET /v0/usage/export` for chargeback. |
| **The rest of the slice program** (experimental) | Session index, portable session bundle and sub-range replay; A2A object mapping and Agent Card facet; embodied ODD, sim-to-real, teleop and timing evidence; agentic-science lab and instrument provenance; settlement payment chains; risk-transfer liability/SLA/coverage; shared-store access ledger and cross-run memory derivation; format-migration and LTV re-seal records; transitive `nova trust-path`; OTel GenAI severity in both directions; and an API deprecation removal gate. |
| **The honesty sweep** | The SLURM runner had been sealing `success` for cancelled, timed-out and OOM-killed jobs. `nova erasure request` reported a GDPR Art.17 erasure it never performed. Energy receipts claimed `confidence: measured` on hardware with no counter. A DSSE envelope's second signature was neither honoured nor detected. Azure Key Vault seals were silently unverifiable. `nova verify` now checks the capsule on disk is the one that was sealed. An unpriced model reported `$0.00`, which reads as free. The published v0.38.0 Scale-S4 latency claim is **withdrawn** — it was never met. The public decisions index was under-claiming eleven shipped features. |
| **Security, supply chain and onboarding** | The Kubernetes runner no longer ships your shell's environment into the cluster; the sdist and Docker build context no longer carry the private tree; the runtime image no longer runs as root; the capsule watcher's queue is bounded and degrades to rescan rather than dropping events; npm and gRPC-Go advisories patched with a standing audit gate. Capture adapters for **LlamaIndex, Pydantic AI and Haystack** (issues #1–#3), three runnable examples, an integrations guide, `docs/for-researchers.md`, and a CLA. |

## Upgrade notes

- **BREAKING — `--runner kubernetes` no longer inherits the submitting environment.** A
  workload that implicitly relied on a variable will now start without it. **Migration:**
  name it explicitly with `--runner-option extra_env='{"LOG_LEVEL":"debug"}'`. For anything
  secret do **not** use `extra_env` — its values land in the Job object — bind a
  `service_account` to a Kubernetes `Secret` instead. See `docs/operator-guide.md` §3.4.
  `--runner slurm` and `--runner docker` are unchanged; they already filtered, and their
  open-coded filters were replaced by the shared helper so the three cannot drift apart.
- **BREAKING (Helm chart) — the deployed default is secure now.** An upgrade **refuses**
  until you state your intent. To keep the old behaviour, set `mode: dashboard`,
  `serve.insecure: true`, `serve.acknowledgeInsecureExposure:
  i-accept-serving-evidence-over-plain-http` and `upgradeAcknowledged: true`. To take the
  new defaults, confirm you have read this with `upgradeAcknowledged: true`. A fresh
  install needs neither.
- **Everything else is additive.** No change to `schemas/run-capsule.*`; new facet fields
  and records ride existing `extra="allow"` facets, so every pre-existing capsule and
  envelope stays valid. `serve` authorization and tenancy are additive and leave the
  default local posture byte-identical.
- **Most of what is new is labelled `experimental`** — it ships and works, but the
  interface may change before the v1.0 schema freeze. The corrections in the honesty sweep
  are not experimental.
