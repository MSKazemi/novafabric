# v0.6.12 — Live cluster validation complete + Ollama URL registry

Released: 2026-05-10

Two self-contained improvements, both surfaced by or in support of live
SLURM cluster work. v0.6.12 closes the v0.6 SLURM live-validation track:
the cluster now submits (`v0.6.10`), captures on compute nodes (`v0.6.11`),
and survives the scheduler placing a job on a node other than the submit
node (`v0.6.12`). In parallel: Ollama local inference is now captured
out of the box with no user configuration required.

## What's new

### `SlurmRunner` live smoke tests use shared filesystem

The existing `TestSlurmRunnerLiveSmoke` class placed capsule directories
in `tmp_path`, which is node-local `/tmp`. That works when the SLURM
scheduler happens to run the job on the same machine as the submit node —
but the moment it allocates a different compute node, the job fails at
startup because `capsule_dir` does not exist on the compute node.

This release adds a `shared_tmp` pytest fixture that respects a new
environment variable `NOVAFABRIC_SLURM_SHARED_DIR`:

- **If set** (e.g. `/home/vagrant` or `/scratch`): creates a uniquely-named
  subdirectory there and removes it on teardown. The directory lives on
  the cluster's shared filesystem (NFS, Lustre, GPFS) and is visible from
  every compute node.
- **If not set**: falls back to `tmp_path` so the default run on a laptop
  (or single-node CI cluster) keeps working.

The `test_echo_succeeds` live smoke test now uses `shared_tmp` instead of
`tmp_path`, removing the node-locality assumption.

### `test_sitecustomize_fires_on_compute` — wire-capture e2e live test

New opt-in test (requires `NOVAFABRIC_SLURM_VENV_PYTHON` to be set) that
runs a real SLURM job on a compute node, makes an httpx call inside it,
and asserts `model-calls.jsonl` is present on the shared filesystem after
the job completes.

This is the automated version of the manual `scripts/live_slurm_capture_e2e.py`
validation from v0.6.11. Running it requires:

```bash
export NOVAFABRIC_SLURM_SHARED_DIR=/home/vagrant   # any shared-FS path
export NOVAFABRIC_SLURM_VENV_PYTHON=/home/vagrant/novafabric-venv/bin/python3
export NOVAFABRIC_SLURM_PARTITION=debug
uv run pytest tests/test_runners_slurm.py::TestSlurmRunnerLiveSmoke -k sitecustomize -v
```

An optional `NOVAFABRIC_SLURM_VENV_SITE` env var can be set to a
site-packages path that gets prepended to `PYTHONPATH` on the compute node
when needed.

### Ollama local inference captured out of the box

`url_registry.yaml` gains two new entries:

```yaml
- match: "localhost:11434"
  gen_ai_system: "ollama"
  transport: "http"

- match: "127.0.0.1:11434"
  gen_ai_system: "ollama"
  transport: "http"
```

Port 11434 is Ollama's default. After this release, any httpx or requests
call to a local Ollama server is classified as `gen_ai.system=ollama` and
recorded into `model-calls.jsonl` with no user configuration.

Non-default ports, remote hosts, or other deployment configurations that are
not reachable at localhost can be captured by adding entries to
`~/.novafabric/url_registry.yaml` (or `$NOVAFABRIC_URL_REGISTRY`). An
override file replaces the bundled default entirely.

## Breaking changes

None. `NOVAFABRIC_SLURM_SHARED_DIR` is a new opt-in environment variable
with no effect when unset. The Ollama URL registry entries are additive —
the override mechanism continues to replace the bundled file entirely when
set.

## What the v0.6 SLURM track has now validated

Three distinct failure modes caught and fixed by running against a real
3-node cluster:

| Release | What was broken | Fix |
|---|---|---|
| v0.6.10 | `sacct` times out when `slurmdbd` not running | `scontrol` primary path |
| v0.6.11 | Compute nodes ran bare — no hooks, empty capsules | `sitecustomize.py` injection |
| v0.6.12 | Jobs fail when scheduler picks a different node than submit node | `shared_tmp` fixture + `NOVAFABRIC_SLURM_SHARED_DIR` |

All three represent the kind of failure that only surfaces on real
infrastructure. The mock-based unit test suite could not have caught any
of them. The recommended operational pattern for anyone deploying SlurmRunner
is now: set `capsule_dir` to a path on shared filesystem (NFS, Lustre, GPFS)
before calling `SlurmRunner().run()`.
