## Track A — Evidence Fabric v1.0 (ADR-0066, proposed)

The first six cap-* primitives of the Evidence Fabric v1.0 pipeline are now
implemented as additive, optional-extra modules. Each is stub-grade for the
infrastructure boundaries it doesn't own (NATS, ClickHouse, S3 endpoint) and
fully tested behind those boundaries with mocks.

### What's new

- **cap-001 Capsule Event Schema** — `src/novafabric/schemas/event_schema.py`
  ships `CapsuleEventType` (25 enum values), `CostFacet`, and `RunEnvelope`
  Pydantic models, plus `schemas/capsule-event-v1.schema.json` (draft 2020-12).
  `nova schema list` is the inspector CLI.
- **cap-002 LLM Cost Attribution** — `cost/interceptor.py` extracts a
  `CostFacet` from OpenAI / Anthropic SDK response objects (6-entry price
  table). `nova cost report` is a stub gated on a ClickHouse cluster.
- **cap-003 Dual-Object GDPR/WORM Split** — `storage/dual_object_store.py`
  splits a capsule into a PII-redacted audit record (WORM) plus a separately
  addressable PII payload object (GDPR-erasable). BLAKE3 digest with SHA-256
  fallback. **Disabled by default**: `NOVA_CAP003_ENABLED=false` until
  OQ-01 (legal review of the no-PII contract) resolves.
- **cap-004 Capture-Level Policy Engine** — `policies/capture_level.py`
  enforces four allowlist tiers: `minimal` (no payloads), `standard`
  (prompts redacted), `forensic` (full payloads), `air_gapped` (no egress).
  Config via `NOVA_CAPTURE_LEVEL`. `nova policy capture-level get/set` CLI.
- **cap-006 LineageConsumer Stub** — `lineage/consumer.py` is a NATS
  JetStream pull-consumer stub plus a pure-Python edge extractor for
  `SPAWNED_BY`, `PRODUCED`, `CONSUMED_BY`, `EVAL_BY`. Per-event-id dedup.
  `run_once()` works without NATS (test mode).
- **cap-009 S3-API Abstraction** — `storage/nova_object_store.py` is a thin
  boto3 wrapper exposing `put_capsule`, `get_capsule`, `validate_object_lock`
  with a configurable `endpoint_url`. `nova storage validate / inspect` CLI.

### Optional dependency extra

```toml
novafabric[scale] = [
  "nats-py>=2.9",            # cluster event bus (ADR-0061)
  "clickhouse-connect>=0.7", # cost rollup tier
  "fastavro>=1.9",           # event serialisation
  "pyiceberg>=0.7",          # cost facet table format
  "blake3>=0.4",             # high-throughput content addressing
  "boto3>=1.38",             # S3 / Object Lock
]
```

All Tier-A licenses under [ADR-0024](../../design/adr/0024-dependency-license-policy.md).

## Track B — Capsule Knowledge Graph v1 (ADR-0067, proposed)

A SECOND KuzuDB instance, intentionally separate from the lineage graph, that
aggregates per-capsule observations into a cross-capsule **knowledge graph**
of agents, models, tools, and routes. This is the foundation for the v1.2
dashboard "AI call graph" visualization layer.

### What's new

- **`KGStore`** (`kg/store.py`) — thread-safe KuzuDB-backed store. Uses a
  read-then-write edge upsert as a KuzuDB 0.11.3 compatibility workaround
  (see ADR-0067 §Spike result).
- **`EntityNormaliser`** (`kg/entity_normaliser.py`) — Tier-1 pure-Python
  canonicalisation: OTel GenAI semconv model-name patterns
  (e.g. `gpt-4o-2024-08-06` → `openai/gpt-4o`), URL normalisation (strip
  query, upgrade http→https, strip trailing slash), case normalisation.
- **`GCounter` / `CRDTAccumulator`** (`kg/crdt.py`) — grow-only CRDT
  counters for `call_count` / `verified_count`, mergeable across
  distributed collectors via elementwise-max. `confidence` is derived.
- **`KGIngestionPipeline`** (`kg/pipeline.py`) — five-stage pipeline:
  `event → normalise → resolve → accumulate → flush`. Handles
  `ModelCallCompleted`, `ModelCallStarted`, `ToolCallCompleted`,
  `ToolCallStarted`, `EndpointRouted`.
- **`nova kg init / status / ingest / query`** — CLI surface.

### Optional dependency extra

```toml
novafabric[scale-kg] = ["kuzu>=0.11.3"]   # MIT, Tier A under ADR-0024
```

Separate from `[lineage-kuzu]` so users can opt-in to KG without committing
to the cluster-scale lineage tier.

## Track C — TV-5 3D Topology View (ADR-0068, proposed)

A 3D companion to the existing 2D Sigma.js topology dashboard. Backed by the
same ADS encoder + DeltaBuffer, but with a separate snapshot store, layout
pipeline, REST/WS router, and React component.

### What's new

**Server-side:**

- **`SnapshotStore3D`** (`serve/topology/snapshot_store_3d.py`) — atomic
  msgpack (preferred) / JSON snapshot writer with fine (5 s) and coarse
  (60 s) retention tiers.
- **`LayoutPipeline3D`** (`serve/topology/layout_pipeline_3d.py`) —
  networkx `spring_layout` two-pass (X/Y from one seed, Z from another)
  inside a `ProcessPoolExecutor`. This resolves **OQ-030** (Python fa2
  blocked at 100K nodes) by avoiding fa2 entirely on the server side.
- **TV-5 REST + WS router** (`serve/topology/router_tv5.py`):
  - `GET /api/tv5/live`
  - `GET /api/tv5/windows`
  - `GET /api/tv5/snapshot/{window_id}` — `window_id` constrained to
    `^[a-z0-9_-]+$` to block path traversal
  - `WS /api/tv5/ws`
- **`nova serve --tv5`** CLI flag.

**Client-side:**

- **`TV5Panel.tsx`** — React component (Three.js via `@react-three/fiber`
  + `@react-three/drei`):
  - `InstancedMesh` for nodes (one mesh per node type)
  - `LineSegments` for edges
  - `OrbitControls` for camera
  - p99 latency health color encoding (green/yellow/red)
  - Time slider over `windows`
  - Click-to-select node → emits to existing dashboard inspector
- Dashboard `package.json` gains `three`, `@react-three/fiber`,
  `@react-three/drei`. Static bundle rebuilt
  (`src/novafabric/serve/static/topology/assets/index-6lWZH2Rq.js`).

## What's deferred / open

- **OQ-01** — legal review of the cap-003 no-PII audit contract. Until this
  closes, `NOVA_CAP003_ENABLED` defaults to `false` and the dual-object path
  is dormant.
- **NATS cluster** — `LineageConsumer.run()` requires a NATS JetStream
  cluster (ADR-0061). The `run_once()` test harness works without it.
- **ClickHouse cost rollups** — `nova cost report` is a stub until a
  ClickHouse instance is wired in.
- **KG: KuzuDB 0.11.3 MERGE atomicity** — works around the issue with a
  read-then-write upsert, locked by a per-store mutex. The follow-up
  spike to validate true `MERGE` atomicity in a later KuzuDB release is
  recorded in ADR-0067.
- **TV-5 LOD billboards** — only `InstancedMesh` nodes are implemented;
  the level-of-detail billboard fallback for >100K nodes is deferred to
  v0.18 alongside a load-test.
