# v0.6.5 — OpenAI streaming-delta merge + capsule auto-allocation

Released: 2026-05-09

This patch closes the v0.6.4 "streaming aggregation queued for v0.6.5"
promise and removes the awkward `mkdir + touch *.jsonl` ceremony from
the api-proxy / mcp-proxy try-it flow.

## What's new

### OpenAI streaming-delta merge in `nova api-proxy`

Streaming SSE responses from OpenAI-compatible endpoints (`stream: true`
in the request body) are now **merged into a synthesized non-streaming
response envelope** for capture purposes:

- Content deltas concatenate into the final assistant message
- Tool-call deltas accumulate by `tool_calls[i].index` — `id`,
  `function.name`, and `function.arguments` are each rebuilt piecewise
- `usage` is pulled from the final stream event when
  `stream_options.include_usage = true`
- `finish_reason` is captured from the choice that emits one
- Top-level `id`, `model`, `created`, `system_fingerprint` carried through

The captured record now has a populated
`gen_ai.response.choices[0].message.content` (full assistant text),
`gen_ai.response.finish_reasons`, `gen_ai.response.id`,
`gen_ai.response.model`, and `gen_ai.usage.{input,output}_tokens` —
even for streaming captures. Before v0.6.5, streaming records had only
the `streaming.{streamed: true, chunk_count}` flag and no merged
response.

The original SSE byte stream is still forwarded to the client unchanged
(this only affects the recorded record, never the client's UX).

The OpenAI delta-merge handles the long tail:
- `data: [DONE]` sentinel correctly skipped (not parsed as JSON)
- Malformed events in the middle of the stream silently dropped
  (capture is a recorder, not a validator)
- Tool-call argument JSON re-assembled across event boundaries

Anthropic streaming uses a different SSE event-type model
(`message_start`, `content_block_delta`, `message_delta`, `message_stop`)
and is queued for v0.6.6.

### Capsule auto-allocation in proxies

`nova api-proxy` and `nova mcp-proxy` now resolve the capsule directory
in three steps:

1. **`--capsule-dir` given:** use it; auto-create if it doesn't exist
2. **`NOVAFABRIC_CAPSULE_DIR` env var:** use it; auto-create if missing
3. **Neither:** allocate a fresh ULID-named directory under
   `$PWD/.novafabric/runs/<run-id>/` and announce the path in the
   startup banner

Before v0.6.5, both proxies errored if the capsule dir didn't exist,
forcing users to do this manually:

```bash
RUN=01$(date +%y%m%d-%H%M%S | tr -d '-')000000000000
mkdir -p .novafabric/runs/$RUN/{inputs,outputs}
touch .novafabric/runs/$RUN/{model-calls,tool-calls,trace,assets}.jsonl
nova api-proxy --capsule-dir .novafabric/runs/$RUN ...
```

Now the same flow is just:

```bash
nova api-proxy \
  --listen 127.0.0.1:8765 \
  --upstream-url https://api.anthropic.com
# nova api-proxy listening on http://127.0.0.1:8765 → https://api.anthropic.com
# Allocated capsule: /home/.../.novafabric/runs/01HX…
# Recording to: /home/.../.novafabric/runs/01HX…
```

The startup banner shows where the capsule lives so the user can find
the records after the session.

`CapsuleWriter.open()` (which proxies use) is idempotent — `mkdir
parents=True, exist_ok=True` plus per-file `touch` — so existing
capsule directories with prior contents are unaffected.

## Quality

- **651 tests passing** (was 645 at v0.6.4; **+6** new — six streaming-
  merge tests covering content concatenation, tool-call accumulation,
  usage extraction, [DONE] sentinel handling, malformed-event resilience,
  and the streaming-extension-coexists assertion)
- **89.63% coverage**
- ruff clean, mypy strict clean across 90 source files

Three older CLI tests inverted from "errors when capsule dir missing"
to "auto-allocates when capsule dir missing" — the previous behavior
was the bug; the new behavior is the feature.

## Breaking changes

**One semantic change** to `nova api-proxy` and `nova mcp-proxy`:
previously, omitting `--capsule-dir` (and the env var) caused the
command to error with "Set --capsule-dir or NOVAFABRIC_CAPSULE_DIR".
Now it auto-allocates. Anyone scripting against the old error behavior
should pass an explicit `--capsule-dir` to keep the previous semantics
(or check exit codes — auto-allocation succeeds, the old behavior
exited 2).

No other CLI surface changed; no schema changed.

## Upgrade

```bash
pip install --upgrade novafabric==0.6.5
```

No migration. Existing capsules from v0.6.4 are unaffected.

## Try it (capture Claude Code, now in 2 commands instead of 5)

```bash
# Terminal 1: start the proxy (capsule auto-allocated)
nova api-proxy \
  --listen 127.0.0.1:8765 \
  --upstream-url https://api.anthropic.com
# → Allocated capsule: ./.novafabric/runs/01HX…
# → nova api-proxy listening on http://127.0.0.1:8765 → https://api.anthropic.com

# Terminal 2: point Claude Code at the proxy
ANTHROPIC_BASE_URL=http://127.0.0.1:8765 claude
```

Each LLM round-trip (streaming or not) lands in
`.novafabric/runs/<run-id>/model-calls.jsonl` with the merged response,
finish_reason, usage, and full semconv field set.
