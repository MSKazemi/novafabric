# v0.12.9 — Dashboard UX polish + promote dialog fixes

Released: 2026-05-14

Patch release focused entirely on the experimental dashboard. Three promote-dialog bugs
fixed; nine UX improvements across eight tabs added in a single parallel build pass.
No CLI changes, no schema changes, no API-breaking changes, no new dependencies.

---

## Bug fixes

### Promote dialog: invalid target statuses now disabled (Bug-1)

The "Target status" segmented button in the Registry tab Promote dialog previously
allowed selecting any of the three statuses (`staging`, `production`, `archived`)
regardless of the asset's current status. This meant a user could click "Promote"
on an `archived` asset and select `production` as the target — a transition the server
correctly rejects with `409 Conflict` — and the UI gave no indication of the error
until the server returned an error toast.

From v0.12.9, a new `validTargetsFor(status)` helper enforces valid transitions
client-side:

| Current status | Valid targets |
|---|---|
| `development` | `staging`, `archived` |
| `staging` | `production`, `archived` |
| `production` | `archived` |
| `archived` | `staging` |

Invalid target buttons are rendered at 30% opacity with `cursor-not-allowed` and
`disabled` so they cannot be clicked.

### Promote dialog: inline error banner on server rejection (Bug-2)

When a promote request returned a `4xx` response (e.g., `409 Conflict` for invalid
state transitions, `403 Forbidden` for policy denial), the dialog closed after
flashing a disappearing toast, leaving the user without actionable feedback.

From v0.12.9, promotion errors appear as a persistent inline banner inside the dialog
directly below the target buttons. The dialog stays open so the user can adjust their
selection (e.g., enable `--force` or pick a valid target) without reopening it.

The banner is cleared when the user changes the target or cancels the dialog.

### Promote dialog: eval-gate copy conditional on asset type (Bug-3)

The promote dialog description always appended "Agent assets must have a passing eval
unless `--force` is used" regardless of the asset's type. This was misleading for
non-agent assets (`model`, `dataset`, `tool`, `config`) which do not have an eval
gate.

From v0.12.9, the eval-gate copy only appears when `asset_type === 'agent'`.

## UX improvements

### DU-1 — RunsTab status filter pill-bar

A pill-bar above the runs table now provides one-click filtering by run status:
**All · running · success · failure · error**. The filter is applied client-side
(no additional API call). Selected pill uses the accent colour. Resets to "All" on
each data refresh.

### DU-2 — RunsTab copy run ID

A clipboard icon appears on hover next to each run ID in the table. Clicking it
calls `navigator.clipboard.writeText` on the UUID and shows a brief "Copied" label
(1.5 s). The icon is hidden by default and only visible on row hover to keep the
table uncluttered.

### DU-3 — Lineage ancestry breadcrumb

When a node is selected in the lineage DAG, a compact breadcrumb row appears above
the graph: `root → … → parent → **selected**`. Each ancestor is clickable — clicking
re-selects that node and updates the side panel. The breadcrumb is hidden when the
selected node is already the root (no incoming edges). Cycles in the graph are guarded
with a visited-set to prevent infinite traversal.

### DU-4 — Diff tab: sessionStorage persistence

After a successful diff, the `fromId`, `toId`, and full diff result are saved to
`sessionStorage` under the key `nova_diff_last`. Navigating away and back to the
Diff tab restores the last comparison without re-fetching from the server. The stored
value is cleared whenever the user changes run A or run B. `JSON.parse` is wrapped in
`try/catch` to handle corrupted storage gracefully.

### DU-5 — Registry tab: bulk promote

A checkbox column is added to the asset lifecycle table, with a select-all master
checkbox in the header. When one or more assets are checked, a floating action bar
appears at the bottom of the viewport:

```
3 selected  [Promote 3]  [Deselect all]
```

Clicking "Promote N" sequentially calls `api.promoteAsset` on each selected asset
using `nextStatusFor(current_status)` as the target, then flashes a summary:
"Promoted 3" or "Promoted 2, 1 failed" on partial failure. Selections clear on
every data refresh.

### DU-6 — Audit tab: action-type filter

A `<select>` dropdown is added between the search input and the result filter in the
Audit tab. The available action types are derived dynamically from the loaded entries
(no hardcoded list) so any new action types in future releases appear automatically.
Default is "All actions". The filter resets on every data refresh.

### DU-7 — Home tab: staleness indicator

Resume cards on the Home tab now show an amber border when the `ts` timestamp on the
card is older than 24 hours. Hovering over a stale card shows the tooltip:
"Last updated X — may be stale". Cards updated within 24 hours retain the default
border. The 24-hour threshold is a named constant `STALE_MS` at the top of the
component.

### DU-8 — Capture tab: open capsule folder

A "Recent capsules" section at the bottom of the Capture tab fetches the 5 most
recent runs and renders each with an **Open folder** anchor link (`file://` protocol)
when `capsule_path` is non-null. This removes the friction of copy-pasting paths into
a file manager.

### DU-9 — Policy tab: client-side Rego syntax feedback

A Rego source textarea is added to the Policy tab. A `lintRego()` function runs with a
300 ms debounce and checks for two common mistakes: missing `package` declaration and
unbalanced braces. When an issue is detected, an advisory warning banner appears
below the textarea:

```
⚠ Missing package declaration — advisory only, you can still save
```

The banner is advisory only — the user can still submit the policy. It clears when
the issue is resolved.

## Upgrade

`pip install --upgrade novafabric`

No migration required. No database changes. No schema changes.
The dashboard bundle is embedded in the package; `nova serve --experimental` will serve
the updated UI immediately after upgrading.
