# NovaFabric v0.64.0 — 2026-07-24

The **four-cohort integration release**: one merge brings together the backup
full-coverage cohort, the top-10 must-have campaign, the graph-intelligence
cohort, and phases A+B of the enterprise dashboard program — 22 ADR first
slices (0198–0217), reconciled to a single coherent surface. Everything new is
`experimental`. Full detail: `CHANGELOG.md` §[0.64.0].

## Highlights

### Back up ALL the things, restore, open and read (ADRs 0216/0217)
- **Full local coverage** — `nova backup create` now packs every persistent
  store (incidents, metadata, the PII DEK store, seal transparency log, TSA
  nonces, ratchet state, dashboard DuckDB, spool, the hash-chained audit log)
  with a **signed coverage table**: what a set does NOT contain is recorded
  evidence, never silence. Sensitive members restore 0600; key material only
  under the `--include-keys`/`--restore-keys` dual opt-in.
- **Automated pg restore** — `nova restore` dispatches on the verified
  manifest: refuse-non-empty without `--force` (which first takes a safety
  dump), single-transaction `pg_restore` (failure leaves the target
  unchanged), alembic-to-head, manifest-anchored row counts, RLS re-applied
  and proven. The DSN never appears in any output.
- **Manifest-only profile** for WORM deployments — chain-head pinning against
  the live bucket, WAL-drain guard, ancestor verification + metadata rebuild
  on restore, distinct exit 2 when the bucket is unreachable.
- Proven end to end: backup → offline verify → restore into a fresh home →
  registry, lineage, capsules, incidents, metadata, seal log, and PII
  decryption all read back through the real APIs; shredded subjects stay
  shredded — even for shreds applied *after* the backup was taken.

### Top-10 must-have campaign (ADRs 0202–0211)
- **Python client SDK** (`novafabric.client`) — sync httpx REST client for
  `/v0` with typed errors and bounded retries.
- **Ingest hardening** (real zip-slip fix), **FTS5 content search**
  (`nova search`), **webhook registry** (`/v0/webhooks`), **keyset pagination
  + capsule delete/bulk-delete**, **verified batch import** (`nova import`),
  **usage metering + workspace quotas** (`/v0/usage`), **`capture.record`
  façade** (+ a redaction-hole closure), and **real REST erasure** (the
  silent no-op stubs now execute DEK crypto-shreds with receipts).
- **Schema-skew guard + migration tracks** (ADR-0211 Part B) — a fail-closed
  startup guard against new-code-on-old-schema and `nova db upgrade --track`
  closing the dual-alembic wrong-database trap. (Part A's parallel restore
  path was superseded at merge by ADR-0217 — one restore path ships.)

### Graph intelligence (ADRs 0212–0215)
- `nova lineage metrics` (degree/PageRank/betweenness/articulation points),
  `nova lineage root-cause` (ranked upstream suspects, refuses to fabricate),
  `nova lineage export-graph` (GraphML/GEXF/Cypher), and `nova insights`
  (one synthesized health report) — all read-only, zero new dependencies.

### Enterprise dashboard program, phases A+B (ADRs 0199–0201)
- Stdlib SVG chart engine with server-side report HTML/PDF, client chart
  export (SVG/PNG), dashboard scale slices (bounded queries, keyset cursors),
  a CLI↔dashboard parity-classification CI guard, and a generic compliance
  export registry.

### Security (ADR-0198)
- Device-grant demo-flow hardening + pinned JWT algorithms — closes the one
  exploitable-as-shipped finding from the 2026-07-24 audit.

## Upgrade notes

- Backup manifest schema is now **0.2.0** (additive): pre-0.64 sets verify
  and restore unchanged; pre-0.64 binaries reject 0.64 manifests.
- Default backup sets now include the PII DEK store — treat backup sets as
  sensitive artifacts and store them encrypted at rest
  (`docs/ops/backup-restore.md`).
- No breaking CLI/API/schema changes; every new surface is additive and
  `experimental`.
