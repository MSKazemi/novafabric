# v0.6.10 — SlurmRunner: live cluster validation + slurmdbd-independence fix

Released: 2026-05-09

This release ships a **real bug fix** the v0.6.1 SlurmRunner unit
tests missed — surfaced by validating against an actual SLURM
cluster for the first time. Closes the v0.6.x acceptance gap the
ROADMAP explicitly listed for the SLURM runner.

## What's new

### `SlurmRunner` no longer requires `slurmdbd`

The v0.6.1 SlurmRunner polled exclusively `sacct` for job state.
That works fine on production clusters with `slurmdbd` (the SLURM
accounting database) running, but **fails silently on dev / minimal
clusters where `slurmdbd` is not installed** — `sacct` returns
nothing useful, the runner times out, and the user sees
`runner_status: timeout` even when the job actually completed.

This release adds a primary state-query path through `scontrol show
job <jobid>`, which reads directly from `slurmctld` memory and
works without `slurmdbd`. `sacct` becomes the fallback (still
needed once `slurmctld` forgets the job, ~5 min after completion).

State-query strategy added in `_query_state(jobid)`:

1. **`scontrol show job <jobid>`** — fast, slurmdbd-independent.
   Parses `JobState=...` and `ExitCode=N:M` from the output.
2. **Fallback to `sacct -j <jobid>`** — used when scontrol returns
   "Invalid job id" (job aged out of slurmctld memory) or when
   scontrol is unusable.
3. Returns `(None, "")` if both fail; the caller's polling loop
   continues until terminal state or timeout.

### How this was found

The v0.6.1 SlurmRunner had 18 unit tests, all mock-based. They
passed cleanly because the mocks gave back the `sacct` shape the
runner expected. Real-world validation against the founder's local
3-node Vagrant + libvirt SLURM cluster (Ubuntu 22.04, no slurmdbd)
surfaced the bug on the first run:

```
== Live SlurmRunner smoke (v0.6.9, before fix) ==
  exit_code      : 124
  runner_status  : timeout
  runner_error   : sacct still reports state 'PENDING' after 120.0s
  job_id         : 10
  final_state    : PENDING

  stdout (17 bytes):
hello-from-slurm        ← the job actually ran fine!

FAIL
```

The job actually completed and wrote `hello-from-slurm` to the
output file. But sacct never reported COMPLETED because slurmdbd
wasn't running. The runner concluded "timeout" while the cluster
sat idle.

After the fix:

```
== Live SlurmRunner smoke (v0.6.10, after fix) ==
  exit_code      : 0
  runner_status  : completed
  job_id         : 11
  final_state    : COMPLETED
  sacct_exit     : 0:0

  stdout (17 bytes):
hello-from-slurm

PASS
```

### `scripts/live_slurm_smoke.py` — minimal pytest-free smoke harness

For anyone validating SlurmRunner against a real cluster: a small
script that submits an `echo` job through SlurmRunner and prints
the result. No pytest dependency.

```bash
# On a SLURM submit node, with novafabric installed:
python /path/to/live_slurm_smoke.py [partition] [output_dir]
```

Defaults: `partition=debug`, `output_dir=$HOME/nova-slurm-smoke`.

This is the script that surfaced the slurmdbd bug. Documented for
reproducibility — run it on your own cluster to verify SlurmRunner
works there too.

### Cluster topology validated

| Component | Detail |
|---|---|
| Cluster | 3-node Vagrant + libvirt VMs (Ubuntu 22.04) |
| Roles | controller (slurmctld + slurmd + NFS server) + 2× compute (slurmd + NFS client) |
| Resources | 6 vCPU, ~6 GB RAM total |
| Partitions | `debug` (1h limit, 3 nodes) + `compute` (unlimited, 2 nodes) |
| Auth | munge with shared 1024-byte key |
| Shared FS | `/home` and `/scratch` NFS-shared from controller |
| **Notably missing** | **slurmdbd** — and that's the point |

Per the ROADMAP's "validated against at least 2 distinct SLURM
cluster configurations" gate: this is configuration #1. Configuration
#2 (a real production HPC cluster, with slurmdbd) is queued for
when one is reachable.

## Quality

- **672 tests passing** (was 667 at v0.6.9; **+5** new — covering
  the scontrol-first state-query strategy + the parse helpers)
- **90.03% coverage** maintained
- ruff clean, mypy strict clean across 90 source files

The new tests directly assert the fix:

- `test_scontrol_used_first_when_available` — proves the primary
  state path uses scontrol; sacct is NEVER called when scontrol
  returns successfully (1 subprocess call, not 2)
- `test_sacct_fallback_when_scontrol_returns_nonzero` — proves
  the fallback fires when scontrol returns "Invalid job id"
- `test_returns_none_when_both_fail` — both fail gracefully
- `test_parse_scontrol_output` / `..._with_invalid_jobid` — the
  parser handles real scontrol output and the absent-JobState case

## Breaking changes

None for callers. Internally, `SlurmRunner.__init__` gains a new
`scontrol_bin` keyword (default `"scontrol"`) and `supports()` now
also probes for the `scontrol` binary. Existing user code that
constructed `SlurmRunner()` with no arguments continues to work
unchanged.

## Reproducing the live validation

The cluster used is documented at
`/home/mohsen/scratch/lpt/projects/slurm/USAGE.md` (founder's
machine). The reproduction recipe for any 3-node Vagrant + SLURM
cluster:

```bash
# Build a wheel and copy to the controller
cd novafabric
uv build --wheel
scp dist/novafabric-0.6.10-py3-none-any.whl controller:~/

# Set up a Python 3.12 venv on the controller (NFS-shared home so
# compute nodes see the same interpreter)
ssh controller
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH=$HOME/.local/bin:$PATH
uv python install 3.12
uv venv --python 3.12 ~/novafabric-venv
uv pip install --python ~/novafabric-venv/bin/python ~/novafabric-0.6.10-py3-none-any.whl

# Run the smoke
~/novafabric-venv/bin/python /path/to/live_slurm_smoke.py debug
```

`live_slurm_smoke.py` is shipped in `dist/` next to the wheel.
