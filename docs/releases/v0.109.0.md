# v0.109.0 — Replay that refuses rather than pretends: what it cannot serve, it names

**Released 2026-11-22.** A replay-fidelity release. Before it, a mocked replay could end
`status: success` while a model call, a framework tool body or a network connection ran live and was
not counted. Now a strict mocked replay serves each recorded call it can, refuses before anything
runs a capsule holding one it cannot serve, and fails on a connection past loopback that it did not
serve; `--permissive` counts an unservable recorded model call that runs live through `httpx`,
`requests` or `urllib3`. **This release changes behaviour. Read
[Behaviour changes and upgrade notes](#behaviour-changes-and-upgrade-notes) before upgrading.**

## What's in it

### A strict replay that stops instead of running something live

- **Model calls replay cannot serve are refused before anything runs** (works today, ADR-0319). A capsule
  holding one ends `status: aborted` with `ModelSurfaceNotServable` (count and endpoint hosts per
  `gen_ai.system`), exit `1`, also under `--dry-run`, which lists each as `[LIVE] model call (...)`.
- **A connection past loopback fails a strict replay** (works today, ADR-0319 amendment). Served surfaces
  never open a socket, so any other IPv4/IPv6 connect by the replayed process, or by a Python child that
  reported in, is the divergence `unserved_network`, with the destinations named. The connection is
  observed, not blocked; `--hermetic` blocks.
- **The replay report says what its network count covers.** Connection outcomes per `host:port`, the child
  processes the workload started, and whether each Python child's network was observed
  (`network_observation_coverage`); an unobserved child makes the count a lower bound (works today).
- **`--permissive` counts what ran live.** An unservable recorded model call that went to the network through
  `httpx`, `requests` or `urllib3` is counted in `model_calls_live` (it read `0`), and an unservable tool call is one entry in the call sequence, not two
  (works today).

### Capture records what replay needs, and replay serves it

- **Generic wire** (experimental, ADR-0324). A call through `httpx`/`httpx2` or `requests` to any host the URL
  registry classifies as a model provider (Mistral, Cohere, Together, Replicate, Hugging Face Inference,
  OpenAI-compatible servers you register, raw HTTP to OpenAI or Anthropic) now stores its response body and a
  request digest, and mocked replay serves it at the `httpx` transport or at `urllib3`. A request that differs
  from the recorded one is the divergence `wire_request_mismatch`. Google Gemini API and Vertex AI hosts are in
  the registry (works today for recording; served by this layer).
- **Ollama** and **AWS Bedrock `Converse` / `ConverseStream`** calls are recorded with their response and served
  (experimental). Bedrock is tested with real `boto3` against a fake local server only; `InvokeModel` is
  recorded without a response and refused.
- **Framework tools you did not wrap** (experimental, ADR-0306 r3). With no code change, LangChain / LangGraph
  tools and OpenAI Agents SDK function tools are recorded, and mocked replay serves a servable record before the
  tool body runs. A tool result captured below `forensic` is served from the next recorded model request when
  its digest matches exactly. Tools that return a `ToolMessage` or a LangGraph `Command`, sub-agent tools, ADK
  `AgentTool` and Agents SDK `Agent.as_tool` calls are served too when the record can be rebuilt exactly (the
  refusal names the field otherwise), and the calls made inside a served tool call are counted as covered. The Agents SDK seams are private SDK functions checked against `openai-agents`
  0.24.0 only.
- **`httpx` transports.** A model call is served whichever transport the client uses (`MockTransport`,
  delegating or subclassed transports), counted once at the outermost seam (experimental).

### Know before you replay, and know what the replay reproduced

- **`replayability.json` at capture** (experimental). Every finalized capsule says whether a strict mocked
  replay would start or refuse, and why, classified by the replay's own functions; `nova capture` prints a
  `replay:` line, and `nova capture --require-replayable` exits `4` after writing a capsule that is not fully
  replayable. The workload is never stopped.
- **A fidelity verdict and a replay capsule** (experimental, ADR-0321). `replay_result.yaml` gains a `fidelity`
  block (`faithful` · `diverged` · `failed` · `not_compared`) comparing the exit code, stdout after the
  `volatile-ids/1` rule set, the end state of every file the recorded workload wrote, and the call sequence per
  model turn. The replay writes its own capsule, so `nova diff <capsule> <replay-dir>` compares the two runs.
  `nova replay --require-faithful` exits `4` unless the verdict is `faithful`.

### Isolation, adapters and Hugging Face

- **`nova replay --hermetic`** (experimental, Linux, ADR-0322). The replayed process tree runs with no network
  beyond loopback and a read-only host filesystem, under bubblewrap or, where unprivileged user namespaces are
  restricted (stock Ubuntu 24.04), Landlock + seccomp. When no backend can be set up the replay is refused
  (exit `5`), never run un-isolated. Blocked attempts are not counted from outside the process yet.
- **Framework-adapter capsules can be replayed** (experimental, ADR-0306 open question 7). Adapters and the
  `@agent` decorator record how their process was started; mocked replay re-runs that invocation only when
  every guard passes, and names the guard when it refuses. Tested end to end with real LangGraph; the other
  adapters record the facet but are not replayed end to end in the tests.
- **Hugging Face evidence** (experimental, opt-in): `smolagents` capture, Inference Providers and dedicated
  Endpoints recorded as model calls (reported model and provider `null`, never guessed), Hub revision references
  with an explicit evidence strength, and an eval receipt. `smolagents` tools are capture only. See
  [docs/integrations/huggingface.md](../integrations/huggingface.md).

### Audit profiles and dependencies

- Built-in SOC 2 and ISO/IEC 42001 profiles cite control identifiers, not standard text; to audit against the
  publisher's wording, load your own licensed catalog. Two `iso42001` control IDs were wrong and are renamed;
  `nova audit map --capsule` no longer hides the controls that capsule failed; `nova export-compliance iso42001`
  reads the capsule it reports on.
- Locked Python dependencies clear four HIGH advisories (`pyasn1` 0.6.5, `dnspython` 2.9.2, `joserfc` 1.8.0),
  and `npm audit` reports 0 vulnerabilities in all three npm trees, with no waivers left.

## Behaviour changes and upgrade notes

The full list is in the [CHANGELOG](../../CHANGELOG.md) under *Changed — BREAKING*. The ones most likely to
affect you:

- **Strict replays that passed may now stop.** `ModelSurfaceNotServable` and `ToolSurfaceNotServed` (exit `1`,
  before anything runs) for calls replay cannot serve; `unserved_network` (exit `1`) for a connection past
  loopback. A capsule captured before this release holds no record of a LangChain or Agents SDK tool you did not
  wrap, so each such call is refused before its body runs: capture again, or use `--permissive
  --allow-unknown-mutation`. A Bedrock replay with no AWS credentials needs credentials or
  `AWS_EC2_METADATA_DISABLED=true`.
- **More is stored.** Response bodies (completion text) of calls to model-provider hosts in the URL registry are
  stored at every capture level, as OpenAI responses already were; `NOVAFABRIC_CAPTURE_WIRE_RESPONSES=off`
  stores none. Unwrapped framework tools are recorded under the same payload rules as wrapped ones.
- **`nova replay` of an adapter capsule now re-runs the recorded script** when every guard passes (it was
  refused). Adapters running inside a mocked replay write no capsule.
- **Replay results read differently:** the verdict compares tool calls per model turn; `--permissive` counts
  live unservable model calls in `model_calls_live`; replay-capsule placeholder records carry a ULID and keep
  what happened in `extensions["io.novafabric.replay_placeholder"]`.
- **Audit and compliance:** `nova audit map --capsule ID` exits `1` for that capsule's gaps;
  `nova export-compliance iso42001` needs `--capsule DIR`; `ISO42-8.5-RESPONSIBLE-AI` is now
  `ISO42-7.5-DOCUMENTED-INFORMATION` and `ISO42-10.2-CONTINUAL-IMPROVEMENT` is
  `ISO42-10.1-CONTINUAL-IMPROVEMENT`; a custom profile with an unknown `evidence_type` fails to load.

## Try it

```bash
pip install --upgrade "novafabric==0.109.0"
nova --version                          # novafabric 0.109.0

nova capture --require-replayable -- python agent.py   # exit 4 if a strict replay would not serve every call
nova replay <run-id> --dry-run                         # [MOCK] / [LIVE] / [NOT SERVED] / [COVERED by …] per call
nova replay <run-id> --require-faithful                # exit 4 unless the fidelity verdict is faithful
nova replay <run-id> --hermetic                        # Linux: no network beyond loopback, read-only host
```

## Known limits

Calls the capture did not record cannot be served or predicted: non-Python child processes, raw sockets, gRPC,
`aiohttp`, `urllib3` used directly (Bedrock `InvokeModel`), binary bodies and streamed bodies with a
`content-encoding`. `--hermetic` does not count blocked attempts from outside the process. Several tool seams
rely on undocumented framework internals checked against one release each (named in the CHANGELOG entries).
The open items from earlier releases are in the [ROADMAP](../../ROADMAP.md) open-items table.
