# v0.23.0 — OAS v1.0 spec track: V-0, V-1, V-2 complete

**Released:** 2026-05-19

## What changed

V-0, V-1, and V-2 of the v1.0 roadmap track are now complete.
All code-side technical gates from ADR-0034 §1 are satisfied.

### V-2 — JSON schema promotion (8 schemas)

All eight OAS component schemas that carry a `schema_version` field now
lock the pattern to `^1\.` (ADR-0034 §1). Capsules or bundles with
`schema_version: "0.1.0"` will fail validation against the v1 schema.
Use `nova migrate <capsule-dir> --output <new-dir>` to convert them.

Schemas updated:
- `run-capsule.schema.json`
- `evidence-bundle.schema.json`
- `model-call.schema.json`
- `tool-call.schema.json`
- `lineage-edge.schema.json` (description also added)
- `environment.schema.json`
- `replay-policy.schema.json`
- `secret-redaction.schema.json`

`diff-report.schema.json` is excluded — it carries no `schema_version`
property in the body (it is a derived output format per ADR-0034 §2).

### V-1 — Spec doc promotion (9 docs)

All nine `design/spec/*-v1.md` component spec documents are promoted from
"pre-freeze draft" to "pre-freeze ready". All YAML and JSON examples updated
to `schema_version: "1.0.0"`. Table rows updated to reflect the v1.0.0
canonical value. Versioning-history prose ("Patch bump 0.1.0 → 0.1.1") is
intentionally preserved.

### V-0 — OAS umbrella doc update

`design/spec/open-agent-spec-v1.md` updated:
- Status line updated to "pre-freeze ready"
- Component table: schema version column shows `1.0.0` (not `0.1.0 → 1.0.0`)
- Component table: status column shows "Pre-freeze ready" for all nine
- Freeze tracker: expanded with "Schema locked" column; all nine rows updated
- Technical gate checklist added (V-0 through V-3 all ✅; V-5 ⏳ 1/3)
- Migration section: note that `nova migrate` already ships (v0.22.0, 51 tests)

## What remains for v1.0 freeze

The only remaining gate is design partner sign-offs (V-5): ≥3 are required
per ADR-0034 §5. Current status: 1/3 (BDFL self-validation). The spec is
technically stable — the freeze declaration is a governance step.

## Upgrade

```bash
pip install novafabric==0.23.0
```

Existing v0.1.x capsules are still readable by the NovaFabric tooling.
To migrate to v1.0.0 format (required for third-party v1 validators):

```bash
nova migrate ./my-capsule --output ./my-capsule-v1
```
