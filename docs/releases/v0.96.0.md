# NovaFabric v0.96.0 — 2026-07-30

**Closes ADR-0220's own deferred follow-up.** v0.95.0 fixed the run-boundary event
taxonomy (`RunStarted`/`RunCompleted`/`RunFailed`) but explicitly scoped out per-call
model/tool events as "a separate, larger piece of work." This release does that work:
`nova kg ingest --source nats` now builds real `CALLS`/`USES_TOOL` edges from real
captured runs, not just mocks.

## Highlights

### Real per-call events for `nova kg ingest --source nats`

`capture/orchestrator.py` already parses `model-calls.jsonl`/`tool-calls.jsonl` once, at
run finalize, to compute the capsule manifest's call counts. It now also re-emits each
record as a spool event: `ModelCallCompleted`/`ModelCallFailed` for model calls,
`ToolCallCompleted`/`ToolCallFailed` for tool calls — matching the canonical
`CapsuleEventType` values `KGIngestionPipeline` already expects. There's no `*Started`
variant: the source JSONL has one record per completed-or-failed call, never a separate
start event, so emitting one would be inventing data that was never actually captured.

The payload is deliberately narrow — `model_id`/`provider`/`status`/`duration_ms`/token
counts for model calls, `tool_name`/`status`/`duration_ms`/`mutates` for tool calls. No
message content, no tool arguments or results: this re-emission crosses a network
boundary (NATS) that the local capsule file it reads from doesn't, so it stays to
summary fields by default, matching the project's capture-privacy stance.

A malformed JSON line, or a record missing the field the KG pipeline actually keys an
edge on (`model_id` for calls, `tool_name` for tools), is skipped silently — same
tolerance `CapsuleEventConsumer`'s own local-dir reader already has. Gated behind
`--emit-spool` (off by default); fail-open throughout.

### A second producer/consumer field-shape mismatch, found and fixed

Wiring this up surfaced that `KGIngestionPipeline.ingest_event()` reads `model_id`/
`tool_name`/`url` only from the top level of the event dict — but a real Event Envelope
v1 (the actual NATS wire format) nests all event-type-specific data under a `payload`
key, since the envelope schema has no dedicated slot for per-event-type fields. This is
the same class of bug ADR-0220 found in `LineageConsumer` a day earlier: code written
against an assumed flat shape, never checked against the real wire format. Fixed
additively — `ingest_event()` now falls back into `event.get("payload", {})` when a
field is absent at the top level. Local-dir ingestion (already-flat records) is
unaffected.

New end-to-end test, `tests/kg/test_kg.py::test_real_producer_to_kg_pipeline_end_to_end`:
writes real `model-calls.jsonl`/`tool-calls.jsonl`, runs the real
`emit_call_events_from_capsule()` producer to build real spool envelopes, feeds those
(nested payload and all) into the real `KGIngestionPipeline.ingest_event()`, and asserts
real `CALLS`/`USES_TOOL` edges land in a real KuzuDB-backed store. Not a hand-built
KG-schema fixture at any point in the chain.

### Schema note

Event Envelope v1's `event_type` enum gained four more values
(`ModelCallCompleted`/`ModelCallFailed`/`ToolCallCompleted`/`ToolCallFailed`), additively
— nothing removed, `.sha256` pin regenerated. `EndpointRouted` still isn't emitted by any
producer; that remains open, unrelated work.

## Upgrade notes

All additive. No breaking changes, no new required dependencies, no CLI flag changes.
