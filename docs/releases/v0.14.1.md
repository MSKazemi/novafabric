# v0.14.1 — SealTab dashboard + /api/seal/* REST routes

**Released:** 2026-05-15
**ADR:** [ADR-0059](../decisions.md) (patch on v0.14.0)

---

## What's new

This patch extends v0.14.0 by wiring the NovaSeal maker-checker workflow into the dashboard and REST API. All new endpoints are read-only and observable from the existing `nova serve --experimental` local dashboard and the multi-user server.

### Dashboard — SealTab

A new **Seal** tab appears under the "Audit & Verify" navigation group (icon `⊚`, badge `SoD`).

**Policy panel** — displays the active promotion policy: proposer key IDs, approver key IDs, bypass window, approval threshold, and policy version badge. Shows an `EmptyState` with a CLI hint if no policy has been signed yet.

**Capsule lookup** — type a capsule ID (with `SuggestInput` autocomplete from existing run IDs), click "Load proposals" to fetch all proposal bundles for that capsule.

**Proposal cards** — each proposal shows UUID (copyable via `CopyButton`), proposer subject, justification, timestamp, and a status badge:
- `Awaiting approval` (yellow) — no approval bundle present
- `Approved` (green) — approval present, with approver subject and timestamp

**Verify SoD chain** button — enabled only when an approval exists; calls `POST /api/seal/{capsule_id}/verify` and displays the inline result panel:
- Green pass banner if all five checks pass
- Red per-check table showing which check failed and why

### REST API

Three new endpoints are available in **both** local-mode (`nova serve --experimental`) and the multi-user server (`nova server`):

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/seal/policy` | Latest promotion policy predicate (or 404) |
| `GET` | `/api/seal/{capsule_id}/proposals` | List proposals with approval status |
| `POST` | `/api/seal/{capsule_id}/verify` | Run five-check SoD verifier |

The multi-user server registers the endpoints via `src/novafabric/server/routes/seal.py` under the `/v0/seal` prefix. The local dashboard uses inline endpoint definitions in `src/novafabric/serve/app.py` under `/api/seal`.

The `NOVAFABRIC_SEAL_DB_PATH` environment variable overrides the Merkle log DB path for both modes (defaults to `~/.novafabric/novaseal-merkle.db`).

### Makefile target

```bash
make seal-smoke-test
```

Runs the full propose → approve → verify flow in a temp directory using the ECDSA P-256 test keys at `tests/fixtures/promote/keys/`. Useful for a quick local integration check.
