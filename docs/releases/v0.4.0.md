# v0.4.0 — Lineage Graph

**Released:** 2026-05-08

## What's new

### Automatic lineage emission

Every `nova capture` run now automatically writes `lineage.jsonl` into the capsule
directory. Three mechanical edge types are inferred from observed capture evidence:

| Edge type | Source | Confidence |
|---|---|---|
| `consumed` | `assets.jsonl` entries | `observed` |
| `produced_by` | output files in `capsule.yaml` | `inferred` |
| `replayed_from` | replay metadata in `capsule.yaml` | `declared` |

`lineage.jsonl` is the durable source of truth. The SQLite index (`novafabric.db`) is
a rebuildable cache — if the DB fails, capture succeeds and `lineage.jsonl` is preserved.

### Queryable lineage graph

Four canonical graph queries via `nova lineage`:

```bash
nova lineage provenance <ref>                    # what does this node depend on?
nova lineage blast-radius <ref>                  # what depends on this node?
nova lineage replay-chain <run-id>               # replay chain back to the original
nova lineage time-travel <ref> --asof <iso8601>  # snapshot of lineage at a point in time
```

All queries support `--output json` for programmatic use. `provenance` and `blast-radius`
support `--depth N`.

### Retroactive import

Import lineage from existing capsules captured before v0.4.0:

```bash
nova lineage import /path/to/runs/01HXRUN...   # single capsule
nova lineage import /path/to/runs/             # all capsules in a directory
```

### Lineage validation

`nova validate` now checks `lineage.jsonl` against the JSON Schema when present.

## Schema

Lineage records follow `schemas/lineage-edge.schema.json` (JSON Schema 2020-12).
The schema version is `0.1.0`.

## Breaking changes

None. All changes are additive.

## Upgrading

No action required. Existing capsules without `lineage.jsonl` validate correctly.
Run `nova lineage import <runs-dir>` to backfill the index from existing capsules.
