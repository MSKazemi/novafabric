# NovaFabric v0.46.0 — Dashboard parity gap closure

**Released:** 2026-06-11 · **Status:** experimental · **Breaking changes:** none

## Summary

A fresh audit of the full `nova` CLI surface (~80 commands) against the
`nova serve` route table found 12 capabilities that could not be performed
from the dashboard. This release closes all of them: 12 new REST endpoints
(161 total) and 12 panels across 7 dashboard tabs.

## New endpoints and panels

| CLI command | Endpoint | Dashboard panel |
|---|---|---|
| `nova eval list` | `GET /api/eval/suites` | Governance tab |
| `nova eval run --suite <id>` | `POST /api/eval/run` | Governance tab |
| `nova policy list` | `GET /api/policy/list` | Policy tab → Policy Inventory |
| `nova policy sign` | `POST /api/policy/sign` | Policy tab → Sign Promotion Policy |
| `nova classify list-vocabularies` | `GET /api/governance/vocabularies` | Governance tab → Regulatory Vocabularies |
| `nova classify run` | `POST /api/governance/classify-manual` | Governance tab → Manual Risk Classification |
| `nova aibom generate [--all] [--force]` | `POST /api/aibom/generate` | Compliance tab → Generate AI-SBOM |
| `nova ingest-capsule <id> \| --all` | `POST /api/ingest-capsule` | Admin tab → Reindex Capsules |
| `nova run show --with-children` | `GET /api/runs/{run_id}/tree` | Runs tab → Distributed Capsule Tree |
| `nova run lineage [--edge-types]` | `GET /api/runs/{run_id}/run-lineage` | Runs tab → Run Lineage Edges |
| `nova lineage-store profile` | `GET /api/lineage-store/profile` | Infra tab → Lineage Store Deployment Profile |
| `nova scan-secrets [--fail-on]` | `GET /api/runs/{run_id}/scan-secrets` | Runs tab → Secret Scan (PASS/FAIL gate) |

Notes:

- `POST /api/eval/run` runs any registered suite adapter. The built-in
  `novafabric-smoke-v1` suite executes host-env with no container; the OCI
  suites (GAIA, SWE-bench, AgentBench, MMLU, TruthfulQA) need their image
  digest env vars configured, exactly as for `nova eval run`.
- `POST /api/policy/sign` reads the key/cert PEM paths **server-side** — the
  private key never travels through the browser. The dashboard form submits
  filesystem paths, matching local-first `nova serve` semantics.
- `GET /api/runs/{run_id}/scan-secrets?fail_on=<severity>` returns
  `triggered: true/false`, giving the dashboard the same CI-style severity
  gate as `nova scan-secrets --fail-on`.

## Command registry

The Commands tab registry gained 4 new entries (`eval list`, `policy list`,
`aibom generate`, `ingest-capsule`) and 8 updated entries with native-tab
notes. The stale `lineage-store profile` entry (which described a
non-existent performance profiler) was rewritten to match the real CLI.

## Fixed

- **Stale virtualenv shebangs after the repo move** — `.venv/bin/*` entry
  points still pointed at the old `~/scratch/novafabric/.venv` interpreter,
  so `uv run pytest` / `uv run mypy` silently executed in the obsolete
  environment. The env was rebuilt with `uv sync --all-extras --reinstall`.
  The correctly resolved mypy now reports 85 pre-existing errors across 35
  files (tracked as backlog; this release introduces zero — the count is
  identical on clean HEAD).

## Tests

- `tests/serve/test_v046_dashboard_parity.py` — 39 tests covering all 12
  endpoints: success paths, validation failures (400/422), and not-found
  paths (404).

## Upgrade

```bash
uv pip install --upgrade novafabric
nova serve   # the dashboard bundle ships in the wheel
```

No schema, CLI, or API breaking changes.
