# NovaFabric v0.55.0 — Accountability Spine cores + dashboard CLI-coverage + slice-C forwarder

**Released:** 2026-06-19

A feature release on three independent tracks:

1. **The Accountability Spine** — the first implemented slices of three
   research-grounded, tamper-evident *ex-post evidence* features
   ([ADR-0093](../../design/adr/0093-energy-anchored-action-receipts.md),
   [ADR-0094](../../design/adr/0094-adversary-anchored-ledger-and-replay-attestation.md),
   [ADR-0095](../../design/adr/0095-evidence-grounded-safety-case-and-admissible-evidence.md)).
2. **Dashboard CLI-coverage expansion** — ~30 previously CLI-only commands surfaced in
   `nova serve`, on a new shared 10x-quality frontend foundation.
3. **Capture→spool forwarder (slice C, increment C0)** — `nova capture --emit-spool` +
   the resident `novafabric-spool-forwarder` drain loop
   ([ADR-0092](../../design/adr/0092-warm-capture-daemon.md)).

All three tracks are **additive and opt-in**. No existing schema, CLI default, or capture
behavior changes; the only two top-level formats remain Run Capsule and Evidence Bundle
([ADR-0034](../../design/adr/0034-v1-spec-stability-policy.md)).

---

## Why — the Accountability Spine

The 2026 "accountable autonomy" research corpus is blunt: prevention (sandboxing) and
in-flight oversight both leak under adaptive attack, so the load-bearing accountability
pillar is **ex-post evidence (domain D3)** — which is nearly empty as a product space while
every other domain depends on it. The single most defensible wedge is **energy-anchored
provenance (D3 × D7)**: no competitor binds physical cost to agent provenance, and it
requires HPC bare-metal access to validate. v0.55.0 ships the first working cores. The
integrating overview is `design/architecture/accountability-spine.md`; every feature claim is
evidence-cited in `design/research/accountability-spine-traceability.md`.

## Highlights

### `nova energy` — Energy-Anchored Action Receipts (feature A, ADR-0093)

The flagship, under one invariant: **measured-or-declared-unknown, never fabricated**.

- `EnergyReceipt` model bound to `schemas/energy-receipt.schema.json`, with a JCS-canonical
  `payload_hash` that excludes the mutable seal block.
- **Honest degradation by design.** On hardware that cannot attribute per-action energy
  (the common case — n1 is CPU-only; the GB10 SoC exposes only NVML per arXiv 2605.27599),
  receipts are stamped `measurement_source="unavailable"`, `measured_joules=null`, and list
  the node's readable counters so an auditor can tell *"hardware cannot"* from *"NovaFabric
  failed"*. The legacy forgeable `nova.carbon` / `energy_joules_estimated` figures are
  reclassified `confidence="declared"` — never able to masquerade as a measurement.
- **The HPC moat.** A Slurm `sacct ConsumedEnergyRaw` parser yields the strongest receipt
  class: a *measured* per-job joule total.
- DSSE/in-toto **seal binding** of each receipt's `payload_hash`, and a signed **energy
  conservation** check (`balanced` / `diverged` / `unmeasurable`).
- CLI `nova energy probe|attest|verify|report`, with forgery-guard exit codes — a `measured`
  receipt with no available counter fails `verify`.

### `nova ledger` + replay attestation — Adversary-Anchored Ledger (feature B, ADR-0094)

Tamper-evident against a compromised agent **and** a malicious operator.

- `src/novafabric/trust/ledger/`: per-stream **sidecar hash-chains** over a capsule's jsonl
  event streams (the `.jsonl` files are never mutated), DSSE-signed `CheckpointRecord`s via
  the existing NovaSeal path, and a verifier with a structured **tamper taxonomy** and
  seal-style exit codes (content edit / reorder / truncation / bad-sig / no-checkpoint).
  `nova ledger anchor|verify|status`.
- `src/novafabric/evidence/replay_attestation.py`: a `ReplayAttestation` determinism
  certificate — `BIT_EXACT` / `BOUNDED_EQUIVALENT` / `NON_DETERMINISTIC` — extending the
  existing re-performance attestation, plus a `replay_attestation.rego` release gate
  (`NON_DETERMINISTIC` deny-by-default unless a signed maker-checker bypass).
- Reuses accepted ADR-0089/0090/0070/0071; **no new dependency**.

### `nova safety-case` — Evidence-Grounded Safety-Case compiler (feature C, ADR-0095)

- `src/novafabric/safetycase/`: compiles a **Claims-Arguments-Evidence** tree from a capsule's
  *real* artifacts (evals, seals, criterion bindings, replay attestations). Honesty is
  **structural**: invariant I1 forbids naked claims (enforced in-schema and in a validator);
  eval-derived claims must carry a process-evidence pointer; backing states are driven by
  inter-judge κ and Wilson confidence intervals (κ < 0.6 or a straddling CI → `CONTESTED`;
  dangling reference → `UNSUPPORTED`); `residual_risk` defaults to *not-quantified*.
- Energy receipts and replay attestations compose in as `evidence_kind` leaves at zero schema
  cost. `nova safety-case build|verify|export`; `clymer-generic-v0` template populated, EU AI
  Act Annex IV / NIST RMF templates are loadable stubs.

### Dashboard CLI-coverage expansion + 10x foundation

~30 previously CLI-only commands are now in `nova serve`: five new tabs (**Eval**, **Risk**,
**Storage & Recovery**, **Incidents** with a live EU AI Act Art. 73 deadline clock, **Ops**)
plus **Seal → Ratchet** and **Evidence → Assertions** panels, backed by ~14 new serve routes.
Destructive / process-control actions are confirmation-gated ("safe mutations only"); daemon
control stays read-only over HTTP. A new shared frontend foundation (toast context, unified
`useMutation`, `ConfirmDialog`/`ActionButton`, virtualized `DataTable`, `TabShell`,
URL-deep-linked tabs, global Cmd+K entity search) underpins it.

### Capture→spool forwarder (ADR-0092 slice C, increment C0)

`nova capture --emit-spool` writes run-boundary EventEnvelope v1 records (`run.start`,
`capsule.finalize`) to a local event spool; the resident `novafabric-spool-forwarder` drains
the spool to NATS JetStream with exactly-once, restart-no-loss semantics. Proven byte-identical
on the n1 NATS round-trip.

## What is *not* yet in this release (honest limitations)

The Accountability Spine ships **cores**, not the full features. Deferred to later versions
(tracked in each ADR's "Implementation status"):

- **Feature A:** the live sampling daemon, the live n1 Slurm `sacct` runner call, the
  `energy-receipts` predicate row in Evidence Bundles, and the `EnergyTab` dashboard panel.
- **Feature B:** wiring the sidecar chain into live capture, and the external Rekor/RFC3161
  anchoring cadence at the hub.
- **Feature C:** the court-admissibility Evidence-Bundle binding (FRE-902(14) chain-of-custody),
  the Annex IV renderer, and the dashboard panel.

These are documented design intent, not implemented behavior.

## Upgrade

No action required — all new surfaces are additive and opt-in. Old Run Capsules and Evidence
Bundles remain valid unchanged. GPU energy measurement (NVML) is behind an optional extra:

```bash
pip install 'novafabric[energy-gpu]'   # only if you want NVML on a GPU box
```

## Quality

177 Accountability-Spine tests + 10 OPA policy tests; the spine modules are 98–100% covered
(feature C ≥ 90% per module). `mypy --strict` clean across the source tree; `ruff` clean.
The three new CLI command groups are proven end-to-end (including ledger tamper-detection
firing on a modified sealed stream).
