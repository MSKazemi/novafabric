# v0.100.0 — the release that makes the repository usable by outsiders

**2026-08-05** · Apache-2.0 · `pip install novafabric==0.100.0`

No runtime behaviour changes for existing capsules. This release is about two things:
**a repository a stranger can actually contribute to**, and **a release pipeline that
delivers.**

> **Read this first if you are upgrading:** v0.98.0 through v0.99.0 were tagged but
> **never reached PyPI** — a broken step in the publish workflow blocked the upload for
> five consecutive releases. If you installed from PyPI, you have been running **0.97.0**
> regardless of what the repository said. This release fixes the pipeline and carries
> every fix from those versions with it.

---

## Fixed — the release pipeline never published

`Generate SBOM (syft)` failed on five consecutive release tags starting 2026-07-31.
Because it was a blocking step it took the whole `build` job down, so the dependent
`publish` job never ran.

The consequence was invisible and serious: the three defects v0.99.0 fixed **for released
installs** — schemas missing from the wheel, ~1.5% of API keys unrotatable, concurrent
captures cross-filing into each other's capsules — never reached a single user.

The step is now `continue-on-error` with an explicit warning annotation. **A supply-chain
nicety must not be able to block the supply chain**; a broken third-party action should
show up as a failed step, not as a silent non-release.

## Security — three HIGH-severity advisories cleared

| Package | From | To | Cleared |
|---|---|---|---|
| `cryptography` | 48.0.1 | **50.0.0** | PYSEC-2026-3552, PYSEC-2026-3553 (HIGH), PYSEC-2026-3554 |
| `aiohttp` | 3.14.1 | **3.14.3** | PYSEC-2026-3545 (HIGH), plus two moderate |

`cryptography` underpins NovaSeal signing, so the major bump was **verified, not
assumed**: 621 tests across `seal/`, `trust/`, `evidence/` and `supplychain/` pass, and
the p99 seal-latency gate holds at 6.44 ms against its 200 ms ceiling. Transitive
updates: `sigstore` 4.5.0, `pyopenssl` 26.4.0, `msal` 1.37.0.

## Fixed — Postgres migrations could not run as documented

`alembic -c alembic-postgres.ini upgrade head` — the command in the runbook — failed with
`ModuleNotFoundError: No module named 'psycopg2'` for any ordinary `postgresql://` DSN.
SQLAlchemy resolves the bare scheme to psycopg2; NovaFabric ships `psycopg[binary]`
(psycopg 3).

It survived because every other consumer passes the DSN straight to `psycopg.connect()`,
where it is correct — only the SQLAlchemy path was affected. New
`novafabric.metadata_store.dsn.to_sqlalchemy_url` normalises bare `postgresql://` and
`postgres://` to `postgresql+psycopg://` and leaves an explicitly named driver alone.

## Fixed — CI had been failing for weeks in three different ways

- **`integration` had not executed a single test since at least 2026-07-30.** It installed
  without `--all-extras`, so `alembic` was absent and the migration step died first.
- **`web` could not build the site on any run.** It pinned Node 20; Astro 7 requires
  ≥ 22.12. `web/package.json` *also* declared `>=20.0.0`, so the pin agreed with the
  declaration and the declaration was what was wrong.
- **`unit` had never completed** — 30 consecutive runs hit a 15-minute cap. GitHub reports
  a job timeout as `cancelled`, which reads like an interrupted run, so a permanently
  broken job never looked like one. The suite and the 90% coverage gate had not run in CI
  at all. Raised to 40 minutes; it now completes in ~23 minutes and the coverage gate
  passes at 90.78%.

Each is guarded by a test so it cannot regrow silently.

## Added — the contributor surface

**151 links in the public documentation pointed at files excluded from the public
repository** — every one a 404 for every visitor, including the RFC-process link
`CONTRIBUTING.md` tells contributors to read first.

The fix generalised into a rule now enforced by `make check-links`: **a link's target must
be tracked by the public git, not merely exist on disk.** Those differ exactly where it
matters, and checking git membership found nine more instances a path denylist could not.

New public documentation:

- [RFC process](../governance/rfc-process.md), [maintainer criteria](../governance/maintainer-criteria.md),
  [design partners](../governance/design-partners.md), and [`docs/rfcs/`](../rfcs/) with a template
- [`docs/decisions.md`](../decisions.md) — an index of all 225 architecture decisions, so an
  `ADR-0123` citation anywhere resolves
- [`docs/architecture.md`](../architecture.md) — the public subsystem map, the design
  invariants, schema migrations, and an explicit "what NovaFabric is not"
- [`docs/comparison.md`](../comparison.md) — honest comparisons against Langfuse, LangSmith,
  MLflow, W&B and raw OpenTelemetry, **including where NovaFabric is the wrong choice**

Contributor onboarding: `CONTRIBUTING.md` now opens with a 15-minute path from clone to
pull request *before* any governance material; a `.devcontainer/` removes the
`uv sync`-without-`--all-extras` failure that breaks ~30 tests for every newcomer;
`CODEOWNERS`, `CONTRIBUTORS.md`, YAML issue forms, and published response commitments in
`SUPPORT.md`. GitHub private vulnerability reporting, secret scanning and push protection
are enabled.

## Added — the documentation is on the web

`novafabric.ai/docs/` publishes the `docs/` tree as **48 pages**, read directly from the
repository at build time so the site cannot drift from what maintainers edit. Includes
`TechArticle` JSON-LD, per-page meta descriptions, sitemap entries, and relative `.md`
links rewritten to working URLs.

## Known issues

- **[#23](https://github.com/novafabric/novafabric/issues/23) — server mode: `register_run()`
  fails after running the packaged Postgres migrations.** `v002_partition_ddl` gives `runs`
  a primary key of `(run_id, started_at)` while the store writes
  `ON CONFLICT (run_id, tenant_id)`. **Pre-existing, not introduced here**, and it affects
  server mode only — local mode is unaffected. Every candidate fix changes a documented
  guarantee, so it is deliberately left for a decision rather than patched quietly.
- **[#21](https://github.com/novafabric/novafabric/issues/21)** — a set of CLI `--help`
  assertions fail in CI and not locally; unexplained, tracked separately.

## Upgrading

```bash
pip install --upgrade novafabric
nova --version
```

No capsule migration is required. The Run Capsule and Evidence Bundle formats are
**still not frozen** — expect schema changes before v1.0.
