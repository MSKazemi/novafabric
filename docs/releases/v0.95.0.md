# NovaFabric v0.95.0 — 2026-07-30

**Closes the "known limitation" v0.94.0 shipped honestly instead of hiding.** v0.94.0
documented that the cluster-scale NATS event pipeline silently produced zero lineage
edges because the producer and consumers disagreed on `event_type` strings. This
release fixes it — and the investigation into *why* found the original diagnosis was
itself half-wrong, which is worth knowing if you read v0.94.0's release notes or
ADR-0061/ADR-0220 before this fix landed.

## Highlights

### ADR-0220: the real event-taxonomy gap, fixed

v0.94.0 described this as a Go-vs-Python problem: a Go collector using one `event_type`
taxonomy, Python consumers expecting another. Implementing the fix surfaced that framing
was wrong in an important way — **there is no real Go event producer in this repository.**
`collector/pkg/envelope/envelope.go`'s `EventType` constants were dead code (zero
production call sites; only referenced in that package's own test), and the Go NATS
publisher is a dumb byte-forwarder that never inspects `event_type` at all.

The actual, only real producer is Python: `capture/orchestrator.py`'s two
`SpoolSink.emit_event()` calls, which — before this release — emitted `"run.start"` and
`"capsule.finalize"`. Neither matches anything `LineageConsumer._process_event()` checks
for (`RunStarted`, `ArtifactProduced`, `ArtifactConsumed`), so a fully-wired
`nova lineage consume` pipeline would connect cleanly and extract zero edges, forever —
a same-codebase producer/consumer mismatch, not a language-boundary one.

**Fixed at the BDFL's direction (Option A — the producer conforms to the canonical
taxonomy):**

- `orchestrator.py` now emits `"RunStarted"` at run start and `"RunCompleted"`/
  `"RunFailed"` (by exit code) at run finalize, and reads
  `NOVAFABRIC_GLOBAL_RUN_ID`/`NOVAFABRIC_PARENT_RUN_ID` so a child capsule's
  `RunStarted` event carries `parent_run_id` — previously neither field was ever
  populated by this call site, so no `SPAWNED_BY` edge could ever be derived even once
  the naming was fixed.
- The frozen Event Envelope v1 wire schema's `event_type` enum was widened
  **additively** — the four canonical `Run*` values were added; the six legacy
  lowercase/dotted values stay valid for backward compatibility (a versioned,
  hash-pinned wire format never loses a value, only gains new ones). `.sha256` pin
  regenerated.
- `collector/pkg/envelope/envelope.go`'s dead constants were corrected to the real
  canonical values (not deleted — kept as accurate reference, with a doc comment
  explaining the real producer is Python).
- `EndpointRouted` — already consumed by the KG ingestion pipeline but missing from the
  canonical `CapsuleEventType` enum — was added (additive).

**Deliberately not addressed here:** model-call/tool-call-level event granularity is
still not emitted into the NATS pipeline by any producer. That's a materially larger
piece of work (instrumenting every wire-level hook to also emit to the spool, not a
taxonomy fix) and is correctly left as separate, open work rather than rushed into this
slice.

New test: `tests/scale_architecture/test_lineage_consumer.py::TestRealProducerEndToEnd`
runs two real `CaptureOrchestrator.run()` calls (parent + child), reads the actual spool
segments they write, and confirms `LineageConsumer` derives the right `SPAWNED_BY` edge
— the producer/consumer-boundary-crossing test the original gap was invisible without.

See [ADR-0220](../decisions.md)
for the full option analysis and the corrected
[ADR-0061](../decisions.md).

### PAR-ADR-002 resolved: `pending_parent_timeout` stays 86400s (24h)

A month-old spec-vs-code disagreement (the spec said 300s, the code shipped 86400s) is
now resolved by the BDFL: **keep the shipped 24h default.** It favors legitimately
slow-starting HPC/multi-node Slurm jobs over fast orphan-detection for short jobs — the
right tradeoff given NovaFabric's HPC/cluster-scale-first architecture. No code change;
`NOVAFABRIC_PENDING_PARENT_TIMEOUT` remains available for operators who want faster
detection. Documentation updated to stop presenting this as an open question.

### Fixed: the v0.94.0 version bump itself

`pyproject.toml`/`uv.lock` were never bumped when v0.94.0 was tagged — `nova --version`
reported `0.93.0` on a v0.94.0 checkout. Every release before it bumped this file; the
v0.94.0 release commit missed the step. Caught while auditing release state for this
release; fixed directly to 0.95.0.

## Upgrade notes

All additive. No breaking changes, no new required dependencies, no CLI flag changes.
The Event Envelope v1 schema change is additive-only (new enum values; nothing removed),
so existing recorded envelopes and any downstream schema validators remain valid.
