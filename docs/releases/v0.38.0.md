# Release notes — v0.38.0 (2026-05-20)

## Scale-S4: Postgres Merkle log backend for NovaSeal

### What's new

> **Correction (2026-09-04).** This note originally stated that v0.38.0 "meets
> the Scale-S4 acceptance criterion: `nova seal log verify` p99 < 200 ms at 1M
> log entries." **That claim was wrong and is withdrawn.** The backend shipped
> and works; the latency criterion was never met.
>
> `verify_consistency()` recomputes the Merkle root from every stored leaf hash
> on its default path. At 1M leaves that is ~1M SHA-256 calls in Python —
> measured at **1361 ms in-process with no database involved**, 6.8x the entire
> 200 ms budget. End-to-end the nightly gate measures **~1879 ms**. The target
> is not reachable with this algorithm, so no amount of faster hardware closes
> it.
>
> The gate that would have caught this ran nightly and was red continuously from
> 2026-08-05; nobody read it. It now reports against a measured baseline, and the
> route to a genuine 200 ms path — verifying inclusion proofs against a signed
> tree head instead of recomputing the full root, which is a *weaker* guarantee
> and needs a design decision — is tracked in
> [#93](https://github.com/MSKazemi/novafabric/issues/93) rather than assumed.
>
> The text below is left as published, with the withdrawn sentence marked.

**Postgres storage backend for the NovaSeal Merkle log** — at > 1M capsule
signing events the SQLite log's sequential full-table scan becomes a bottleneck.
v0.38.0 ships a production-ready Postgres backend. ~~It meets the Scale-S4
acceptance criterion: `nova seal log verify` p99 < 200 ms at 1M log entries.~~
**(withdrawn — see the correction above)**

**Install the extra:**

```bash
pip install 'novafabric[seal-postgres]'
```

**Configure the backend:**

```bash
# Via env var (accepts both file paths and postgresql:// DSNs)
export NOVAFABRIC_SEAL_DB_PATH=postgresql://user:pass@host:5432/nova
nova seal log verify
```

Or in `~/.novafabric/novaseal.yaml`:

```yaml
merkle_db: postgresql://user:pass@host:5432/nova
```

**`nova seal log verify` enhancements:**

```bash
# Fast check (default) — samples the entry re-hash, but still recomputes
# the root from every leaf: ~1.9 s at 1M entries (NOT the withdrawn 200 ms)
nova seal log verify

# Full O(N) re-hash audit — verifies every entry_json
nova seal log verify --full

# Explicit DSN override (bypasses NOVAFABRIC_SEAL_DB_PATH)
nova seal log verify --db postgresql://user:pass@host:5432/nova
```

### Architecture

The backend is selected automatically by URI shape via `open_merkle_log(uri)`:

| URI form | Backend | Requirement |
|---|---|---|
| `Path` or file path string | `MerkleLog` (SQLite) | none (default) |
| `postgresql://…` or `postgres://…` | `PostgresMerkleLog` | `[seal-postgres]` |

`NovaSeal.__init__` already calls `open_merkle_log(db_path)`, so the switch is
transparent — no code changes needed in callers.

**Self-bootstrapping tables** — `PostgresMerkleLog` creates `nova_seal_leaves`,
`nova_seal_tree_heads`, and `nova_seal_leaf_seq` on first connection using
`CREATE … IF NOT EXISTS`. No Alembic migration is needed; `nova db upgrade` is
unaffected.

**Append-only invariant** — Postgres triggers on `nova_seal_leaves` forbid
`DELETE` and `UPDATE` (mirrors the SQLite trigger behaviour).

**Sampled `verify_consistency()` fast path:**

1. Count all leaves.
2. Spot-check up to 1 000 random `(leaf_index, leaf_hash, entry_json)` rows —
   recompute `SHA256(0x00 || entry_json_bytes)` and compare.
3. Stream all `leaf_hash` values (not `entry_json`) and recompute the Merkle root.
4. Compare against the stored `tree_heads` entry.

The spot-check is sound because the append-only DB triggers prevent stored
leaf hashes from being modified after they are written. The root comparison
catches any global divergence.

### Bug fix

`nova seal log verify --db` default now resolves `NOVAFABRIC_SEAL_DB_PATH` at
invocation time. Previously it was evaluated at module import time, so
`NOVAFABRIC_SEAL_DB_PATH=postgresql://...` was silently ignored unless `--db`
was also passed.

### Tests

- `tests/seal/test_postgres_merkle.py` — 8 unit tests (no live Postgres required)
- Integration tests (gated on `NOVA_INTEGRATION=1` + `NOVA_TEST_POSTGRES_DSN`):
  `test_append_and_read_leaf`, `test_tree_size`, `test_current_root_*`,
  `test_verify_entry_returns_true`, `test_verify_consistency_*`,
  `test_inclusion_proof_valid`
- Benchmark test: 1M-entry bulk insert + repeated `verify_consistency()`. As
  published this asserted p99 < 200 ms; that threshold was never met on any run
  and the assertion is now a regression guard against a measured baseline
  (see the correction at the top).

### Upgrade

No breaking changes. SQLite remains the default backend.

```bash
pip install --upgrade novafabric
# Optional: Postgres backend
pip install 'novafabric[seal-postgres]'
```
