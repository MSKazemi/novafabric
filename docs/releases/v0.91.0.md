# NovaFabric v0.91.0 — 2026-07-25

**Sign with your own long-lived key — and verify it air-gapped.** ADR-0055's `x509`
signing profile lands its offline, certificate-pinned core: sign with an enterprise
ECDSA/RSA key, embed the operator certificate, and verify anywhere with no CA server and
no network — the trust anchor is a pinned certificate fingerprint. `experimental`. Full
detail: `CHANGELOG.md` §[0.91.0].

## Highlights

### The `x509` signing identity (ADR-0055)

NovaSeal's ephemeral, keyless signing (sigstore/Fulcio) is great when you have OIDC and a
transparency log. Regulated and air-gapped deployments want the opposite: a **long-lived,
operator-controlled key** bound to an **operator-issued X.509 certificate**, working fully
offline. `trust/novaseal/x509_identity.py` delivers that core:

- `X509SigningIdentity.from_pem(key_pem, cert_pem)` loads a PKCS#8 PEM key and PEM
  certificate. `.sign(payload)` returns an `X509Signature` carrying the algorithm, the raw
  signature, and the embedded certificate — for **ECDSA P-256** (`ecdsa-p256-sha256`) or
  **RSA** (`rsa-pss-sha256`). No service call at signing time.
- `.certificate_fingerprint` is the `sha256:`-prefixed certificate fingerprint — the value
  an operator pins.

### Certificate-pinned trust — no CA server, no path-building

`verify_x509_signature(payload, sig, pinned_fingerprints=…)` verifies with two conditions,
both offline:

1. the embedded certificate's SHA-256 fingerprint is in the operator's **pinned trust
   set** — the trust anchor is an explicit list of trusted certificates, not a CA chain to
   walk; and
2. the signature verifies under the certificate's public key.

A valid signature from an *unpinned* certificate is rejected (untrusted signer); a tampered
payload is rejected. It uses only the `cryptography` library's standard verification
primitives — **no hand-rolled crypto** — and never raises: a failure is a `valid=False`
result with a human-readable reason.

### Scope, honestly

This is the offline, cert-pinned core. **Deferred, unchanged design intent:** full CA-bundle
chain/path validation (the alternative to pinning), PKCS#11/PKCS#12 key sources, embedding
the signature in a DSSE envelope, the optional Rekor inclusion proof, and the entire
`sigstore` (OIDC/Fulcio/Rekor) profile. All of them layer on top of this without changing
the signature format — shipping the pinned core now is what makes them additive. ADR-0055
moved `proposed → accepted` for this slice under delegated authority. No new dependencies
(`cryptography` is already present).
