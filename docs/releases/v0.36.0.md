# Release notes — v0.36.0 (2026-05-20)

## Scale-S3: CapsuleWatcher + `nova ingest-capsule`

### What's new

**`nova ingest-capsule`** — a new standalone CLI command that populates the
`runs_cache` SQLite index from capsule files on disk. Works without `nova serve`
running. Four modes:

```bash
# Index a single capsule by run ID
nova ingest-capsule abc123

# Full re-index of the entire capsule directory
nova ingest-capsule --all

# Foreground watcher loop (prints each new capsule as it appears)
nova ingest-capsule --watch --interval 5

# Use inotify/FSEvents backend (requires pip install novafabric[watch])
nova ingest-capsule --watch --backend watchdog
```

**`CapsuleWatcher`** — the engine behind `nova ingest-capsule` and `nova serve`.
Pluggable backends:

- `PollingBackend` — default, zero extra deps, incremental directory scan
- `WatchdogBackend` — optional inotify/FSEvents/kqueue backend
  (`pip install novafabric[watch]`; requires `watchdog>=4.0.0`)

Backend selection: `NOVA_WATCHER_BACKEND=auto|polling|watchdog` env var.
Poll interval: `NOVA_WATCHER_INTERVAL` env var (default 2.0 s).

**`nova serve` delegating to `CapsuleWatcher`** — startup indexing and the
2-second incremental poll now go through `CapsuleWatcher` instead of calling
`build_runs_index()` inline. This decouples the indexing logic from the stats
refresh loop and makes it independently testable.

**`[watch]` optional extras** — `pip install novafabric[watch]` pulls
`watchdog>=4.0.0` (Apache-2.0, Tier A under ADR-0024).

- `TestCapsuleWatcherBackground` — 2 tests (includes 5 s SLA acceptance test)

- `TestIngestCapsuleCLI` — 6 tests

### Upgrade

No breaking changes. `nova serve` behavior is unchanged from the outside.

```bash
pip install --upgrade novafabric
# Optional: add watchdog for inotify/FSEvents support
pip install 'novafabric[watch]'
```
