# NovaFabric v0.43.0 — CLI help overhaul

**Released:** 2026-05-23

---

## Summary

All ~55 `nova` commands now have consistent, user-facing help text: a one-liner
description, a `Scope:` line (local / server / both), and a `\b Examples:` block
with runnable snippets. Eight `str` Enum types were added for fixed-value CLI
options, enabling shell tab-completion and typed validation at the Typer layer.
No functional changes — this is a documentation and UX-only release.

---

## What changed

### Consistent help text on every command

Every command docstring now follows this template:

```
One-liner description.

Scope: local | server | both

\b
Examples:
    nova <command> [args...]
    nova <command> [flags...]
```

The `Scope:` line tells operators at a glance whether a command requires
`nova serve` (server mode) or works standalone (local mode).

### Eight new `str` Enum types

Fixed-value CLI options now use typed `str` Enum classes instead of bare strings.
This means:

1. **Shell tab-completion** — `nova --install-completion` now surfaces the valid
   choices for each option.
2. **Validation at parse time** — passing an invalid value exits 2 with a clear
   error message listing valid choices (instead of a cryptic runtime error).

| Enum | Module | CLI option | Valid values |
|---|---|---|---|
| `RunnerName` | `cli/capture.py` | `nova capture --runner` | `local`, `docker`, `kubernetes`, `slurm`, `lsf`, `pbs` |
| `ReplayMode` | `cli/replay.py` | `nova replay --mode` | `mocked`, `forensic`, `semantic`, `exact` |
| `DiffOutputFormat` | `cli/diff.py` | `nova diff --output-format` | `text`, `json`, `github-annotation` |
| `ReportFormat` | `cli/report.py` | `nova report --format` | `markdown`, `json` |
| `LineageOutputFormat` | `cli/lineage.py` | `nova lineage --output` | `text`, `json` |
| `AssureOutputFormat` | `cli/assure.py` | `nova assure --format` | `rich`, `json` |
| `ScanSeverity` | `cli/scan_secrets.py` | `nova scan-secrets --fail-on` | `critical`, `high`, `medium`, `low`, `info` |
| `ScanThreshold` | `cli/mcp_.py` | `nova mcp scan --threshold` | `HIGH`, `MEDIUM`, `LOW` |

### Shell completion upgrade

After installing tab-completion (`nova --install-completion`), enum-typed options
now show valid choices inline:

```bash
nova replay <capsule> --mode <TAB>
# → mocked  forensic  semantic  exact
```

### ADR and internal reference cleanup

All `help=` strings that previously exposed ADR numbers, FR identifiers (`cap-001`,
`ADR-0027`), or internal ticket references have been cleaned up. Users now see
plain English descriptions.

### `main.py` docstring rendering fix

`help=` overrides were removed from `app.command()` calls in `main.py`. Typer now
renders the full command docstring (including the `\b Examples:` block) instead of
the short override string.

---

## Test changes

Two test assertions updated to match the new Enum behavior:

- Exit-code assertions for invalid `--mode` / `--output-format` values changed from
  `1` to `2` (Typer Enum validation exits 2, matching Click convention).
- The `nova serve` banner test no longer asserts the presence of `ADR-0027` (removed
  from banner text as part of the internal-ref cleanup).
