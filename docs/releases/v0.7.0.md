# v0.7.0 — Server mode + multi-user backend

Released: 2026-05-10

This release adds an optional multi-user server mode to NovaFabric. Local-only
workflows are completely unchanged — the new components are gated behind the
`novafabric[server]` optional extra and activated only when explicitly started.

## What's new

### Storage layer (S-0)

- **`StorageBackend` protocol** (`storage/_base.py`) — `runtime_checkable`
  duck-typed protocol shared by both backends. `get_backend()` factory selects
  the implementation via `NOVAFABRIC_BACKEND` env var (default: `sqlite`).
- **Alembic two-track migrations** — `alembic.ini` (SQLite) and
  `alembic-postgres.ini` (Postgres) manage schema evolution independently.
  Initial revisions `s0001` (SQLite) and `p0001` (Postgres) create all four
  tables idempotently.
- **`nova doctor --check-storage`** — inspect schema version, row counts, and
  pending migrations without modifying any state. Works with both backends.

### Postgres migration (S-1)

- **`nova migrate-to-postgres`** — one-time, idempotent migration from a local
  SQLite registry to Postgres. Features:
  - `--dry-run` to preview what would be migrated
  - JSONL migration log (`--log-file`) for audit trail
  - Row-count verification against both databases after migration
  - Exit codes: `0` = success, `1` = verification failure, `2` = connection/import error
  - DSN password redacted in all output

### REST API server (S-2)

- **`nova server start`** — starts the multi-user REST API server (FastAPI,
  uvicorn). Requires `novafabric[server]`.
- **Five resource families** under `/v0`:
  - `GET/POST /v0/assets` — asset registry CRUD with cursor-based pagination
  - `GET/POST /v0/capsules` — capsule upload (multipart) + list
  - `GET /v0/lineage` — provenance + blast-radius queries
  - `GET/POST /v0/replays` — replay result submissions
  - `GET/POST /v0/evidence` — evidence bundle upload + tamper-detect verify
- **API contract** in `api/openapi.yaml` (OpenAPI 3.1). Versioned, hand-authored
  spec — no auto-generated drift.
- **`GET /health`** endpoint returns `{"status": "ok", "version": "..."}` for
  liveness probes.
- **Cursor-based pagination** — base64url-encoded `{"offset": N}` cursors on
  all list endpoints; `limit` capped at 100.
- **Structured error envelope**: `{"error": {"code", "message", "details"}}` on
  all 4xx/5xx responses.

### Authentication + RBAC (S-3)

- **OIDC Bearer token auth** — `verify_token` FastAPI dependency validates JWTs
  against the issuer's JWKS endpoint (cached with TTL). Supports RS256, ES256,
  and Ed25519 algorithms.
- **No-auth local mode** — when `oidc.issuer_url` is empty in `server.yaml`,
  every request is treated as `AuthContext(subject="local", roles=["admin"])`.
  No token required. Safe for single-machine deployments.
- **RBAC** — four roles: `reader < writer < admin`, `auditor` (orthogonal).
  `require_role(minimum)` dependency factory enforces the hierarchy.
- **Offline tokens** — `nova server token issue/revoke/list` manages ed25519
  tokens for service accounts and CI pipelines. Keypair stored at
  `NOVA_OFFLINE_KEY_PATH` (PEM, mode 0600). All issuances/revocations written
  to a `token_audit` table.
- **`nova login` / `nova logout`** — OIDC Device Authorization Grant (RFC 8628).
  Credentials stored at `~/.config/novafabric/credentials.json` (mode 0600).

### CLI surface + docs (S-4)

- **`nova server start/token`** — new server subcommand group.
- **`cli-reference.md`** updated with all new commands and flags.
- **`docs/ops/server-deployment.md`** — new operator guide covering four
  deployment scenarios (local no-auth, local OIDC, Docker, Kubernetes) with
  explicit "works today" / "experimental" labels.
- **`design/adr/0029-server-config-schema.md`** — ADR documenting the server
  config schema design and secret handling policy (secrets only via env vars,
  never in YAML).

### Integration tests + CI split (S-5)

- **`tests/integration/`** — 58 integration tests covering:
  - Storage backends (SQLite + Postgres path with real DB when
    `NOVAFABRIC_TEST_POSTGRES_DSN` is set)
  - Migration round-trip
  - Full REST API smoke test (assets, capsules, lineage, replays, evidence)
  - Auth and RBAC enforcement
- **CI split** — `unit` job (no Postgres) and `integration` job (postgres:16
  service container). Both required to pass before merge.

## Breaking changes

None. All new functionality requires `novafabric[server]` and is behind `nova
server`. Local-only commands (`nova capture`, `nova validate`, `nova replay`,
etc.) are unchanged. Existing SQLite databases are forward-compatible.

## Upgrade

```bash
# Local-only (no change needed):
pip install novafabric==0.7.0

# Multi-user server mode:
pip install 'novafabric[server]==0.7.0'
```

No migration required for local SQLite users. Operators deploying server mode
should provision Postgres and run Alembic migrations before starting:

```bash
NOVAFABRIC_POSTGRES_DSN=postgresql://... alembic -c alembic-postgres.ini upgrade head
nova server start --config server.yaml
```

## Try it

```bash
# Check your local storage health:
nova doctor --check-storage

# Start a local no-auth server (SQLite, no config needed):
nova server start

# Migrate local SQLite to Postgres (dry-run first):
nova migrate-to-postgres --dsn "postgresql://..." --dry-run
nova migrate-to-postgres --dsn "postgresql://..."

# Issue an offline token for a CI pipeline:
nova server token issue --subject ci-pipeline --roles writer

# Authenticate with a remote server:
nova login --server https://nova.example.com
```
