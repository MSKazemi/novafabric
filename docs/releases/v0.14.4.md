### Why phased instead of one mega-bump

Each phase is its own commit so a regression bisects cleanly. Phase C (OTel 1.27/1.39 → 1.43) was the highest-risk step — 16 minor versions of API churn — so it was isolated with its own build/test gate.

| Phase | Commit | Risk | Verification |
|---|---|---|---|
| **A** — critical grpc | `def3f05` | Low — one patch version | `go build ./... && go test ./...` |
| **B** — web transitive | `242d702` | Low — `npm audit fix` + `tmp` override | `npm run build:dashboard && npm audit` |
| **C** — OTel coordinated | `747bc64` | Medium-high — large minor jump | Full collector test re-run with `-count=1` |
| **D** — mapstructure | `9c810cc` | Medium — alpha → stable | Full collector test re-run |

NovaFabric uses the OTel collector framework types (`pdata`, `component`) rather than the SDK directly, so the 1.27/1.39 → 1.43 SDK API churn did not surface in our code.

### tmp override approach

`tmp` reached us through `@lhci/cli (Lighthouse CI) → inquirer → external-editor → tmp` — a Lighthouse-CI dependency chain. The two clean fixes were:

1. **`npm audit fix --force`** would downgrade `@lhci/cli` itself to a much older version (breaking change for the dev tool).
2. **`overrides` block** in `web/package.json` forces `tmp ^0.2.4` transitively without touching Lighthouse CI.

We chose option 2:

```json
"overrides": {
  "tmp": "^0.2.4"
}
```

## CI restoration

Collector CI had been failing since BQ-011 merged in v0.14.3. The Dependabot triage (specifically Phase C) made it impossible to ignore, since `go.mod` started requiring Go ≥1.25 while CI was pinned to 1.22.

### Three failures, three fixes

| Issue | Root cause | Fix | Commit |
|---|---|---|---|
| **Toolchain mismatch** | `GO_VERSION: "1.22"` in workflow vs `go 1.25.0` in go.mod | Bump workflow to 1.25 | `3d848a3` |
| **Lint false-positive** | `grep` on `flock|mmap|fcntl` matched the spool's own explanatory comments ("no flock used here") | Filter leading-comment lines (`//` or ` *`) before the rejection check | `3d848a3` |
| **Race-mode throughput** | `go test -race` instrumentation slows GH Actions runners to ~20K events/sec against a 25K floor | Split correctness (latency, p99 < 200ms — both modes) from perf budget (throughput — non-race only) | `4293f48` |
| **MPL-2.0 license** | OTel 1.43 transitively pulls `hashicorp/go-version` (MPL-2.0); CI rejects MPL-2.0 by default | Narrow allowlist in CI + ADR-0024 amendment | `4293f48` |

The all-green run is commit `4293f48`. Before this release: zero green CI runs since 2026-05-15 04:02 UTC (last green: v0.14.2's `9c2a035`).

### ADR-0024 amendment

Per the project's dependency license policy ([ADR-0024](../../design/adr/0024-dependency-license-policy.md)), MPL-2.0 is **default-deny**. The amendment dated 2026-05-15 adds one narrow exception:

> `github.com/hashicorp/go-version` is allowlisted as an MPL-2.0 transitive dep. … MPL-2.0 is file-level copyleft, not viral. Linking an unmodified MPL-2.0 Go module into an Apache-2.0 binary does not require us to relicense our code. The obligation only triggers if we modify go-version's source files (we do not).
>
> The alternative is dropping the OTel collector framework, which is core to the cluster-scale collector (BQ-011 / Phase 2). The framework itself is Apache-2.0; only this one transitive sub-dep is MPL-2.0.

**Scope of exception:** narrow to `github.com/hashicorp/go-version` only. Future MPL-2.0 deps require their own amendment.

### Race-mode test pattern (precedent)

The split between **correctness** (asserted under `-race`) and **perf budget** (asserted in non-race only) is a pattern future tests should follow:

```go
// Correctness — asserted in BOTH race and non-race modes.
// Catches deadlocks/livelocks even under instrumentation.
if p99 >= 200*time.Millisecond {
    t.Errorf("p99 batch signing latency %v ≥ 200ms", p99)
}

// Perf budget — asserted only in non-race builds.
// The race detector adds 5–10× overhead; CI runner variance is wide.
// Benchmarks (BenchmarkX, always race=false) carry the perf budget for
// race=false runs and dedicated perf workflows.
if !raceEnabled {
    if eventsPerSec < 100_000 {
        t.Errorf("throughput %.0f events/sec < 100K/sec", eventsPerSec)
    }
}
```

## Toolchain side-effects (operator-facing)

- **Go ≥ 1.25 is now required** to build the collector locally. The collector CI workflow has been bumped accordingly. NovaFabric core (`src/novafabric/`) is Python and unaffected.
- **`google.golang.org/grpc v1.80.0`** is pinned indirectly via Phase C. Forward-only from the v1.79.3 Phase A bump; no regression risk.
- A pre-existing TypeScript 7.0 `baseUrl` deprecation warning continues to surface during `cd web && npm run lint` (unrelated to this release).
- A GitHub Actions deprecation warning for `actions/checkout@v4`, `actions/setup-go@v5`, `actions/setup-python@v5` running on Node.js 20 surfaces in workflow runs. Not failing — Node.js 24 default starts 2026-06-02.

## Upgrade

No schema changes, no API shape changes, no CLI changes. Drop-in replacement for v0.14.3.

```bash

```

```bash
go version  # must be ≥ go1.25
cd collector && go build ./...
```
