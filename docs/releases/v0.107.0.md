# v0.107.0 — Capture that a workload cannot turn against its host, one verifier behind every trust surface, and documented behaviour that is true

**Released 2026-10-23.** A security and correctness release. A line-by-line review checked the
documentation against the code (about 1,300 claims) and a docs-vs-code audit added 54 more items;
every confirmed defect was fixed with a test that fails when the fix is removed, and four
independent attack reviews then tried to break the fixes and found the next layer of holes, which
are fixed here too. **This release changes behaviour in many places. Read
[Behaviour changes and upgrade notes](#behaviour-changes-and-upgrade-notes) before upgrading.**

## What's in it

### Two critical fixes

- **`nova serve`: a read-only token could become admin.** Rego posted to `/api/policy/check` ran in
  an `opa` that inherited the server's environment and could read the admin session token. Caller
  Rego now needs `admin`, and every `opa` NovaFabric starts runs with no inherited environment and
  without `opa.runtime`, `http.send` or network lookups.
- **`nova server`: a writer could overwrite any file the server could write** through
  `POST /v0/evidence`. Request paths are gone from that API, and every id that becomes a file name —
  from a request, manifest, event or capsule — must be a single safe path segment.

### Capture integrity

- **The capsule is untrusted input once the workload has run.** After the workload exits, a sweep
  removes every symlink, FIFO, socket and device at any depth — never following one — and records
  the tamper in the signed manifest (`capture_tampered`), in `capture-health.json` and in the
  redaction proof; the capsule directory is then pinned. Every later read refuses links and never
  blocks; every later write replaces the file by rename. Before this, a workload could make the
  secret scanner rewrite a file outside the capsule, hang capture with a FIFO, or — under
  `--runner docker` or Kubernetes — make host-side finalisation write host files.
- **Capture never reaches the network and never breaks your call.** A nested remote `$ref` in a
  tool schema was fetched at every capture level, `air_gapped` included. Recorder failures in the
  OpenAI, Anthropic, MCP and wire hooks reached the workload; they are now logged and counted.
  `openai` 3.x traffic over `httpx2` is captured again; streamed responses are never consumed by
  a hook; a stream records only into the capture that opened it.
- **A required capsule file that is present but unusable is an error, never empty output** —
  exports, reports, verdicts and attestations stop instead of reporting $0, "no secrets" or a
  dropped run.

### Verification and evidence

- **One verifier per artifact, behind every surface.** `nova verify`, the trust radar, the Seal
  tab and `POST /api/runs/{id}/verify` share `verify_capsule`; `nova verify <bundle>.zip` and
  `POST /api/evidence/{id}/verify` share `verify_bundle_archive`. A tampered or transplanted
  capsule can no longer read `attested` on one surface while `nova verify` fails it, and a
  capsule whose `capsule.yaml` was swapped for an edited `capsule.json` fails everywhere.
- **Evidence Bundles sign every member.** A members statement covers every file and the
  manifest's fields; a bundle's runs come only from its verified signatures; signer trust is
  pinned with `NOVAFABRIC_EVIDENCE_TRUSTED_KEYS`; symlinks are never followed by any exporter.
  Bundles built before this release verify as "signed content only".
- **NovaSeal:** an unverifiable RFC 3161 token is not a timestamp, and an unanchored one is
  labelled `UNANCHORED` (`timestamp_trust`); the sealer's own log is identified by signer; re-seals
  verify; `nova ledger verify` produces exit 8; a Postgres `merkle_db` DSN is never written to
  disk; one Merkle-log resolver serves every caller.

### Governance

- **Every route into production is gated.** Registration accepts only `development`; rollback
  restores without a policy decision only a version that was in production, bound to its content;
  HTTP promote, `nova server` promote and `nova prompt promote` go through `promote_direct`.
- **Maker-checker** for protected labels — and for relaxing their protection — binds to the signer
  trust list. **Legal holds** live in one store, block erasure, deletion and the retention sweep at
  the moment of action, and releasing one needs `admin`. **Seal bypasses** are fail-closed on their
  audit entry, and the audit log's hash chain cannot fork under concurrent writers.

### Server, runners and tooling

- `nova serve` confines request paths to an allowlist, keeps its own secrets out of reads, writes
  no part of its token to any log, refuses unclassified routes to everyone and caps request bodies.
- Batch job scripts and Docker `extra_env` values never reach a command line; the cluster
  collector authenticates and scopes tenants; `novacap` falls back instead of refusing to run.
- About 54 smaller documented-but-untrue behaviours were made true or documented honestly, among
  them `assign-role`, Helm dashboard mode, `nova login`, `storage validate`, retention paths,
  capture levels and capsule schema refs.

## Behaviour changes and upgrade notes

The full list is in the [CHANGELOG](../../CHANGELOG.md) under *Changed — BREAKING*. The ones most
likely to affect you:

- **Specs:** a spec declaring any `status:` other than `development` is refused at registration;
  unknown spec keys are refused (put extensions under `extensions:`).
- **`nova serve`:** request-body paths are confined (`NOVAFABRIC_SERVE_PATH_ROOTS` adds roots;
  `NOVAFABRIC_SERVE_ALLOW_ANY_PATH` is gone); HTTP promotion to production needs a
  `promote_direct` allow; releasing a legal hold needs `admin`.
- **Capsules:** any symlink a workload leaves in its capsule marks it tampered; `@agent(capsule_dir=X)`
  writes one capsule per call under `X/<run_id>/`; replays default to `$NOVAFABRIC_HOME/replays`.
- **Bundles and seals:** a bundle whose run statement signs no `predicate.run_id` fails; a seal
  bypass created before this release stops counting until re-created; the promotion-policy store
  defaults to the resolved NovaSeal Merkle log.
- **Config:** `NOVAFABRIC_DB_PATH` names only the registry (`NOVAFABRIC_METADATA_DB_PATH` names the
  metadata store); the collector refuses non-loopback callers without `NOVA_COLLECTOR_TOKEN`.
- **After upgrading:** rotate the `nova serve` token and any non-admin issued tokens, and an
  auto-generated `$NOVAFABRIC_HOME/keys/signing_key.pem`; re-verify capsules and bundles you relied on from the radar or the verify
  APIs; rotate a Postgres password you put in `merkle_db` and delete any stray
  `postgres:`/`postgresql:` directory where you ran `nova`; rotate credentials you passed through
  `extra_env` with `slurm`, `lsf` or `docker`; rotate the serve token if old audit records left the
  machine. See [SECURITY.md](../../SECURITY.md).

## Try it

```bash
pip install --upgrade "novafabric==0.107.0"
nova --version                          # novafabric 0.107.0

nova verify --json ~/.novafabric/capsules/<run-id>      # capture_tampered, special_entries, timestamp_trust
nova export-evidence <run-id> -o bundle.zip
NOVAFABRIC_EVIDENCE_TRUSTED_KEYS=signer.pub.pem nova verify bundle.zip   # every member signed, signer pinned
```

## Verification

Release-preparation gates on the release tree: the fast tier (`make test-fast`) ran **22,245
passed, 0 failed, 95 skipped** after the final merge of `main`; `ruff check` and `mypy src`
(1,009 files) are clean; the OpenAPI specs, the command registry and the architecture diagrams
regenerate unchanged; the dashboard type-checks and its unit suite passes. Every fix has a test
that fails when the fix is reverted. Four attack reviews rebuilt exploits against the release
code — path tricks, symlink and FIFO planting by a hostile workload, forged and re-signed
bundles, manifest substitution, concurrent bypasses — and each confirmed hole they found is fixed
in this release; the remaining known limits are listed in the
[ROADMAP](../../ROADMAP.md) open-items table and in SECURITY.md.
