# NovaFabric v0.76.0 — 2026-07-25

**Provable delegated authority — the "acted-as" delegation chain.** ADR-0106's
category-defining evidence object (§NF-084) ships: a signed, offline-verifiable
authority chain for agentic runs, with a verifier whose whole job is to make
privilege escalation impossible. `experimental`. Full detail: `CHANGELOG.md`
§[0.76.0].

## Highlights

### The delegation chain (§NF-084)

An agent rarely acts on its own authority — it acts *as* a user, and may hand a
narrower slice to a sub-agent. `trust/delegation.py` records that as a
`DelegationChain`: an ordered list of signed `Grant` hops
(`user → agent → sub-agent`), each stating *who granted*, *to whom*, *what scope*,
and *until when*, signed by the granter's Ed25519 key. It is **evidence, not an
issuer** — NovaFabric verifies a chain a third party can re-check offline; it does
not mint the underlying credentials.

### The verifier enforces the four properties that matter

`verify_delegation_chain(chain, trusted_roots=...)` rejects anything that isn't
airtight, and returns the effective acting principal + effective scope only when
all hold:

1. **Authenticity** — every hop's signature verifies under its granter's key.
2. **Linkage** — the key/identity a hop delegates *to* is exactly the key/identity
   that signs the next hop (you cannot substitute a different key for a reused
   name).
3. **Attenuation** — each hop's scope is a subset of its granter's scope, so
   authority only ever narrows and **no hop can grant a capability its granter did
   not hold**. This is the anti-privilege-escalation core.
4. **Freshness** — no grant is expired, and a child grant never outlives its
   parent.

The test suite exercises the happy path *and* every failure a real adversary would
try: scope escalation, a tampered signature, broken key linkage, an untrusted
root, an expired grant, and a child outliving its parent — each rejected with a
specific error.

### Secrets never enter a grant

Per ADR-0106 I-2, a `Grant` carries only public keys, identities, scopes,
expiries, an optional public grant reference, and the signature — never private
keys or secret tokens.

### Scope, honestly

This is the first slice — the category-defining one. The rest of ADR-0106
(NF-083 agent-identity binding at capture, NF-085 pre-action authorization log,
NF-086 HITL evidence, NF-087 AP2 mandate capture, NF-088 MCP OAuth token metadata,
NF-089 A2A scope-containment) remains future design. ADR-0106 was accepted (first
slice) under delegated authority.
