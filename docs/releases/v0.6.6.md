# v0.6.6 — Anthropic streaming + validator coverage cleanup + README refresh

Released: 2026-05-09

A polish release that closes three small open items: Anthropic
streaming-delta merge in the api-proxy (mirror of v0.6.5's OpenAI
support), `spec/validator.py` coverage cleanup, and a README refresh
to reflect everything shipped in v0.6.x.

## What's new

### Anthropic streaming-delta merge in `nova api-proxy`

Anthropic's SSE event-type model differs from OpenAI's. Where OpenAI
streams chat-completion delta events with the same shape as the final
response, Anthropic streams typed events:

| Anthropic event | What we extract |
|---|---|
| `message_start` | `id`, `model`, initial `usage.input_tokens` |
| `content_block_start` | declares a content block (text or tool_use) |
| `content_block_delta` (`text_delta`) | concatenates into the block's text |
| `content_block_delta` (`input_json_delta`) | re-assembles the tool's input JSON across event boundaries |
| `content_block_stop` | closes a block (no-op for the merger) |
| `message_delta` | `stop_reason`, cumulative `output_tokens` |
| `message_stop` | terminal sentinel |

The merger walks all events and synthesizes a non-streaming response
shaped like Anthropic's standard Messages API response. The
api-proxy's record adapter then converts the Anthropic shape (`content`
blocks) into an OpenAI-shaped `gen_ai.response.choices` array — text
blocks concatenate into the assistant message, `tool_use` blocks become
OpenAI-style `tool_calls`. So **a captured Anthropic streaming call
produces a record byte-identical in shape to a captured OpenAI streaming
call** — consumers don't need provider-specific code to read records.

### Provider-aware dispatch

`nova api-proxy` now dispatches to the right merger based on
`gen_ai_system` (resolved from the upstream URL):

- `gen_ai.system: "anthropic"` → `_merge_anthropic_streaming_response`
- `gen_ai.system: "openai"` (and unknown providers as fallback) →
  `_merge_openai_streaming_response`

Future providers (Vertex AI, watsonx if they grow streaming) plug into
the same dispatcher.

### `spec/validator.py` coverage cleanup

Three real fixes:

1. **`union_tag_invalid` error type now produces a hint.** Pydantic v2
   emits this for invalid discriminated-union tags (e.g. unknown
   `asset_type` values). Previously the validator's `_hint_for_error`
   missed this case, so users got an opaque "Input tag '…' does not
   match any of the expected tags" with no actionable hint. Now they
   get "Valid asset_type values: model, agent, prompt, tool, …".
2. **Five new tests** covering the previously-untested hint paths
   (top-level non-mapping YAML, invalid asset_type, invalid status,
   invalid semver).
3. **CI coverage gate restored from 89 → 90.** Cleaning the validator
   coverage gap let the global figure cross the threshold cleanly
   (90.03%). The temporary inline TODO in `.github/workflows/ci.yml`
   pointing at this work is removed.

## Try it (capture Anthropic streaming via the api-proxy)

```bash
nova api-proxy \
  --listen 127.0.0.1:8765 \
  --upstream-url https://api.anthropic.com
# (capsule auto-allocated under ./.novafabric/runs/01HX…)

# In another terminal, point any Anthropic client at the proxy:
ANTHROPIC_BASE_URL=http://127.0.0.1:8765 \
  python -c "
import anthropic
client = anthropic.Anthropic()
with client.messages.stream(
    model='claude-haiku-4-5-20251001',
    max_tokens=64,
    messages=[{'role':'user','content':'Hi'}],
) as stream:
    for text in stream.text_stream:
        print(text, end='', flush=True)
"

# Inspect the capsule — streaming call has merged content + finish_reason + usage
RUN=$(ls -dt .novafabric/runs/*/ | head -1)
jq '.["gen_ai.response.choices"][0].message.content,
    .["gen_ai.response.finish_reasons"],
    .["gen_ai.usage.output_tokens"]' \
  $RUN/model-calls.jsonl
```
