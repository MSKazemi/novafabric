# NovaFabric v0.79.0 — 2026-07-25

**An append-optimized proof log — the Merkle Mountain Range.** ADR-0110 names an
MMR append log as the structure behind cross-node ordering proofs; this release
ships that structure as a standalone, verified primitive. `experimental`. Full
detail: `CHANGELOG.md` §[0.79.0].

## Highlights

### `MerkleMountainRange` (ADR-0110 §NF-051, D14)

An MMR is an accumulator built for append: its persistent state is the small set
of **peaks** (the roots of the perfect binary subtrees that tile the leaves), so
both the state and every inclusion proof are O(log n). `trust/novaseal/mmr.py`
provides:

- `append(leaf_hex)` — add a leaf; the MMR carries equal-height peaks into parents.
- `root()` — the deterministic **bag of peaks** (folded right-to-left under a hash).
- `inclusion_proof(i)` — an O(log n) proof: the sibling path to the leaf's subtree
  peak plus the neighbouring peaks.
- `verify_mmr_proof(leaf, proof, root)` — a pure verifier that recomputes the peak
  from the path, re-bags it, and compares to the root; it returns `False` on any
  mismatch or malformed proof and never raises.

### Provably append-only

Appending never rewrites an existing node, so an old leaf's proof still verifies
against every later root. The test suite proves this directly: across leaf counts
1–21 it generates a proof for **every** leaf and verifies it against the current
root, checks that an old leaf still proves after many more appends, and rejects a
wrong leaf, a tampered path, and a wrong root. Hashing is domain-separated (leaf
`0x00`, node `0x01`), matching the transparency-log convention.

### Why it matters here

This is the verifiable-half foundation of NF-051: a node's *signed ordering
commitment* is a signature over an MMR root of its worker-capsule event log — a
tiny, append-only, independently-checkable record of "what happened, in order."
An MMR is also a better fit than a fixed binary tree for the append-heavy
transparency-log and witness-checkpoint scenarios.

### Scope, honestly

This ships the D14 append-log structure. The rest of NF-051 (per-node
forward-secure-key signing of ordering commitments, cross-node happened-before
consolidation) and NF-082 (the Slurm-native consolidation profile) layer signing
and multi-node/Slurm consolidation on top and remain future design. ADR-0110 was
accepted (D14 slice) under delegated authority.
