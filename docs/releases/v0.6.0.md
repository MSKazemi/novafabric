# v0.6.0 — Wire-level capture expansion + OTel semconv + multi-target runners

Released: 2026-05-09

This release completes the v0.6 wire-level expansion track from
[RFC-0001](../../design/governance/RFC-0001-multi-vendor-strategy.md) Option C,
ships the full OTel GenAI semconv field set across every capture
hook, refactors execution behind a `RunnerSpec` protocol per
[ADR-0025](../../design/adr/0025-runner-spec-interface.md), and delivers the
first non-local runner (`docker`).

## What's new

### Wire-level capture — three new transports (RFC-0001 Option C, Track C-3)

- **`aiohttp` capture hook** (C-3.1) — async wire-level capture. Patches
  `aiohttp.ClientSession._request`, the universal entry point all
  `aiohttp` HTTP methods funnel through. Closes the gap for any
  LangChain async path, FastAPI agent, or streaming-first SDK that
  ships over `aiohttp`. Mirrors the `_httpx` / `_requests` hook shape.
- **`urllib3` capture hook + shared layering guard** (C-3.2) — patches
  `urllib3.connectionpool.HTTPConnectionPool.urlopen`, the lowest tier
  of the Python HTTP stack. Catches the long tail of clients that
  bypass higher-level libraries. New shared `_layering.py` primitive
  (a `contextvars.ContextVar`-based guard) prevents double-recording
  when `requests` calls go through `urllib3` internally — verified
  end-to-end: a single `requests.post()` produces exactly one record,
  not two.
- **AWS Bedrock URL registry entries** (C-3.3a) — `boto3` is now
  transparently captured via the `urllib3` hook. The `bedrock-runtime.*`
  and `bedrock.*` hostname patterns are in the vendored URL registry,
  classified as `gen_ai.system: aws.bedrock`. No separate `boto3` hook
  required. Body-shape adapter for per-provider Bedrock body shapes
  (Cohere, Titan, Llama) is queued as a v0.6.x followup.

### OTel GenAI semconv — full field coverage (RFC-0001 Track C-4)

NovaFabric's per-call records now emit the full set of OTel "Required
when applicable" `gen_ai.*` fields whenever they are present in the
request — across both the wire-level hooks and the per-SDK hooks. This
fixes a real spec-compliance gap in v0.5.x where only `model` and
`messages` were extracted, silently dropping all the determinism
inputs replay needs.

- **C-4 phase 1** — wire-level hooks (`_httpx`, `_requests`, `_aiohttp`,
  `_urllib3`) now extract `temperature`, `top_p`, `top_k`, `max_tokens`,
  `stop_sequences` (normalized across OpenAI's `stop` and Anthropic's
  `stop_sequences`), `seed` (critical for exact-mode replay
  determinism), `frequency_penalty`, `presence_penalty`, and
  `choice.count` whenever the request body contains them.
- **C-4 phase 2+3** — per-SDK hooks (`_openai`, `_anthropic`) migrated
  to the same shared builder. Plus they now populate
  `gen_ai.response.id` and `gen_ai.response.finish_reasons` from the
  SDK response object — fields the spec lists as required-when-
  applicable but were silently dropped before.
- **C-4 phase 4** — closed as no-work-needed. Tool-call schema is
  intentionally MCP-aligned (`design/spec/tool-call-v0.md`), not
  OTel-GenAI-aligned; the `_mcp` hook is already correct.
- New shared extractor at `src/novafabric/capture/hooks/_otel_genai.py`
  is the single source of truth. Adding a new semconv field now means
  editing one file, not five.

### Multi-target runners (ADR-0025)

- **ADR-0025 accepted** — defines the `RunnerSpec` protocol that local /
  docker / kubernetes / slurm runners will satisfy. Synchronous-blocking
  in v0.6 (async deferred to v0.7); per-runner `runner_options` dict
  with no orchestrator validation; each runner responsible for syncing
  capsule artifacts to the local FS before `run()` returns.
- **Runners.1 — `LocalRunner`** — refactor of the v0.5.x `CaptureOrchestrator`
  subprocess logic behind the `RunnerSpec` protocol. Behavior-preserving;
  no user-visible change. Default runner.
- **Runners.2 — `DockerRunner`** — runs the captured workload inside a
  container via `docker run`. New CLI surface:
  ```bash
  nova capture --runner docker \
    --runner-option image=myorg/agent-runtime:abc1234 \
    --runner-option network=bridge \
    --runner-option user=1000:1000 \
    python my_agent.py
  ```
  The capsule directory is mounted as a volume at `/novafabric/capsule`;
  artifacts land on the host filesystem. Required option: `image`.
  Optional: `network`, `workdir`, `user`, `extra_volumes`, `extra_env`.
  Image responsibility is on the user (must have NovaFabric installed).

  ADR-0025 anti-patterns enforced (and tested explicitly): no
  `--privileged`, no docker-socket mount, no host namespace defaults,
  no `PATH`/`HOME`/etc. host env leakage to the container.

- **Runners.3 (kubernetes) and Runners.4 (slurm)** are queued for
  v0.6.x patch releases.

### Cleanup — exception-recording symmetry

`_httpx` and `_requests` hooks were silently dropping records when the
underlying call raised (connection failures, timeouts, TLS errors). The
new wire-level hooks (`_aiohttp`, `_urllib3`) used a `try/finally` pattern
that recorded the attempt with `status=error` and re-raised. This
release brings `_httpx` and `_requests` to the same pattern. Connection
failures now produce a complete audit trail.

### Examples + tutorial (already on v0.5.0 `main`, included for completeness)

The five examples and the day-by-day tutorial that landed on v0.5.0's
`main` are formally part of v0.6.0:

- `examples/replay-and-diff/` — regression-detection workflow

- `examples/azure-openai/` — Azure OpenAI, proves endpoint-agnostic capture

### Paper cuts

- `nova --version` / `nova -V` now prints the installed version.
- `examples/*/runs/` and `examples/*/capsule/` added to `.gitignore`
  so example-run capsules don't accumulate in working trees.

### Path A research note (non-Python LLM-client capture, deferred)

`design/research/llm-api-proxy.md` captures the design for a future
`nova api-proxy` for non-Python LLM clients (Cursor, Claude Desktop,
Node/Go agents). Status: candidate only, **not built**. Promotion
criteria are explicit; TLS MITM is permanently rejected as an option.

## Breaking changes

None. All additions are new files, new CLI flags with safe defaults, or
additive schema fields. The `--runner` flag defaults to `local`,
preserving every v0.5.x usage. Existing capsules from v0.5.x validate
unchanged.

## Upgrade

```bash
pip install novafabric==0.6.0
# or:
uv add novafabric@0.6.0
```

## Try it

```bash
# Capture an async LangChain agent — async paths now flow through aiohttp hook
nova capture python my_async_agent.py

# Capture a boto3 / Bedrock workload — urllib3 hook fires automatically
nova capture python my_bedrock_agent.py

# Run the same workload inside a container
nova capture --runner docker \
  --runner-option image=myorg/agent-runtime:latest \
  python my_agent.py

# Replay determinism is real now: seed and temperature flow into the record
cat .novafabric/runs/<run-id>/model-calls.jsonl | jq '{
  seed: .["gen_ai.request.seed"],
  temperature: .["gen_ai.request.temperature"],
  finish_reasons: .["gen_ai.response.finish_reasons"]
}'
```
