# NovaFabric v0.2.0 — Execution Capsules

## Summary

NovaFabric v0.2.0 introduces **Execution Capsules** — the core primitive of
Replayable AI Infrastructure. Every command, script, or agent function run can
now be captured as a portable, schema-validated directory that records what
happened, what the environment was, and that no secrets leaked.

This is the first release where NovaFabric is a **recorder**, not just a
registry.

---

## What is an Execution Capsule?

An execution capsule is a directory written to `.novafabric/runs/<ulid>/`
containing:

| File | Contents |
|---|---|
| `capsule.yaml` | Run manifest: id, status, command, timing, artifact refs |
| `trace.jsonl` | Execution spans (OpenTelemetry-compatible) |
| `model-calls.jsonl` | LLM API calls (OTel GenAI semconv) |
| `tool-calls.jsonl` | Tool invocations |
| `env.lock` | Full environment snapshot: packages, OS, Python, hardware |
| `redaction-proof.json` | Proof that no secrets appear in any artifact |
| `replay.yaml` | Replay policy and constraints |
| `inputs/` | Input artifacts |
| `outputs/` | stdout, stderr, and output artifacts |

Capsules are written on **success and failure**. A failed run is often the most
valuable one to inspect.

## Highlights

### `nova capture <cmd>`

Wraps any command and produces a full capsule:

```bash
nova capture python train.py --lr 0.001
nova capture -- python -c "import sys; sys.exit(1)"
ls .novafabric/runs/
```

AI SDK calls (OpenAI, Anthropic, httpx) made inside the subprocess are
intercepted via `sitecustomize.py` injection — no changes to application code
required.

### `nova validate <path>`

Smart routing: accepts both capsule directories and asset YAML files:

```bash
# Validate a run capsule
nova validate .novafabric/runs/01HXAY7M5JZ8R7K4P9DPBYK2WX/

# Validate an asset spec (v0.1 behavior, unchanged)
nova validate my-model.yaml
```

Capsule validation checks `capsule.yaml`, `env.lock`, and `redaction-proof.json`
against their JSON Schemas, and verifies all required files exist.

### `@agent(capsule_dir=...)` decorator

SDK-decorator capture mode — hooks are installed in-process:

```python
from novafabric.sdk.agent import agent

@agent(name="research-agent", version="0.1.0", capsule_dir="capsule/")
def run():
    # openai, anthropic, and httpx calls are auto-captured
    ...
```

The `capsule_dir` parameter is optional. Without it, the decorator behaves
exactly as in v0.1.

### Secret redaction

Every capsule includes `redaction-proof.json`, a signed record that all
artifacts were scanned against 12 LLM provider key patterns (Anthropic,
OpenAI, HuggingFace, Replicate, and more). Detected secrets are replaced with
`[REDACTED:<rule-id>]` before the capsule is written.

### Failure capsules

A non-zero exit code produces a complete capsule with:

```yaml
status: failure
exit_code: 1
error:
  type: NonZeroExit
  message: "Command exited with code 1"
```

## New CLI commands

| Command | Description |
|---|---|
| `nova capture <cmd>` | Capture a command as a run capsule |
| `nova validate <capsule-dir>` | Validate a capsule directory |

The `nova` binary is an alias for `novafabric`. Both are available after
install.

---

## Schemas

All capsule artifacts validate against JSON Schema 2020-12:

| Schema | File |
|---|---|
| Run capsule manifest | `schemas/run-capsule.schema.json` |
| Environment lock | `schemas/environment.schema.json` |
| Secret redaction proof | `schemas/secret-redaction.schema.json` |
| Model call record | `schemas/model-call.schema.json` |
| Tool call record | `schemas/tool-call.schema.json` |
| Replay policy | `schemas/replay-policy.schema.json` |

Schemas are bundled with the package. `nova validate` uses them without
requiring network access.
