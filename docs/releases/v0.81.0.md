# NovaFabric v0.81.0 — 2026-07-25

**Decentralized identity for agents — `did:key` and Verifiable Credentials,
offline.** ADR-0075's core ships: a self-certifying DID method and credential
verification that need no network and no new dependency, composing with the
delegation chain from v0.76.0. `experimental`. Full detail: `CHANGELOG.md`
§[0.81.0].

## Highlights

### `did:key` — self-certifying, no network

An agent's identity should be verifiable from a sealed capsule alone. `did:key`
makes that possible: the identifier *encodes* the public key. `trust/did.py`
provides `did_key_from_public_key` and `public_key_from_did_key` for Ed25519 —
multibase base58btc over the multicodec-prefixed key, producing the standard
`did:key:z6Mk…` form. Resolution is **pure decoding**: no network, no registry, no
external service.

### Verifiable Credentials — offline-checkable authorization

`VerifiableCredential` records an authorization grant — an issuer DID attests a
subject DID holds a scope of capability URIs until an expiry — with an Ed25519
proof over the canonical credential. `verify_credential`:

- resolves the issuer DID to its key and checks the proof;
- checks the expiry;
- **rejects** a tampered authorization, a credential signed by a key *other than*
  the one the issuer DID encodes, and an expired credential — and never raises.

`issue_credential` refuses to sign a credential in a DID's name with a key that
doesn't match that DID, so a credential is always bound to its issuer's identity.

### Composes with the delegation chain

This slots directly beneath the ADR-0106 delegation chain from v0.76.0: a grant's
`grant_ref` can point at a VC issued here, turning "who delegated what" into a
chain of independently-verifiable credentials.

### No new dependency

base58btc is implemented in-module (stdlib only) and the signatures reuse the
existing `cryptography` Ed25519 — **zero new runtime dependencies** (ADR-0075). The
`did:key:z6Mk…` output was cross-checked against the W3C multicodec spec.

### Scope, honestly

This ships the `did:key` + VC verification core. Optional `did:web` anchoring for
federated deployments, the full W3C VC 2.0 JSON-LD serialization, and end-to-end
authorization-chain reconstruction from capsule metadata remain future design.
ADR-0075 (which was `Future Design`) was accepted (first slice) under delegated
authority.
