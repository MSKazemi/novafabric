# NovaFabric v0.71.0 — 2026-07-24

**Cloud KMS envelope encryption — the AWS branch, implemented.** The
application-layer envelope-encryption KMS wrap path (ADR-0185) had a real local
implementation and a test double, but the cloud branches were "planned,
infra-gated." This release ships and verifies the AWS one. Everything new is
`experimental`. Full detail: `CHANGELOG.md` §[0.71.0].

## Highlights

### `AwsKmsWrappingBackend` (ADR-0185)

`trust/novaseal/signing_backend.py` gains `AwsKmsWrappingBackend`, which
satisfies the `KeyWrappingBackend` capability (`wrap_key` / `unwrap_key` /
`kek_ref`) using AWS KMS `Encrypt` / `Decrypt`:

- The plaintext key-encryption key **never leaves KMS** — the process only ever
  holds the data-encryption key and the opaque KMS ciphertext blob.
- `novafabric.trust.envelope_encryption` accepts it directly, so per-object DEK
  wrapping now works through a real cloud KMS, not just the local/mock KEK.
- `kek_ref()` returns a stable, non-secret `aws-kms:<region>:<key-id>` identifier
  for audit/manifest use.

### Verified without a cloud account

The backend is exercised end-to-end — including the full
`encrypt_blob` / `decrypt_blob` round-trip — against an **in-process AWS mock**.
`moto` (Apache-2.0, Tier A under ADR-0024, **dev/test-only**) is added to the dev
dependency group; no live AWS credentials are required to run the suite. `boto3`
was already the `[seal-aws]` runtime extra.

The Azure Key Vault and GCP Cloud KMS wrap paths remain planned; the local and
mock backends are unchanged.

## Upgrade notes

Additive — no breaking changes and no new *runtime* dependency (the AWS backend
uses the existing `[seal-aws]` boto3 extra; `moto` is dev-only). Existing
envelope encryption with the local/mock KEK is unchanged.
