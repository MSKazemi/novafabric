# v0.13.3 — N-Run Diff in Dashboard (C-5)

Released: 2026-05-15

The dashboard diff comparison now supports up to 5 runs at once. Selecting 3–5 runs
in the RunsTab and clicking "Compare selected ⊕" enters a new **N-run mode** in
DiffTab: the first run is the baseline and N-1 parallel diffs fire against it,
with results shown as stacked collapsible cards.

---

## Background

C-4 (v0.12) added the compare shortcut for exactly two runs. C-5 lifts that cap
and introduces a "baseline + N-1" model: the first selected run serves as the
reference, each subsequent run is compared against it in parallel. This avoids an
N×N matrix (O(N²) diffs, hard to read) and keeps results anchored to a single
reference point.

The URL format is migrated from `?run_a=&run_b=` to `?run_ids=a,b,c` to support
an arbitrary number of IDs. The old parameters are still parsed on load for
backward compatibility with bookmarked URLs.

---

## Changed

### `RunsTab`

- `checkedIds` state type changed from `[string] | [string, string] | []` to
  `string[]` with a max of 5.
- Checkbox `disabled` condition: `checkedIds.length >= 5 && !isChecked`
  (was `=== 2`).
- Compare banner: visible when `checkedIds.length >= 2` (was `=== 2`);
  label shows `{checkedIds.length} runs selected` (was hardcoded "2 runs selected").
- Banner "Compare selected" click: calls `onCompareTo(checkedIds)` (was
  `onCompareTo(checkedIds[0], checkedIds[1])`).
- `onCompareTo` prop type: `(ids: string[]) => void` (was `(a, b) => void`).
- Cmp button (2-run per-row flow): calls `onCompareTo([compareA!, r.run_id])`.
- `CapsuleInspector` receives a wrapped adapter: `(a, b) => onCompareTo([a, b])`.

### `DashboardApp`

- `diffPair: { a: string; b: string } | null` replaced by `diffIds: string[]`.
- `handleCompareTo(ids: string[])` replaces `handleCompareTo(a, b)`.
- URL serialisation: `?run_ids=a,b,c` (old `run_a`/`run_b` params still parsed
  during `useState` initialisation for backward compat).
- `useEffect` clears `run_ids`, `run_a`, and `run_b` from the URL on tab change.
- DiffTab rendered as `<DiffTab initialIds={diffIds.length > 0 ? diffIds : undefined} />`.

### `DiffTab`

- Props changed: `{ initialA?: string; initialB?: string }` →
  `{ initialIds?: string[] }`.
- When `initialIds.length === 2`: existing single-diff flow (auto-run on load).
- When `initialIds.length > 2`: `runMultiDiff(baseline, comparisons)` is called
  immediately.
- Session storage (DU-4) only activates in 2-run mode; N-run state is ephemeral.

---

## Added

### `runMultiDiff(baseline, comparisons)`

New `useCallback` in `DiffTab`:

1. Initialises `multiResults` with N-1 `{busy: true}` entries.
2. Fires N-1 parallel `Promise.allSettled([api.diff(baseline, cId), api.getRun(cId)])`.
3. On settle: updates each entry with `report`, `capsule`, or `error`.

### `MultiDiffCard` component

Rendered once per comparison run. Features:

- Collapsible header showing truncated run ID + change-count badge
  (`identical` when 0 Δ, amber `N Δ` when diffs exist).
- Expanded body: `<DiffSection report={result.report} />` (reuses the existing
  diff renderer).
- Busy state shows "diffing…" inline.
- Error state shows the error message.

### `MultiDiffResult` interface

```typescript
interface MultiDiffResult {
  runId: string;
  report: DiffReport | null;
  error: string | null;
  busy: boolean;
  expanded: boolean;
  capsule: FullCapsule | null;
}
```

### N-run mode header

A header card above the stacked diff cards shows:

- "N-run comparison — N runs" label.
- Baseline run ID (first 16 chars).
- "N-1 runs compared against it" count.
- "← 2-run mode" button to clear multi-run state and return to the standard form.

---

## Upgrade Notes

No Python or CLI changes. Only TypeScript / React components changed.

The `onCompareTo` prop in `RunsTab` changed from `(a: string, b: string) => void`
to `(ids: string[]) => void`. If you have custom integrations or components that
pass this prop, update them to wrap as `(a, b) => onCompareTo([a, b])`.

Bookmarked URLs using `?run_a=…&run_b=…` continue to work — they are parsed into
`diffIds` on load and the URL is normalised to `?run_ids=…` when the diff tab is
next opened from the runs tab.
