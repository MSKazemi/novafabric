# v0.105.0 — Mocked replay that fails closed, a diff gate that tells a difference from a failure to compare, and one secret pipeline for every capsule

**Released 2026-10-10.** A replay, diff and evidence-integrity release. Mocked replay now serves
much more of a recorded run (async, streamed and Responses API calls, recorded model errors,
recorded MCP results, declared Python tools) and **fails closed** when the re-run diverges.
`nova diff` keeps exit `1` for "found a difference" and uses `2` for "cannot compare". Every
capsule writer (`nova capture`, the framework adapters, `@agent`, OTLP ingest) now goes through
the same secret scan, residual pass and opt-in seal. **This release changes behaviour in several
places. Read [Behaviour changes and upgrade notes](#behaviour-changes-and-upgrade-notes) before
upgrading a CI gate.**

Maturity labels follow the project convention: **works today**, **experimental**, **planned**,
**future design**. Each feature is labelled in the [CHANGELOG](../../CHANGELOG.md) entry for this
version; experimental features below stay experimental.

## What's in it

### Security and evidence integrity

| Area | What changed |
|---|---|
| **One finalization path** | Framework-adapter, `@agent` and OTLP-ingested capsules now finalize through `nova capture`'s path (`capture/finalize.py`). They get manifest redaction, the residual pass, the fail-closed manifest gate, `lineage.jsonl` and `evidence_digests`, and they are sealed when a signing profile exists (sealing stays opt-in). `nova verify` passes on them. A finalization failure never fails the wrapped call. The capsule is left unsealed with `metadata.finalization_error`. |
| **Residual pass** | After the last write, every capsule file except `capsule.yaml`, the proof and `.seal/` is rescanned before it is digested and sealed. This covers secrets written into `replay.yaml`, the C2PA marker or by an ADR-0135 masker. The final manifest is checked once more. If it still matches a rule, the capsule is **not sealed**. Recorded in the new optional `residual_check` block of `redaction-proof.json`. Scanner 0.4.0. |
| **Rule pack 0.7.0** | AWS access key ids, AWS secret access keys (only when their key name is next to them), GitHub tokens (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`) and fine-grained PATs (`github_pat_`) are now detected. 18 rules, up from 14. The run-capsule architecture page lists what the scanner still does **not** detect, and a test keeps that list honest. |
| **Maskers and `capture-health.json`** | ADR-0135 maskers (experimental) now walk the same files as the built-in scanner. `capture-health.json` is written before the residual pass, so it is scanned and bound by `evidence_digests`. |
| **Audit log** | Every audit-log reader and writer resolves the path at call time: `NOVAFABRIC_AUDIT_LOG_PATH`, else `$XDG_DATA_HOME/novafabric/audit.jsonl`, else `~/.local/share/novafabric/audit.jsonl`. Before, most writers ignored the override. |
| **Sealing and verify** | `nova seal init` (experimental, ADR-0301) sets up opt-in sealing in one offline command with a local, **self-asserted** identity. `nova verify` reports the signer's trust level (`identity_trust`) and gains `--json`. `timestamp_ok` is `null` when there is no timestamp. `ca_chain_ok` is true only when `--ca-bundle` validated the chain. A key that does not match its certificate no longer produces a seal that can never verify. |
| **Fixes** | `nova export-evidence --timestamp` bundles now pass their own verification recipe. `nova init --force` archives the old signing key instead of overwriting it. `nova verify` reports, instead of crashing on, a DSSE signature that is not valid base64. Locked dependencies clear every `pip-audit` finding, and the three npm trees pass the `npm-audit` gate (one time-boxed waiver for a dev-only chain). |

### Replay

| Area | What changed |
|---|---|
| **Fail-closed mocked replay (ADR-0300)** | A replay that makes more model calls than were recorded, calls another provider or in another order, calls an unsupported surface, makes an unrecorded MCP call or leaves recorded responses unconsumed ends `failure` (`ReplayDivergence`, exit 1). `--permissive` keeps the old warn-and-continue outcome and still records every divergence. New `replay_contract` block and counters in the replay result. |
| **More surfaces served (ADR-0304)** | OpenAI `chat.completions.create`, OpenAI `responses.create` and Anthropic `messages.create` are served sync and async, streamed or not. Live network connections made by the replayed process are reported, never blocked. A generated support matrix in [replay modes](../architecture/replay-modes.md) says what is served, refused or not controlled. |
| **Recorded model errors (experimental)** | A recorded rate limit, 4xx, 5xx, timeout or connection error is raised again as the SDK's own exception class, from an allow-list. A stream that failed part-way is served as its delivered chunks, then the same exception. |
| **Tool results** | Recorded MCP `call_tool` results are served one-to-one (ADR-0300). `record.tool` (experimental, ADR-0306 slice 1) captures declared Python functions and serves their results before the body runs. `replay.yaml` `tool_overrides` (experimental, ADR-0306 slice 2) are enforced inside the replay, through the same decision `--dry-run` prints. **Other tools still run live**, so run replays in a sandbox. |
| **Logical calls (ADR-0305)** | The `httpx` wire record under an SDK call is marked `transport` and linked to the SDK record. Counts, `nova cost`, `nova diff`, replay counters, the dashboard and the exporters read logical calls only. |
| **Refusing what cannot be re-run** | A framework-adapter, `@agent` or OTLP-imported capsule has a label, not a program, as its command. `mocked` replay now refuses it up front (`CapsuleNotReplayable`) instead of trying to execute the label. `intervention` records whether a substituted tool result reached the workload (it does not; tools run live). |

### Diff and CI gate (ADR-0303 and Amendments 1 and 2)

| Area | What changed |
|---|---|
| **Exit codes** | `0` no difference (or no gate), `1` the gate found a difference, `2` cannot compare. An unresolvable ref, an unreadable or malformed `capsule.yaml` or `env.lock`, and malformed record lines under the gate are all exit `2`. `--help` and the CLI reference list every code. |
| **What counts as a change** | A paired model call is compared on its provider and every recorded `gen_ai.request.*` parameter (`temperature`, `seed`, `max_tokens`, …), not only model, messages and response. Nested files under `outputs/` are compared. |
| **Output** | The JSON report carries `has_changes` and `skipped_malformed_lines`. `--json` means `--output-format json` in every mode. `name@version` diffs honour `--output-format`. `github-annotation` reports added-only or removed-only diffs as errors, and annotation messages are escaped. `GET /api/diff` returns the counts and `has_changes`. |

### Capture

| Area | What changed |
|---|---|
| **Runner, image and Slurm job (experimental, ADR-0307)** | `capsule.yaml` records `host.runner` (the runner name; for `docker` and `kubernetes`, the image reference and the digest the runtime resolved, never taken from the tag) and, inside a Slurm job, `host.slurm` from an explicit allow-list (node list stored as a hash). |
| **SDK calls** | Async, streamed and Responses API calls are recorded with their response. Each SDK record names its API surface. A stream that never delivered a finish reason is recorded with `finish_reason: null`. Anthropic finish reasons are stored in the schema enum, with the provider's raw value kept in an extension. |
| **Framework adapters (experimental)** | LlamaIndex, Pydantic AI and LangGraph streams are captured for the whole stream. An abandoned or cancelled stream is recorded as `status: partial`. LlamaIndex `WorkflowHandler` runs and Haystack `AsyncPipeline` runs are captured once and completely. A bare adapter run id now resolves in `nova replay`, `nova diff` and `nova validate`. |
| **Host facts** | Every capsule writer measures `host` with one function. Adapter capsules no longer record `x86_64`, `cpu_count: 1` or `memory_bytes: 0` regardless of the machine. macOS and Windows record real memory. `env.lock` names the real NovaFabric version. A command that never started records `error.type: WorkloadNotStarted`. |

### CLI, packaging and docs

- **`--json` is plain JSON.** 38 JSON output paths no longer carry ANSI colour codes when colour
  is forced. Eleven commands no longer print notes after their JSON on stdout.
- **`--help` examples use real flags and IDs.** `nova classify run`, `nova eval agent`,
  `nova eval run`, the `nova audit` commands, `nova serve` and `nova export-examiner pccp` are
  corrected.
- **Every documented command resolves.** A new guard checks every `nova …` invocation in
  `README.md`, `llms.txt`, `docs/` and `examples/**/*.md` against the real command tree. It found
  and fixed 54 that did not exist.
- **Public claims match the code.** `CITATION.cff`, `.zenodo.json`, the GitHub Action and the
  Claude Code plugin say *secret-scanned* and *sealable*, not "secret-redacted" or "signed", and
  name five replay modes. A test reads the rule count and the replay modes from the code.
- **The wheel ships the dashboard only (ADR-0299).** `nova serve --experimental` no longer
  carries a copy of the website. The public pages live on <https://novafabric.ai>. The dashboard
  source moved from `web/` to `ui/dashboard/`.
- **Collector.** `go install github.com/MSKazemi/novafabric/collector/cmd/novafabric-collector@latest`
  works: the Go module now declares the path its code lives at.
- **Server mode.** Alembic migration `v005` grants the application role `DELETE` on `runs`,
  `capsules` and `signatures`, so governed delete works as `novafabric_app` under row-level
  security.

## Behaviour changes and upgrade notes

Each item below is flagged as a behaviour change in the [CHANGELOG](../../CHANGELOG.md).

1. **Mocked replay fails closed.** A replay that passed before may now end `failure`
   (`error.type: ReplayDivergence`, exit 1). This includes leaving recorded responses
   unconsumed, and replays of non-Python commands that have recorded model calls. `nova evidence
   attest-replay --mode mocked` attests `mismatch` for such runs. Pass `--permissive` to get the
   old outcome.
2. **A recorded model failure that cannot be raised faithfully fails the replay at that call.**
   The divergence is `recorded_error_unreconstructable`. Before, the failed call was handed the
   next call's response.
3. **`--permissive` alone no longer runs an unmatched MCP call live.** MCP calls are always of
   `unknown` mutation class. Add `--allow-unknown-mutation` to keep the old behaviour.
4. **A strict mocked replay refuses to start (exit 3)** when a `replay.yaml` `allow: false`
   override names a tool replay cannot intercept (`ToolOverrideUnenforceable`). `--dry-run`
   labels now say what the replay will do with each override.
5. **`nova diff` exit codes.** An unresolvable capsule ref or `name@version` ref exits `2` (it
   was `1`). An unreadable or malformed `capsule.yaml` or `env.lock` exits `2` in every mode.
   Malformed record lines exit `2` under `--assert-no-regressions` and under
   `--assert-same-shape`. A gate that tests only for non-zero is unaffected.
6. **`nova diff --assert-no-regressions` may fail where it passed.** A changed request
   parameter, a change of provider or a changed nested file under `outputs/` is now a
   difference. `github-annotation` output reports an added-only or removed-only diff as
   `::error`.
7. **Model-call counts halve for SDK workloads (ADR-0305).** Each OpenAI or Anthropic SDK call
   is now counted once (before, it was counted again for each HTTP attempt). This applies to
   `model_call_count`, `nova cost`, `nova diff`, replay counters, `nova query`, the dashboard and
   the exporters. Both records are still written. The `model_call_count` sealed into an older
   manifest is not rewritten, so **old sealed manifests keep their doubled counts**. Older
   capsules are read through a fallback that recognises the old duplicate shape.
8. **`finish_reason` may be `null`** for a stream that never delivered one. Anthropic finish
   reasons are stored as `stop` / `tool_calls` / `length` / `content_filter`, with the raw value
   in `extensions["io.novafabric.provider_finish_reasons"]`.
9. **`nova validate` from v0.104.0 or earlier rejects capsules from this version.** New proofs
   carry `residual_check`, new manifests may carry `host.runner`, and `finish_reason` may be
   `null`. Validate new capsules with v0.105.0 or later. Older capsules still validate here.
10. **The audit log path honours `NOVAFABRIC_AUDIT_LOG_PATH` everywhere.** With neither
    `NOVAFABRIC_AUDIT_LOG_PATH` nor `XDG_DATA_HOME` set, the path is unchanged.
    `NOVAFABRIC_HOME` deliberately does **not** move the audit log. An evidence export whose
    policy decision cannot be written to the audit log now fails (CLI exit `1`, dashboard
    `503 audit_unavailable`) instead of raising an unhandled `OSError`.
11. **Scale-S4's `nova seal log verify` p99 < 200 ms target is withdrawn (ADR-0268).**
    Verification still recomputes the Merkle root from every leaf. That is O(N), about 1.9 s at
    1M entries. No faster, weaker mode is planned.
12. **`nova verify` result fields.** `timestamp_ok` is `None` (JSON `null`) for a capsule with no
    timestamp. Library callers that tested `is True` now get `None`. `ca_chain_ok` is `True` only
    when a CA bundle validated the chain.
13. **Replay counters.** `model_calls_mocked` and `tool_calls_mocked` count what was served.
    `tool_calls_available` counts what a dispatcher can serve. The full count is the new
    `tool_calls_recorded`. Re-performance outcome digests of mocked replays change accordingly.
14. **`nova serve --experimental` serves the dashboard only.** `/concepts`, `/install`, `/why`,
    `/spec` and `/showcase/*` return 404 locally. `/` forwards to `/dashboard/`.
15. **`nova init --force`** moves the old Evidence Bundle signing key to `keys/archive/<UTC>/`,
    and refuses (exit 1) when `novaseal.yaml` signs capsules with that key.

Capsules written by earlier versions validate and verify unchanged. Re-capture a run to get the
new coverage. Existing capsules are not rewritten.

## Try it

```bash
pip install --upgrade "novafabric==0.105.0"
nova --version                       # novafabric 0.105.0

nova seal init                       # optional: opt-in sealing with a local, self-asserted identity
nova capture -- python my_agent.py   # prints run_id=<id>
nova verify --json ~/.novafabric/capsules/<run-id>   # identity_trust; timestamp_ok is null without a timestamp

nova replay <run-id>                 # mocked: fails closed on any divergence
nova replay --dry-run <run-id>       # what would be served, refused or run live
nova replay --permissive --allow-unknown-mutation <run-id>   # the pre-0.105 outcome

nova diff <run-a> <run-b> --assert-no-regressions --output-format json
echo "exit=$?"                       # 0 same · 1 different · 2 cannot compare
```
