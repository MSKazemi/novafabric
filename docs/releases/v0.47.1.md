# NovaFabric v0.47.1 — PROV-JSON export fix + opa-agnostic test suite

**Released:** 2026-06-11 · **Status:** experimental · **Breaking changes:** none

## Fixed

### PROV-JSON export crashed on structured lineage edges

Lineage schema v0.1.0 carries structured `source`/`target` nodes
(`{"kind": "run", "run_id": …}` / `{"kind": "asset", "asset_ref": …}`),
but the PROV-JSON exporter's `_sanitize_id` expected bare string ids and
raised on real capsules. A new `_node_id()` normalizer accepts both the
structured and legacy flat forms; the activity `run_id` falls back to
`capsule_run_id` or the source node. `nova lineage export-prov` and
`POST /api/lineage/export-prov` now work on capsules produced by current
captures. Found by the F10 conformance experiment; regression test added.

## Tests

### Suite is now opa-agnostic (TEST-OPA-1)

An autouse conftest fixture hides the `opa` binary from `shutil.which` by
default, so `get_policy_engine()` returns the allow-all `NoopEngine` —
matching CI, which never installs opa. This fixes ~110 gated tests
(export-evidence / seal / approve / SoD / rollback / validate / replay) that
otherwise hit policy DENY on any dev machine with opa installed (the v0.47.0
gate-wiring fix made the gates real; this keeps the suite deterministic).
Tests that inject their own engine or construct `OpaEngine()` directly are
unaffected; opt in to the real engine with `@pytest.mark.real_opa`.
