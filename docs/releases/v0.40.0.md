# NovaFabric v0.40.0 — CLI gap closure: `nova eval list` + `nova policy list`

**Released:** 2026-05-21

---

## Summary

Two missing CLI subcommands identified during a systematic smoke-test of all 139 nova commands have been implemented and tested.

---

## New commands

### `nova eval list`

Lists all registered eval suite adapters discovered via the `novafabric.eval_suites` entry-point group.

```bash
$ nova eval list
```

Output table columns: **Suite ID**, **Version**, **OCI Digest**, **Entry Point**.

All six built-in suites are shown:

| Suite ID | Version | OCI |
|---|---|---|
| `novafabric-smoke-v1` | 0.1.0 | host-env |
| `gaia-v1` | 0.1.0 | host-env |
| `mmlu-v1` | 0.1.0 | host-env |
| `truthful-qa-v1` | 0.1.0 | host-env |
| `swe-bench-verified-v1` | 0.1.0 | host-env |
| `agentbench-v1` | 0.1.0 | host-env |

Third-party suites added via `[project.entry-points."novafabric.eval_suites"]` are discovered automatically. Individual load errors are shown inline without crashing the command.

---

### `nova policy list`

Lists Rego policy files in the built-in bundle and any signed promotion policies stored in the PolicyStore SQLite DB.

```bash
# List everything (bundle + all stored policies)
nova policy list

# Filter signed policies to one namespace
nova policy list --namespace staging

# Use a custom Rego bundle
nova policy list --bundle /path/to/my-bundle

# Explicit PolicyStore DB path
nova policy list --db ~/.local/share/novafabric/merkle.db
```

Output has two sections:

1. **Rego Bundle** — every `.rego` file in the bundle with file name and size.
2. **Signed Promotion Policies** — version, namespace, and creation timestamp of each stored policy. If no PolicyStore DB exists yet, a diagnostic note is printed and the command exits cleanly with code 0.
