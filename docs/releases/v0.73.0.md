# NovaFabric v0.73.0 — 2026-07-25

**SAML SSO can now consume assertions — the ADR-0138 §D5 gate is resolved.** The
signature/XXE layer that §D5 deliberately withheld (pending a SAML XML-signature
library that clears the ADR-0024 transitive-license policy) now ships. It is
`experimental` and **off by default**. Full detail: `CHANGELOG.md` §[0.73.0].

## Highlights

### The §D5 license gate, resolved by `signxml`

The original ADR-0138 evaluated `python3-saml` (needs the native `libxmlsec1`
library — a distribution-license concern) and `pysaml2`. A third candidate not in
that table clears the gate cleanly: **`signxml` (Apache-2.0)**, whose *entire*
runtime tree is Tier-A — `lxml` (BSD-3-Clause) + `cryptography` (already a core
dependency) + `certifi` (already present via httpx) — and which needs **no native
`libxmlsec1`**. It ships as the optional `novafabric[saml]` extra.

### `server/saml_verify.py` — the V1/V2/V10 layer

The verifier plugs into the already-shipped policy layer (rules V3–V9, V11), so
the SP-initiated login and Assertion Consumer Service become functional:

- **V10 (XXE):** the parser resolves no entities, loads no DTD, reaches no
  network; a `<!DOCTYPE`/`<!ENTITY` document is rejected before parsing.
- **V1/V2 (signature + XSW):** signxml verifies the XML-DSIG signature, and
  identity is extracted **only** from the signxml-verified element — never from
  the surrounding, attacker-controllable document. A missing, invalid, or
  wrong-key signature is rejected. **XML-DSIG is never hand-rolled** (ADR-0138 D3).

Verified with real signed fixtures across valid / tampered / unsigned / wrong-key
/ DOCTYPE inputs, plus a full end-to-end ACS flow (verify → policy → role map →
subject → bearer token).

### Off by default, SecArch review still required

The ACS still refuses with 501 and **never parses the posted XML** unless the
operator explicitly sets `server.saml.experimental_acs_enabled: true`. Even then,
a **Security-Architect review remains a pre-production blocking condition**
(CLAUDE.md) — enabling the opt-in acknowledges the pre-review, experimental
status. Local mode is entirely unaffected; installing without the `[saml]` extra
behaves exactly as before.

## Upgrade notes

Additive — no breaking changes, no new *default* dependency (SAML verification is
the opt-in `novafabric[saml]` extra). The default SAML behavior (501 refusal,
never consumes) is unchanged.
